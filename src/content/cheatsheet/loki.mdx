## Mental model: Loki ≠ Prometheus

| | Prometheus | Loki |
| :--- | :--- | :--- |
| What is indexed | **label values** (all of them) | **label names** (value = stream contents) |
| Contents | numbers (samples) | log lines (text) |
| Query | `rate()` over counters | `count_over_time()` over a range |
| Cost | series per label combination | **stream per label combination** |
| Expensive example | 1,000,000 series | 10,000 streams with the same labels |

```text
{app="order-service", namespace="pos"}   ← this is ONE stream
  +----------------+------------------+------------------+
  | 2026-10-21 ... | 2026-10-21 ...  | 2026-10-21 ...  |  ← the log lines inside it
```

> Consequence: in Loki, **label values** = grouping. Every unique combination of
> label values = one stream. And streams cannot be merged → label cardinality is the
> primary limit, not merely a "cost".

## LogQL: stream selector & line filter

```logql
# stream selector — at least one label is REQUIRED
{app="order-service"}
{namespace="pos", app=~"order-.*"}
{app="order-service", status=~"5.."}

# line filter (literal string, case-sensitive)
{app="order-service"} |= "error"
{app="order-service"} != "heartbeat"
{app="order-service"} |~ "timeout|deadline"
{app="order-service"} |~ "(?i)warn"            # (?i) = case-insensitive

# chaining: filter then filter again
{app="order-service"} |= "error" |~ "timeout"

# label filter (after parsing)
{app="order-service"} | json | level="error"
{app="order-service"} | logfmt | status >= 500

# offset & limit
{app="order-service"} |= "error" | offset 5m
{app="order-service"} |= "error" | limit 100

# time direction
{app="order-service"} |= "error" | order asc
```

| Filter | Meaning |
| :--- | :--- |
| `|= "s"` | line **contains** the string |
| `!= "s"` | line **does not contain** the string |
| `\|~ "re"` | regex (RE2, no backreferences) |
| `!~ "re"` | does not match the regex |
| `\| label` | filter by label |
| `\| label != "v"` | negate a label |

> **Pitfall:** `|= "Error"` will **not** match `"error"` — Loki line filters are
> case-sensitive. Use `|~ "(?i)error"` if you are not sure about the format.

## LogQL: parsers

```logql
# json — JSON fields become labels
{app="order-service"} | json
{app="order-service"} | json | level="error" | orderId="8821"

# json with parse-error filter
{app="order-service"} | json | __error__=""          # discard lines that failed to parse
{app="order-service"} | json | __error__!=""         # instead find the ones that failed to parse

# logfmt
{app="order-service"} | logfmt | level="error"

# pattern — for non-JSON logs (nginx, apache)
{app="nginx"} | pattern "<_> - - [<_>] \"<method> <uri> <_>\" <status> <_>"

# unpack — JSON Lines (one JSON per line)
{app="kafka"} | unpack

# label_format — change label values
{app="order-service"} | json | label_format level=uppercase

# line_format — change the line contents
{app="order-service"} | json | line_format "{{.level}}: {{.msg}}"

# drop / keep — drop or keep labels
{app="order-service"} | json | drop level, span_id
{app="order-service"} | json | keep level, msg

# set/rename
{app="order-service"} | json | label_format service=order
```

| Parser | For | Note |
| :--- | :--- | :--- |
| `json` | single-line JSON logs | **every field becomes a label** → cardinality |
| `logfmt` | `key=value` | safer than json (limited fields) |
| `pattern` | fixed format (nginx) | placeholder `<_>` = wildcard |
| `unpack` | JSON Lines | one JSON per line |
| `regexp` | explicit regex | `| regexp "..."` |

> **Pitfall (the most important one in Loki):** the `json` parser **turns every JSON field
> into a label**. If your logs have `userId`, `orderId`, `traceId` → each value
> becomes a new stream → Loki blows up. The fix: use `| logfmt` for fields that
> are numerous, or parse then `| drop` the unneeded fields, or **do not** parse
> high-cardinality fields.

## LogQL: metrics & aggregation

```logql
# count per minute
count_over_time({app="order-service"}[1m])

# count per level
sum by (level) (count_over_time({app="order-service"} | json | level="error" [5m]))

# rate (Loki does NOT have rate() — use count_over_time)
sum(rate({app="order-service"} |= "error" [5m]))       # ← there is no rate function in LogQL
# the correct way:
sum(count_over_time({app="order-service"} |= "error" [5m])) / 300

# top error messages
topk(10, sum by (msg) (count_over_time({app="order-service"} | json | level="error" [5m])))

# bytes
bytes_over_time({app="order-service"}[5m])
bytes_rate({app="order-service"}[5m])

# template variable in Grafana
sum by (level) (count_over_time({app="order-service"} | json [5m]))
```

| Function | Meaning |
| :--- | :--- |
| `count_over_time(v[5m])` | number of lines in the window |
| `bytes_over_time(v[5m])` | number of bytes |
| `bytes_rate(v[5m])` | bytes per second |
| `rate(v[5m])` | **does not exist** in LogQL — derive it from `count_over_time` |
| `rate_counter(v[5m])` | limited rate variant |
| `quantile_over_time(0.99, v[5m])` | quantile of log values (with `unwrap`) |
| `avg_over_time`, `max_over_time`, `sum_over_time` | value aggregation (`unwrap` required) |

## LogQL: unwrap & error rate

```logql
# unwrap: take a numeric field from the log → becomes a sample
sum by (status) (
  rate({app="order-service"} | json | unwrap status [5m])
)

# p99 latency from the duration field (in ms)
quantile_over_time(0.99,
  {app="order-service"} | json | unwrap duration | __error__="" [5m]) by (le)

# bytes per second from the size field
sum by (path) (
  rate({app="order-service"} | json | unwrap bytes [5m])
)
```

| Aturan `unwrap` | Detail |
| :--- | --- |
| Format | `unwrap field` or `unwrap label_format` |
| Field must be **numeric** | string → error parse, seri hilang |
| Error filter | `| __error__=""` (discard those that failed to parse) |
| `le` label | `quantile_over_time` needs an `le` bucket |

> **Pitfall:** `unwrap` without `__error__=""` → lines whose field is not a number
> **drop** samples and make the quantile misleading. Always filter the errors out.

## Label design & cardinality limits

```yaml
# Loki schema / limits
schema_config:
  configs:
    - from: 2024-01-01
      store: tsdb
      object_store: filesystem
      schema: v13
      index:
        prefix: index_
        period: 24h

limits_config:
  # streams per tenant
  max_global_streams_per_user: 10000
  # new labels per day (cardinality guard)
  max_label_names_per_series: 15
  # read volume per tenant
  ingestion_rate_mb: 16
  ingestion_burst_size_mb: 32
  max_query_series: 5000
  max_query_lookback: 720h
  retention_period: 720h            # 30 days
```

| Label | Good? | Why |
| :--- | :--- | :--- |
| `app` / `service` | ✅ | low cardinality |
| `namespace` | ✅ | low |
| `env` / `cluster` | ✅ | low |
| `level` | ✅ | 4–6 values |
| `status` | ✅ |_HTTP status_ a handful |
| `trace_id` | ⚠️ | **must not be a label** — keep it in the body, parse when needed |
| `user_id` | ❌ | one stream per user |
| `order_id` | ❌ | one stream per order |
| `path` | ⚠️ | templated `{id}` only |
| `timestamp` | ❌ | must never be a label |

```logql
# check stream count per label value
sum by (app) (count_over_time({namespace="pos"}[1h]))
```

> **Pitfall:** Loki can *drop* labels that are not in the config, but if the label
> values vary (e.g. `userId`), streams still blow up. **Cardinality guards exist in
> Prometheus, not in Loki** — so label discipline starts in code, not in config.

## Structured logging (JSON, MDC, trace_id)

```xml
<!-- logback-spring.xml — JSON with trace_id -->
<appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
    <encoder class="net.logstash.logback.encoder.LogstashEncoder">
        <customFields>{"service":"${spring.application.name}"}</customFields>
        <includeMdcKeyName>trace_id</includeMdcKeyName>
        <includeMdcKeyName>span_id</includeMdcKeyName>
        <includeMdcKeyName>user_id</includeMdcKeyName>
    </encoder>
</appender>
```

```json
{
  "timestamp": "2026-10-21T10:00:00.123Z",
  "level": "ERROR",
  "service": "order-service",
  "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736",
  "span_id": "00f067aa0ba902b7",
  "thread": "http-nio-8083-exec-3",
  "logger": "com.sanedge.order.OrderService",
  "message": "payment failed for order 8821",
  "orderId": "8821",
  "status": 500
}
```

```java
// filter: TraceIdFilter → MDC
@Component
public class TraceIdFilter extends OncePerRequestFilter {
    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain) {
        String traceId = Optional.ofNullable(req.getHeader("X-Trace-Id"))
                .orElseGet(() -> UUID.randomUUID().toString());
        try (MDC.MDCCloseable ignored = MDC.putCloseable("trace_id", traceId)) {
            chain.doFilter(req, res);
        }
    }
}
```

| Field | Required? | Why |
| :--- | :--- | :--- |
| `timestamp` | yes | chronological order (Loki also uses ingest time) |
| `level` | yes | filtering & aggregation per level |
| `service` | yes | multi-service filtering |
| `trace_id` | **strongly recommended** | log ↔ trace correlation |
| `span_id` | recommended | per-span correlation |
| `message` | yes | contents |
| `user_id` | optional | **body**, not a label |

> **Pitfall:** `user_id` inside the JSON body is **safe** (it does not become a label until parsed),
> but if your query does `| json` → it **becomes a label** → cardinality explosion.
> Use `| json | drop user_id` if you need to parse other fields.

## Alloy / Promtail pipeline

```yaml
# alloy/config.alloy — Loki pipeline
loki.write "default" {
  endpoint {
    url = "http://loki:3100/loki/api/v1/push"
  }
}

loki.source.docker "default" {
  host       = "/var/run/docker.sock"
  targets    = ["all"]
  forward_to = [loki.process.default.receiver]
}

loki.process "default" {
  forward_to = [loki.write.default.receiver]

  stage.json {
    expressions = {
      level   = "level",
      service = "service",
      trace_id = "trace_id",
      span_id  = "span_id",
    }
  }

  stage.labels {
    values = {
      level   = "",
      service = "",
    }
  }

  // trace_id does NOT become a label — body only
  stage.template {
    source = "message"
    template = "{{ .trace_id }}"
  }

  stage.static_labels {
    values = {
      namespace = "pos",
    }
  }
}
```

```yaml
# kubernetes discovery
discovery.kubernetes "pods" {
  role = "pod"
}

discovery.relabel "pods" {
  targets = discovery.kubernetes.pods.targets

  rule {
    source_labels = ["__meta_kubernetes_pod_annotation_prometheus_io_scrape"]
    regex         = "true"
    action        = "keep"
  }
  rule {
    source_labels = ["__meta_kubernetes_namespace"]
    target_label  = "namespace"
  }
  rule {
    source_labels = ["__meta_kubernetes_pod_label_app"]
    target_label  = "app"
  }
}
```

| Stage | For |
| :--- | :--- |
| `stage.json` | parse JSON → fields |
| `stage.logfmt` | parse key=value |
| `stage.regex` | parse regex → fields |
| `stage.labels` | field → **label** (watch the cardinality) |
| `stage.template` | field → body contents (safe for trace_id) |
| `stage.drop` | drop a field |
| `stage.static_labels` | constant labels |
| `stage.timestamp` | set the timestamp from a field |
| `stage.pack` | pack several labels into one |
| `stage.sampling` | take 1 out of N lines (saves volume) |

> **Pitfall:** `stage.labels` for `trace_id` = **a stream per trace** → Loki dies.
> Use `stage.template` (goes into the body) or `stage.pack`.

## Architecture & retention

```
App → (OTLP/push) → Loki Distributor → Ingester (chunks) → Object Storage
                                    ↘ Querier  ↘ Ruler (alert/recording rules)
```

```yaml
compactor:
  working_directory: /loki/compactor
  retention_enabled: true
  delete_request_store: filesystem

storage_config:
  tsdb_shipper:
    active_index_directory: /loki/tsdb-index
    cache_location: /loki/tsdb-cache
  filesystem:
    directory: /loki/chunks

limits_config:
  retention_period: 720h
  allow_structured_metadata: true
```

| Component | Role |
| :--- | :--- |
| Distributor | accepts pushes, batches, forwards to ingesters |
| Ingester | keeps chunks in memory, flushes to object storage |
| Querier | runs LogQL (reads from ingesters + store) |
| Ruler | evaluates recording & alerting rules |
| Compactor | compacts & deletes old chunks (retention) |

| Term | Meaning |
| :--- | :--- |
| Chunk | compressed block of log data (1.5 MB default) |
| Stream | a set of chunks sharing the same label set |
| Index | stream metadata → chunks |
| `period` | index interval (24h default) |
| `retention_period` | how long logs are kept |

> **Pitfall:** `retention_period` does **not** take effect immediately — chunks are deleted by
> the **compactor**, and the compactor must have `retention_enabled: true` +
> a `delete_request_store` matching the object storage. Otherwise the data stays
> around even though it is already "expired".

## Ruler: recording & alert rules

```yaml
# loki/rules/*.yaml
groups:
  - name: order-service-logs
    interval: 1m
    rules:
      - record: order:log_errors:rate5m
        expr: |
          sum(count_over_time({app="order-service"} | json | level="error" [5m])) / 300

      - alert: OrderServiceErrorLogSpike
        expr: |
          sum(count_over_time({app="order-service"} | json | level="error" [5m])) / 300 > 1
        for: 5m
        labels:
          severity: warning
          service: order-service
        annotations:
          summary: "Error log rate > 1/s on order-service"
```

```promql
# use the recording rule on a dashboard
order:log_errors:rate5m
```

## Query debugging

```logql
# does the stream exist?
{app="order-service"}

# are the lines arriving? (try without filters)
{namespace="pos"} |= "order"

# check the JSON parse result
{app="order-service"} | json | __error__!=""

# which fields are readable?
{app="order-service"} | json | label_format dummy="x" | line_format "{{.level}} {{.msg}}"

# count per label
sum by (app) (count_over_time({namespace="pos"}[1h]))
```

```bash
# logcli
logcli query '{app="order-service"}' --since=1h --limit=20
logcli query --instant --query 'sum by (level) (count_over_time({app="order-service"} | json [5m]))'
logcli labels
logcli series '{app="order-service"}'
logcli query-rate-limit
```

| Symptom | Check | Fix |
| :--- | :--- | :--- |
| "no logs" | `curl /loki/api/v1/labels` | check the agent pipeline |
| 429 Too Many Requests | `max_query_series` | raise the limit / simplify the query |
| Out of order | `unordered_writes` | set it to true |
| Missing chunks | ingester has not flushed yet | wait for the flush period |
| Slow query | too many streams | reduce labels / add `by` |
| Old data disappears | retention | check the compactor & storage |
| Duplicate entries | the agent sends twice | check the agent configuration |

## Pitfalls (required reading)

| Pitfall | Symptom | Solution |
| :--- | :--- | :--- |
| `\| json` turns every field into a label | Thousands of streams, Loki dies | `\| logfmt`, or `\| json \| drop field` |
| `trace_id`/`user_id` become labels | Stream per trace/user | Keep them in the body (`stage.template`) |
| `rate()` used in LogQL | Error | Use `count_over_time` |
| `unwrap` without `__error__=""` | Samples disappear, wrong quantiles | Filter parse errors |
| Case-sensitive line filter | Logs not found | Use `\|~ "(?i)..."` |
| `retention_period` without a compactor | Data is never deleted | `retention_enabled: true` + `delete_request_store` |
| Pipeline `stage.labels` for dynamic fields | Streams explode | `stage.template` or `stage.pack` |
| Ingestion rate exceeded | Logs dropped | Raise `ingestion_rate_mb` |
| Query without `by` | Thousands of series | `sum by (...)` |
| Changing pipeline labels without restarting | Old streams remain | Restart the agent → old streams expire |
| Multiline logs (stack traces) | Split per line | Alloy `stage.cri` (container log format) |
| Untrusted timestamp from the log | Out-of-order results | Set `stage.timestamp` or use ingest time |
| No `service` label | Hard to filter across services | Required in every pipeline |
