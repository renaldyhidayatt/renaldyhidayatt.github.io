## System structure & boot

```text
BIOS/UEFI → bootloader (GRUB) → kernel + initramfs → init (systemd PID 1)
   → target (multi-user/graphical) → services (units) → login
```

| Path | Contents |
| :--- | :--- |
| `/` | root filesystem |
| `/etc` | configuration (the only part you edit by hand) |
| `/var` | changing data: logs, cache, databases |
| `/usr` | package binaries & libraries |
| `/opt` | third-party software |
| `/tmp` | temporary (may be wiped on reboot) |
| `/proc` | pseudo-fs for processes & kernel (`/proc/cpuinfo`) |
| `/sys` | pseudo-fs for devices & drivers |
| `/run` | runtime state (tmpfs) |
| `/dev` | device nodes |

```bash
uname -a; uname -r; cat /etc/os-release
hostnamectl
systemctl get-default                    # multi-user.target / graphical.target
journalctl -b                            # this boot's log
journalctl -b -1                         # previous boot
dmesg -T | head -50                      # kernel ring buffer (human-readable timestamps)
lsblk -f                                 # disks + filesystems + mounts
```

| Concept | Meaning |
| :--- | :--- |
| initramfs | temporary image used to mount root |
| systemd target | replacement for runlevels |
| rescue.target / emergency.target | minimal maintenance |
| `/etc/fstab` | mount table used at boot |
| `/etc/default/grub` + `update-grub` | kernel parameters |

> **Pitfall:** editing `/etc/fstab` with the wrong UUID = boot drops into emergency mode.
> Always test with `mount -a` before rebooting.

## Filesystem & permissions

```bash
# list & navigate
ls -lah; ls -i; du -sh *; df -hT; stat file
find . -type f -size +100M -exec ls -lh {} +
find /var/log -type f -mtime +7 -name '*.log' -delete

# permissions
chmod 640 file                # rw-r-----
chmod u+x,g-w,o=r file        # symbolic
chown -R app:app /srv/app
chmod g+s /srv/shared         # setgid: new files inherit the directory's group
chmod o+t /tmp                # sticky: only the owner can delete

# ACLs
getfacl file
setfacl -m u:deploy:rX -R /srv/app
setfacl -m g:ops:rw /var/log/app.log
setfacl -x u:deploy /srv/app     # remove a per-user ACL

# special attributes
lsattr file
chattr +i important.conf         # immutable
chattr -i important.conf
```

| Mode | Number | Meaning |
| :--- | :--- | :--- |
| `r` | 4 | read |
| `w` | 2 | write |
| `x` | 1 | execute (or enter a directory) |
| setuid | 4000 | execute as the owner |
| setgid | 2000 | execute as the group / inherit group |
| sticky | 1000 | delete only by the owner |

| File type | `ls -l` prefix |
| :--- | :--- |
| regular | `-` |
| directory | `d` |
| symlink | `l` |
| socket | `s` |
| named pipe | `p` |
| block/char device | `b`/`c` |

```bash
# umask determines default permissions
umask 027                    # files 640, directories 750
```

> **Pitfall:** `chmod -R 777` fixes the symptom, not the cause. Directories need `x`
> to be traversed; files do not. Fix groups & ACLs, don't open up the world.

## Processes, signals, job control

```bash
ps aux --sort=-%cpu | head
ps -eo pid,ppid,stat,etime,cmd --sort=-etimes | head
pgrep -af 'java'; pgrep -u app -a
pstree -p 1234
top -o %MEM; htop; atop
lsof -p 1234 | head                # files & sockets currently open
lsof -i :8080                      # who is listening on the port
fuser -v 8080/tcp                  # processes on the port (without lsof)
```

```bash
kill -l                            # list of signals
kill -TERM 1234                    # ask it to stop cleanly
kill -HUP 1234                     # reload config (many daemons)
kill -9 1234                       # force (no cleanup!)
pkill -f 'app.jar'
killall nginx
```

```bash
# job control
cmd &                              # background
jobs; fg %1; bg %1
nohup cmd > app.log 2>&1 &
disown %1                          # detach from the shell
screen -S work                     # persistent
tmux new -s work
```

| Signal | Number | Meaning |
| :--- | :--- | :--- |
| SIGHUP | 1 | hangup / reload config |
| SIGINT | 2 | Ctrl+C |
| SIGKILL | 9 | cannot be caught — the process dies instantly |
| SIGSEGV | 11 | segfault (bug) |
| SIGTERM | 15 | request to stop (default `kill`) |
| SIGSTOP | 19 | pause (cannot be caught) |
| SIGCONT | 18 | continue |
| SIGCHLD | 17 | child exited |

| `ps` status | Meaning |
| :--- | :--- |
| `R` | running/runnable |
| `S` | sleeping (interruptible) |
| `D` | uninterruptible sleep (I/O — signals have no effect) |
| `Z` | zombie (parent has not `wait`ed) |
| `T` | stopped |
| `I` | idle kernel thread |

> **Pitfall:** a zombie process cannot be killed — what you need to fix is the parent
> that isn't calling `wait()`. A process in state `D` also cannot be `kill -9`ed.

## systemd (units, timers, journal)

```bash
systemctl status nginx
systemctl start|stop|restart|reload nginx
systemctl enable --now nginx          # enable + start at boot
systemctl disable --now nginx
systemctl list-units --type=service --state=running
systemctl list-units --failed
systemctl daemon-reload               # after changing a unit file
systemctl cat nginx                   # show the unit + drop-ins
systemctl show nginx -p MainPID,ExecStart
systemctl is-active nginx; systemctl is-enabled nginx
systemctl reset-failed nginx
```

```ini
# /etc/systemd/system/app.service
[Unit]
Description=App service
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
Type=simple                        # simple|exec|forking|notify|oneshot
User=app
Group=app
WorkingDirectory=/srv/app
EnvironmentFile=-/etc/app/env
ExecStartPre=/usr/bin/test -f /srv/app/app.jar
ExecStart=/usr/bin/java -XX:MaxRAMPercentage=75 -jar /srv/app/app.jar
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure
RestartSec=5
TimeoutStopSec=30
KillSignal=SIGTERM
LimitNOFILE=65535
MemoryMax=2G
CPUQuota=200%
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/var/lib/app /var/log/app

[Install]
WantedBy=multi-user.target
```

```ini
# /etc/systemd/system/backup.service + .timer
# backup.service
[Unit]
Description=Nightly backup
[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup.sh
```

```ini
# backup.timer
[Unit]
Description=Run backup daily at 02:00
[Timer]
OnCalendar=*-*-* 02:00:00
Persistent=true
RandomizedDelaySec=300
[Install]
WantedBy=timers.target
```

```bash
systemctl list-timers --all
systemctl start backup.timer
journalctl -u backup.service --since today
```

```bash
# journal
journalctl -u nginx --since "1 hour ago" -f
journalctl -p err -b                     # priority error, this boot
journalctl -n 100 --no-pager
journalctl -o json-pretty -n 1
journalctl --vacuum-time=14d             # clear old logs
journalctl --disk-usage
```

| `Type=` | When |
| :--- | :--- |
| `simple` | foreground process (default) |
| `exec` | wait for exec to succeed before considering it started |
| `notify` | the process sends `READY=1` via sd_notify |
| `forking` | classic daemon that forks & exits |
| `oneshot` | one-off task |

> **Pitfall:** `Restart=always` on a unit that fails to start due to bad configuration will
> create an endless restart loop. Use `Restart=on-failure` + `StartLimitBurst=`.

## Packages & users

```bash
# Debian/Ubuntu
apt update && apt upgrade -y
apt install -y nginx
apt remove --purge nginx
apt-cache policy nginx
dpkg -l | grep nginx; dpkg -L nginx; dpkg -S /usr/sbin/nginx
apt-mark hold nginx

# RHEL/Alma/Fedora
dnf install -y nginx; dnf remove nginx; dnf history
rpm -qa | grep nginx; rpm -ql nginx; rpm -qf /usr/sbin/nginx

# users & groups
useradd -m -s /bin/bash -G sudo deploy
passwd deploy
usermod -aG docker deploy
usermod -L deploy           # lock
userdel -r deploy
id deploy; groups; getent passwd deploy
```

```bash
# minimal sudo
# /etc/sudoers.d/deploy
deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart app
```

| Rule | Why |
| :--- | :--- |
| `visudo` / `sudoers.d` | a bad edit = losing root access |
| `NOPASSWD` per command only | never globally |
| `apt-mark hold` / `dnf versionlock` | prevent accidental upgrades |
| `-G` adds a group, `-g` changes the primary group | easy to mix up |

## Networking & debugging

```bash
ip addr; ip route; ip -br link
ip addr add 10.0.1.5/24 dev eth0
ip route add default via 10.0.1.1

ss -tlnp                          # listening TCP + processes
ss -tunap | head                  # all sockets
ss -s                             # summary
ss -ti                            # TCP info (rtt, cwnd)

dig +short example.com; dig @1.1.1.1 example.com A
cat /etc/resolv.conf; resolvectl status
getent hosts example.com

curl -v --max-time 5 https://example.com
curl -w '%{http_code} %{time_total}\n' -o /dev/null -s https://example.com
traceroute -T -p 443 example.com
mtr -rw example.com
tcpdump -i any -nn port 443 -c 20
tcpdump -i eth0 -w cap.pcap && tshark -r cap.pcap | head
```

```bash
# firewall
ufw status verbose
ufw allow 22/tcp; ufw allow from 10.0.1.0/24 to any port 5432
nft list ruleset
iptables -t nat -L -n -v
```

| Symptom | Check first |
| :--- | :--- |
| Port not open | `ss -tlnp` (is a process listening?), not the firewall first |
| Connection refused | service is down / listening on `127.0.0.1` only |
| Connection timeout | firewall / route / security group |
| Slow DNS | `resolvectl status`, `dig` against `@resolver` |
| Packets dropped | `mtr`, `tcpdump`, `ip -s link` counters |
| TLS error | `openssl s_client -connect host:443 -servername host` |

> **Pitfall:** `netstat` is deprecated on many distros — use `ss`. And a service listening
> on `127.0.0.1` will not be reachable from outside even with the firewall open.

## Storage, LVM, mount

```bash
lsblk -f; blkid; df -hT; findmnt
mount /dev/sdb1 /mnt/data; umount /mnt/data
mount -a                          # test fstab without rebooting

# LVM
pvs; vgs; lvs
pvcreate /dev/sdb
vgcreate data /dev/sdb
lvcreate -L 50G -n app data
lvextend -r -L +20G /dev/data/app     # -r resizes the filesystem too
resize2fs /dev/data/app               # ext4 (xfs_growfs for XFS)

# swap
swapon --show; free -h
fallocate -l 4G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
```

```bash
# find the missing disk space
du -xh --max-depth=1 / | sort -h | tail
lsof +L1                          # deleted files that are still open
journalctl --vacuum-size=500M
docker system df
```

| Symptom | Common cause |
| :--- | :--- |
| `df` full but `du` small | deleted file still held open by a process |
| inodes exhausted | many small files (`df -i`) |
| read-only filesystem | I/O error → `dmesg`, `mount -o remount,rw /` |
| slow I/O | `iostat -xz 1`, `iotop` |

> **Pitfall:** extending an LV without `-r` (or `resize2fs`) leaves `df` still reporting
> the old size. Always resize the filesystem after the LV.

## Resource limits & cgroup v2

```bash
ulimit -a
ulimit -n 65535                   # applies to this shell only
cat /proc/1234/limits             # limits of a running process

# cgroup v2
cat /sys/fs/cgroup/cgroup.controllers
systemd-cgtop                     # usage per cgroup
cat /sys/fs/cgroup/system.slice/nginx.service/memory.current
cat /sys/fs/cgroup/system.slice/nginx.service/memory.max
```

```ini
# limits via a systemd unit (the easiest route)
[Service]
LimitNOFILE=65535
MemoryMax=2G
MemoryHigh=1500M
CPUQuota=200%
IOReadBandwidthMax=/dev/sda 100M
TasksMax=512
```

| Setting | Effect |
| :--- | :--- |
| `MemoryMax` | hard limit → OOM kill inside the cgroup |
| `MemoryHigh` | soft limit → throttles allocation |
| `CPUQuota` | percent of one CPU (200% = 2 cores) |
| `TasksMax` | number of tasks/threads |
| `LimitNOFILE` | fds per process |

> **Pitfall:** `ulimit -n` in a shell does not affect systemd services — the limit must be set
> in the unit (`LimitNOFILE`) or in `/etc/security/limits.conf` for login sessions.

## Kernel & sysctl

```bash
sysctl -a | grep net.ipv4.tcp_syncookies
sysctl -w net.core.somaxconn=4096      # temporary
sysctl --system                        # reload all /etc/sysctl.d files

cat /proc/meminfo | head
cat /proc/loadavg
vmstat 1 5
iostat -xz 1 3
mpstat -P ALL 1 3
sar -u 1 5; sar -r 1 5                 # sysstat
```

```ini
# /etc/sysctl.d/99-tuning.conf
net.core.somaxconn = 4096
net.ipv4.tcp_max_syn_backlog = 8192
net.ipv4.ip_local_port_range = 10240 65000
net.ipv4.tcp_tw_reuse = 1
fs.file-max = 2097152
vm.swappiness = 10
```

| Parameter | Meaning |
| :--- | :--- |
| `vm.swappiness` | swap tendency (10–30 for database servers) |
| `vm.overcommit_memory` | allocation strategy (1 = always allow) |
| `net.core.somaxconn` | maximum accept backlog |
| `fs.file-max` | system-wide maximum fds |
| `kernel.pid_max` | PID limit |

> **Pitfall:** setting `vm.overcommit_memory=1` to "avoid OOM" actually causes
> the OOM killer to shoot a random process once memory is truly exhausted.

## Basic containers

```bash
docker ps -a; docker logs -f --tail 100 app
docker exec -it app sh
docker stats --no-stream
docker inspect app | head -40
docker system df; docker system prune -af

# without docker: namespaces & cgroups
unshare --pid --fork --mount-proc bash
ip netns add test; ip netns list
nsenter -t 1234 -n ss -tlnp        # enter a process's network namespace
```

| Command | Function |
| :--- | :--- |
| `nsenter` | enter another process's namespace (container debugging) |
| `unshare` | create new namespaces |
| `systemd-cgls` | cgroup tree |
| `systemd-run --scope` | run a command with limits |

> **Pitfall:** `docker exec` uses the container's namespaces but the host binary if the image
> has no shell. For distroless containers use `nsenter` from the host.

## Performance troubleshooting

```bash
# diagnosis order: load → CPU → memory → I/O → network
uptime; cat /proc/loadavg
top -b -n1 | head -15
pidstat 1 5
vmstat 1 5
iostat -xz 1 3
ss -s; ss -ti | head -30
dmesg -T | tail -50                # OOM, I/O errors
journalctl -p err -b --no-pager | tail -30
```

| Symptom | Tool | Hint |
| :--- | :--- | :--- |
| High load, idle CPU | `ps -eo stat,wchan,cmd` | processes in `D` = waiting on I/O |
| Memory full | `free -h`, `/proc/meminfo` | low `available` → about to OOM |
| OOM kill | `dmesg`, `journalctl -k` | "Killed process … out of memory" |
| Slow I/O | `iostat -xz` | `%util` ~100, high `await` |
| Slow network | `ss -ti`, `mtr` | retransmits, rising rtt |
| Disk full | `df -h`, `df -i` | data vs inodes |
| Slow boot | `systemd-analyze blame` | slowest units |

> **Pitfall:** a high `load average` does not always mean the CPU is busy — processes waiting
> on disk (`D`) are counted too. Always check the `wa` column in `vmstat`.

## Pitfalls (must read)

| Pitfall | Symptom | Fix |
| :--- | :--- | :--- |
| Wrong UUID in `fstab` | boot drops into emergency mode | `mount -a` before rebooting |
| `chmod -R 777` | problem "disappears" but is insecure | fix groups/ACLs |
| Directory without `x` | cannot enter it even with `r` | `chmod a+X` |
| `kill -9` for everything | corrupted data, stale locks | SIGTERM first + timeout |
| Zombie process `kill`ed | it doesn't disappear | fix the parent (`wait`) |
| Waiting on a `D` process | cannot be killed | let the I/O finish |
| `Restart=always` + broken config | restart loop | `on-failure` + `StartLimitBurst` |
| Forgetting `daemon-reload` | the old unit keeps running | `systemctl daemon-reload` |
| Timer without `Persistent=` | job missed while the host was down | `Persistent=true` |
| `ulimit` in a shell | services are unaffected | `LimitNOFILE` in the unit |
| LVM extend without a filesystem resize | `df` doesn't change | `lvextend -r` |
| `df` full, `du` small | file held open by a process | `lsof +L1` |
| inodes exhausted | "No space left" even though the disk is roomy | `df -i`, clean up small files |
| Service listening on `localhost` | unreachable from outside | bind `0.0.0.0` / proxy |
| `netstat` on newer distros | command not found | `ss` |
| `sysctl -w` without persistence | lost after reboot | `/etc/sysctl.d/` |
| `swappiness=0` | can OOM suddenly | 10–30 |
| `NOPASSWD: ALL` | trivial privilege escalation | per-command |
| `docker exec` on distroless | no shell available | `nsenter` from the host |
