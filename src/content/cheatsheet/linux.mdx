## Struktur sistem & boot

```text
BIOS/UEFI → bootloader (GRUB) → kernel + initramfs → init (systemd PID 1)
   → target (multi-user/graphical) → services (unit) → login
```

| Path | Isi |
| :--- | :--- |
| `/` | root filesystem |
| `/etc` | konfigurasi (satu-satunya yang manual) |
| `/var` | data berubah: log, cache, database |
| `/usr` | binary & library paket |
| `/opt` | software pihak ketiga |
| `/tmp` | sementara (bisa dihapus saat reboot) |
| `/proc` | pseudo-fs proses & kernel (`/proc/cpuinfo`) |
| `/sys` | pseudo-fs device & driver |
| `/run` | runtime state (tmpfs) |
| `/dev` | device node |

```bash
uname -a; uname -r; cat /etc/os-release
hostnamectl
systemctl get-default                    # multi-user.target / graphical.target
journalctl -b                            # log boot ini
journalctl -b -1                         # boot sebelumnya
dmesg -T | head -50                      # kernel ring buffer (timestamp manusia)
lsblk -f                                 # disk + filesystem + mount
```

| Konsep | Arti |
| :--- | :--- |
| initramfs | image sementara untuk mount root |
| systemd target | pengganti runlevel |
| rescue.target / emergency.target | maintenance minimal |
| `/etc/fstab` | tabel mount saat boot |
| `/etc/default/grub` + `update-grub` | parameter kernel |

> **Jebakan:** mengedit `/etc/fstab` dengan UUID salah = boot masuk emergency mode.
> Selalu uji dengan `mount -a` sebelum reboot.

## Filesystem & permission

```bash
# lihat & navigasi
ls -lah; ls -i; du -sh *; df -hT; stat file
find . -type f -size +100M -exec ls -lh {} +
find /var/log -type f -mtime +7 -name '*.log' -delete

# permission
chmod 640 file                # rw-r-----
chmod u+x,g-w,o=r file        # simbolik
chown -R app:app /srv/app
chmod g+s /srv/shared         # setgid: file baru ikut group direktori
chmod o+t /tmp                # sticky: hanya pemilik bisa hapus

# ACL
getfacl file
setfacl -m u:deploy:rX -R /srv/app
setfacl -m g:ops:rw /var/log/app.log
setfacl -x u:deploy /srv/app     # hapus ACL user

# atribut khusus
lsattr file
chattr +i important.conf         # immutable
chattr -i important.conf
```

| Mode | Angka | Arti |
| :--- | :--- | :--- |
| `r` | 4 | baca |
| `w` | 2 | tulis |
| `x` | 1 | eksekusi (atau masuk direktori) |
| setuid | 4000 | eksekusi sebagai pemilik |
| setgid | 2000 | eksekusi sebagai grup / inherit grup |
| sticky | 1000 | hapus hanya oleh pemilik |

| Jenis file | Prefix `ls -l` |
| :--- | :--- |
| regular | `-` |
| directory | `d` |
| symlink | `l` |
| socket | `s` |
| named pipe | `p` |
| block/char device | `b`/`c` |

```bash
# umask menentukan permission default
umask 027                    # file 640, direktori 750
```

> **Jebakan:** `chmod -R 777` menyelesaikan gejala, bukan sebabnya. Direktori butuh `x`
> untuk menelusuri; file tidak. Perbaiki grup & ACL, jangan membuka dunia.

## Proses, signal, job control

```bash
ps aux --sort=-%cpu | head
ps -eo pid,ppid,stat,etime,cmd --sort=-etimes | head
pgrep -af 'java'; pgrep -u app -a
pstree -p 1234
top -o %MEM; htop; atop
lsof -p 1234 | head                # file & socket yang dibuka
lsof -i :8080                      # siapa mendengar port
fuser -v 8080/tcp                  # proses di port (tanpa lsof)
```

```bash
kill -l                            # daftar signal
kill -TERM 1234                    # minta berhenti dengan rapi
kill -HUP 1234                     # reload config (banyak daemon)
kill -9 1234                       # paksa (tidak ada cleanup!)
pkill -f 'app.jar'
killall nginx
```

```bash
# job control
cmd &                              # background
jobs; fg %1; bg %1
nohup cmd > app.log 2>&1 &
disown %1                          # lepas dari shell
screen -S work                     # persisten
tmux new -s work
```

| Signal | Nomor | Arti |
| :--- | :--- | :--- |
| SIGHUP | 1 | hangup / reload config |
| SIGINT | 2 | Ctrl+C |
| SIGKILL | 9 | tidak bisa ditangkap — proses mati seketika |
| SIGSEGV | 11 | segfault (bug) |
| SIGTERM | 15 | permintaan berhenti (default `kill`) |
| SIGSTOP | 19 | pause (tidak bisa ditangkap) |
| SIGCONT | 18 | lanjutkan |
| SIGCHLD | 17 | anak selesai |

| Status `ps` | Arti |
| :--- | :--- |
| `R` | running/runnable |
| `S` | sleeping (interruptible) |
| `D` | uninterruptible sleep (I/O — sinyal tidak efektif) |
| `Z` | zombie (parent belum `wait`) |
| `T` | stopped |
| `I` | idle kernel thread |

> **Jebakan:** proses zombie tidak bisa dibunuh — yang harus diperbaiki adalah parent
> yang tidak memanggil `wait()`. Proses status `D` juga tidak bisa di-`kill -9`.

## systemd (unit, timer, journal)

```bash
systemctl status nginx
systemctl start|stop|restart|reload nginx
systemctl enable --now nginx          # aktif + start saat boot
systemctl disable --now nginx
systemctl list-units --type=service --state=running
systemctl list-units --failed
systemctl daemon-reload               # setelah mengubah file unit
systemctl cat nginx                   # tampilkan unit + drop-in
systemctl show nginx -p MainPID,ExecStart
systemctl is-active nginx; systemctl is-enabled nginx
systemctl reset-failed nginx
```

```ini
# /etc/systemd/system/app.service
[Unit]
Description=App service
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
Type=simple                        # simple|exec|forking|notify|oneshot
User=app
Group=app
WorkingDirectory=/srv/app
EnvironmentFile=-/etc/app/env
ExecStartPre=/usr/bin/test -f /srv/app/app.jar
ExecStart=/usr/bin/java -XX:MaxRAMPercentage=75 -jar /srv/app/app.jar
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure
RestartSec=5
TimeoutStopSec=30
KillSignal=SIGTERM
LimitNOFILE=65535
MemoryMax=2G
CPUQuota=200%
NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/var/lib/app /var/log/app

[Install]
WantedBy=multi-user.target
```

```ini
# /etc/systemd/system/backup.service + .timer
# backup.service
[Unit]
Description=Nightly backup
[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup.sh
```

```ini
# backup.timer
[Unit]
Description=Run backup daily 02:00
[Timer]
OnCalendar=*-*-* 02:00:00
Persistent=true
RandomizedDelaySec=300
[Install]
WantedBy=timers.target
```

```bash
systemctl list-timers --all
systemctl start backup.timer
journalctl -u backup.service --since today
```

```bash
# journal
journalctl -u nginx --since "1 hour ago" -f
journalctl -p err -b                     # priority error, boot ini
journalctl -n 100 --no-pager
journalctl -o json-pretty -n 1
journalctl --vacuum-time=14d             # bersihkan log lama
journalctl --disk-usage
```

| `Type=` | Kapan |
| :--- | :--- |
| `simple` | proses foreground (default) |
| `exec` | tunggu exec berhasil sebelum dianggap start |
| `notify` | proses kirim `READY=1` via sd_notify |
| `forking` | daemon klasik yang fork & exit |
| `oneshot` | tugas sekali jalan |

> **Jebakan:** `Restart=always` pada unit yang gagal start karena konfigurasi salah akan
> membuat loop restart tanpa henti. Gunakan `Restart=on-failure` + `StartLimitBurst=`.

## Paket & user

```bash
# Debian/Ubuntu
apt update && apt upgrade -y
apt install -y nginx
apt remove --purge nginx
apt-cache policy nginx
dpkg -l | grep nginx; dpkg -L nginx; dpkg -S /usr/sbin/nginx
apt-mark hold nginx

# RHEL/Alma/Fedora
dnf install -y nginx; dnf remove nginx; dnf history
rpm -qa | grep nginx; rpm -ql nginx; rpm -qf /usr/sbin/nginx

# user & grup
useradd -m -s /bin/bash -G sudo deploy
passwd deploy
usermod -aG docker deploy
usermod -L deploy           # lock
userdel -r deploy
id deploy; groups; getent passwd deploy
```

```bash
# sudo minimal
# /etc/sudoers.d/deploy
deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart app
```

| Aturan | Kenapa |
| :--- | :--- |
| `visudo` / `sudoers.d` | salah edit = kehilangan akses root |
| `NOPASSWD` hanya per command | jangan global |
| `apt-mark hold` / `dnf versionlock` | cegah upgrade tak sengaja |
| `-G` menambah grup, `-g` mengganti grup utama | mudah tertukar |

## Jaringan & debugging

```bash
ip addr; ip route; ip -br link
ip addr add 10.0.1.5/24 dev eth0
ip route add default via 10.0.1.1

ss -tlnp                          # listening TCP + proses
ss -tunap | head                  # semua socket
ss -s                             # ringkasan
ss -ti                             # TCP info (rtt, cwnd)

dig +short example.com; dig @1.1.1.1 example.com A
cat /etc/resolv.conf; resolvectl status
getent hosts example.com

curl -v --max-time 5 https://example.com
curl -w '%{http_code} %{time_total}\n' -o /dev/null -s https://example.com
traceroute -T -p 443 example.com
mtr -rw example.com
tcpdump -i any -nn port 443 -c 20
tcpdump -i eth0 -w cap.pcap && tshark -r cap.pcap | head
```

```bash
# firewall
ufw status verbose
ufw allow 22/tcp; ufw allow from 10.0.1.0/24 to any port 5432
nft list ruleset
iptables -t nat -L -n -v
```

| Gejala | Cek pertama |
| :--- | :--- |
| Port tidak terbuka | `ss -tlnp` (proses listen?), bukan firewall dulu |
| Koneksi refused | service mati / listen `127.0.0.1` saja |
| Koneksi timeout | firewall / route / security group |
| DNS lambat | `resolvectl status`, `dig` dengan `@resolver` |
| Paket hilang | `mtr`, `tcpdump`, counter `ip -s link` |
| TLS error | `openssl s_client -connect host:443 -servername host` |

> **Jebakan:** `netstat` sudah usang di banyak distro — pakai `ss`. Dan service yang
> listen di `127.0.0.1` tidak akan terlihat dari luar meski firewall terbuka.

## Storage, LVM, mount

```bash
lsblk -f; blkid; df -hT; findmnt
mount /dev/sdb1 /mnt/data; umount /mnt/data
mount -a                          # uji fstab tanpa reboot

# LVM
pvs; vgs; lvs
pvcreate /dev/sdb
vgcreate data /dev/sdb
lvcreate -L 50G -n app data
lvextend -r -L +20G /dev/data/app     # -r resize filesystem sekaligus
resize2fs /dev/data/app               # ext4 (xfs_growfs untuk XFS)

# swap
swapon --show; free -h
fallocate -l 4G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
```

```bash
# cari ruang disk yang hilang
du -xh --max-depth=1 / | sort -h | tail
lsof +L1                          # file terhapus tapi masih dibuka
journalctl --vacuum-size=500M
docker system df
```

| Gejala | Penyebab umum |
| :--- | :--- |
| `df` penuh tapi `du` kecil | file terhapus masih dibuka proses |
| inode habis | banyak file kecil (`df -i`) |
| read-only filesystem | error I/O → `dmesg`, `mount -o remount,rw /` |
| I/O lambat | `iostat -xz 1`, `iotop` |

> **Jebakan:** memperluas LV tanpa `-r` (atau `resize2fs`) membuat `df` tetap menunjukkan
> ukuran lama. Selalu resize filesystem setelah LV.

## Resource limit & cgroup v2

```bash
ulimit -a
ulimit -n 65535                   # berlaku untuk shell ini saja
cat /proc/1234/limits             # limit proses yang berjalan

# cgroup v2
cat /sys/fs/cgroup/cgroup.controllers
systemd-cgtop                     # pemakaian per cgroup
cat /sys/fs/cgroup/system.slice/nginx.service/memory.current
cat /sys/fs/cgroup/system.slice/nginx.service/memory.max
```

```ini
# limit via systemd unit (paling mudah)
[Service]
LimitNOFILE=65535
MemoryMax=2G
MemoryHigh=1500M
CPUQuota=200%
IOReadBandwidthMax=/dev/sda 100M
TasksMax=512
```

| Setting | Efek |
| :--- | :--- |
| `MemoryMax` | batas keras → OOM kill di cgroup |
| `MemoryHigh` | batas lunak → throttle alokasi |
| `CPUQuota` | persen dari satu CPU (200% = 2 core) |
| `TasksMax` | jumlah task/thread |
| `LimitNOFILE` | fd per proses |

> **Jebakan:** `ulimit -n` di shell tidak memengaruhi service systemd — limit harus diset
> di unit (`LimitNOFILE`) atau `/etc/security/limits.conf` untuk session login.

## Kernel & sysctl

```bash
sysctl -a | grep net.ipv4.tcp_syncookies
sysctl -w net.core.somaxconn=4096      # sementara
sysctl --system                        # reload semua file /etc/sysctl.d

cat /proc/meminfo | head
cat /proc/loadavg
vmstat 1 5
iostat -xz 1 3
mpstat -P ALL 1 3
sar -u 1 5; sar -r 1 5                 # sysstat
```

```ini
# /etc/sysctl.d/99-tuning.conf
net.core.somaxconn = 4096
net.ipv4.tcp_max_syn_backlog = 8192
net.ipv4.ip_local_port_range = 10240 65000
net.ipv4.tcp_tw_reuse = 1
fs.file-max = 2097152
vm.swappiness = 10
```

| Parameter | Arti |
| :--- | :--- |
| `vm.swappiness` | kecenderungan swap (10–30 server database) |
| `vm.overcommit_memory` | strategi alokasi (1 = selalu izinkan) |
| `net.core.somaxconn` | backlog accept maksimum |
| `fs.file-max` | fd maksimum sistem |
| `kernel.pid_max` | batas PID |

> **Jebakan:** menyetel `vm.overcommit_memory=1` untuk "supaya tidak OOM" justru membuat
> OOM killer menembak proses acak ketika memori benar-benar habis.

## Container dasar

```bash
docker ps -a; docker logs -f --tail 100 app
docker exec -it app sh
docker stats --no-stream
docker inspect app | head -40
docker system df; docker system prune -af

# tanpa docker: namespace & cgroup
unshare --pid --fork --mount-proc bash
ip netns add test; ip netns list
nsenter -t 1234 -n ss -tlnp        # masuk net namespace proses
```

| Perintah | Fungsi |
| :--- | :--- |
| `nsenter` | masuk namespace proses lain (debug container) |
| `unshare` | buat namespace baru |
| `systemd-cgls` | pohon cgroup |
| `systemd-run --scope` | jalankan perintah dengan limit |

> **Jebakan:** `docker exec` memakai namespace container tapi binary host jika image
> tidak punya shell. Untuk container distroless gunakan `nsenter` dari host.

## Troubleshooting performa

```bash
# urutan diagnosa: load → CPU → memori → I/O → jaringan
uptime; cat /proc/loadavg
top -b -n1 | head -15
pidstat 1 5
vmstat 1 5
iostat -xz 1 3
ss -s; ss -ti | head -30
dmesg -T | tail -50                # OOM, I/O error
journalctl -p err -b --no-pager | tail -30
```

| Gejala | Alat | Petunjuk |
| :--- | :--- | :--- |
| Load tinggi, CPU idle | `ps -eo stat,wchan,cmd` | proses di `D` = I/O menunggu |
| Memori penuh | `free -h`, `/proc/meminfo` | `available` rendah → akan OOM |
| OOM kill | `dmesg`, `journalctl -k` | "Killed process … out of memory" |
| I/O lambat | `iostat -xz` | `%util` ~100, `await` tinggi |
| Network lambat | `ss -ti`, `mtr` | retransmit, rtt naik |
| Disk penuh | `df -h`, `df -i` | data vs inode |
| Boot lambat | `systemd-analyze blame` | unit terlama |

> **Jebakan:** `load average` tinggi tidak selalu berarti CPU sibuk — proses yang menunggu
> disk (`D`) juga dihitung. Selalu cek `vmstat` kolom `wa`.

## Jebakan (wajib dibaca)

| Jebakan | Gejalanya | Solusinya |
| :--- | :--- | :--- |
| `fstab` salah UUID | boot ke emergency mode | `mount -a` sebelum reboot |
| `chmod -R 777` | masalah "hilang" tapi tidak aman | perbaiki grup/ACL |
| Direktori tanpa `x` | tidak bisa masuk walau punya `r` | `chmod a+X` |
| `kill -9` untuk semua | data korup, lock tertinggal | SIGTERM dulu + timeout |
| Zombie di-`kill` | tidak hilang | perbaiki parent (`wait`) |
| Proses `D` ditunggu | tidak bisa dibunuh | selesaikan I/O |
| `Restart=always` + config rusak | restart loop | `on-failure` + `StartLimitBurst` |
| `daemon-reload` dilupakan | unit lama tetap jalan | `systemctl daemon-reload` |
| Timer tanpa `Persistent=` | job terlewat saat host mati | `Persistent=true` |
| `ulimit` di shell | service tidak terpengaruh | `LimitNOFILE` di unit |
| LVM extend tanpa resize FS | `df` tidak berubah | `lvextend -r` |
| `df` penuh, `du` kecil | file dibuka proses | `lsof +L1` |
| inode habis | "No space left" padahal disk lega | `df -i`, bersihkan file kecil |
| Service listen `localhost` | tidak terjangkau dari luar | bind `0.0.0.0` / proxy |
| `netstat` di distro baru | perintah tidak ada | `ss` |
| `sysctl -w` tanpa persistence | hilang setelah reboot | `/etc/sysctl.d/` |
| `swappiness=0` | bisa OOM mendadak | 10–30 |
| `NOPASSWD: ALL` | eskalasi trivial | per-command |
| Container `docker exec` di distroless | tidak ada shell | `nsenter` dari host |
