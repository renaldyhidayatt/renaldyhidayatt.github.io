# Terraform — Cheat Sheet

> Target: **Terraform 1.9+** (OpenTofu 1.8 compatible with almost all examples).
> Examples use a common pattern: one root module, several child modules, remote state in cloud
> storage, CI that runs `plan` and then `apply` from a plan file.

## Mental model & workflow

```text
code (.tf) ──> init ──> plan ──> apply ──> state ──> remote
               │          │        │        │
               │          │        │        └── source of truth mapping code ↔ resources
               │          │        └── provider calls the API
               │          └── diff of state + code + real conditions (refresh)
               └── download providers & modules, write lock file
```

| Concept | Meaning |
| :--- | :--- |
| **Configuration** | the `.tf`/`.tf.json` files you write |
| **State** | record of which real resources each code address represents |
| **Provider** | plugin that translates HCL into API calls (AWS, GCP, Kubernetes, ...) |
| **Resource** | an object that is managed (`aws_instance`, `kubernetes_deployment`) |
| **Data source** | an object that is only **read** (`data aws_ami`) |
| **Module** | a reusable configuration package |

> **Main takeaway:** Terraform compares **code ↔ state ↔ reality**. If the three are
> out of sync, the `plan` output gets weird. Nearly every "why does it want to recreate?" issue originates here.

## Project & module structure

```text
infra/
├── envs/
│   ├── staging/           # root module (run terraform from here)
│   │   ├── main.tf
│   │   ├── variables.tf
│   │   ├── outputs.tf
│   │   ├── backend.tf
│   │   └── terraform.tfvars
│   └── production/        # another root module, separate state
├── modules/
│   ├── network/           # child module: inputs, outputs, no provider config
│   ├── app/               # child module
│   └── database/
└── .gitignore             # .terraform/, *.tfstate*, *.tfplan, *.tfvars (if they contain real values)
```

```hcl
# envs/production/main.tf
terraform {
  required_version = ">= 1.9.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.60"          # minor is free, major is pinned
    }
  }
}

module "network" {
  source = "../../modules/network"

  cidr_block = var.cidr_block
  az_count   = 2
}

module "app" {
  source = "../../modules/app"

  vpc_id    = module.network.vpc_id
  subnet_id = module.network.private_subnet_ids[0]
  image     = var.app_image
}
```

| Rule | Why |
| :--- | :--- |
| Root module = 1 environment = 1 state | small blast radius, fast plan |
| Child modules have no `provider` block | providers are inherited from the root |
| Child modules have `variables.tf` + `outputs.tf` | clear contract, easy to test |
| Commit `.terraform.lock.hcl` | identical provider versions in CI & on laptops |
| `.terraform/` in gitignore | contains provider binaries |
| Never store `terraform.tfstate` in git | contains sensitive data & conflicts quickly |

## Daily commands

```bash
terraform init                    # download providers & modules, write lock
terraform init -upgrade           # upgrade according to constraints
terraform validate                # syntax + types, no connection
terraform fmt -recursive          # format HCL
terraform plan -out=tf.plan       # save the plan
terraform show tf.plan            # read the plan (human readable)
terraform apply tf.plan           # apply the plan you already reviewed
terraform apply -auto-approve     # CI only, after the plan has been reviewed

terraform output -json
terraform state list
terraform state show 'aws_instance.app[0]'
terraform console                 # REPL for testing expressions
```

| Command | When |
| :--- | :--- |
| `plan -detailed-exitcode` | CI: 0 = no changes, 1 = error, 2 = there are changes |
| `plan -target=...` | emergencies only — does not guarantee a consistent end state |
| `apply -replace=...` | explicitly recreate a single resource |
| `import` / `moved` | adopt existing resources without destroying them |
| `state mv` / `state rm` | refactor addresses without touching the remote |
| `force-unlock <id>` | state locked because the process died |
| `refresh` | sync state with reality (plan already does this) |
| `destroy` | tear down the whole stack — use only for ephemeral environments |

## Providers & authentication

```hcl
terraform {
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 5.60" }
    kubernetes = { source = "hashicorp/kubernetes", version = "~> 2.31" }
  }
}

provider "aws" {
  region = var.region
  # credentials DO NOT go here — use env / profile / OIDC role
  default_tags {
    tags = { Project = var.project, ManagedBy = "terraform", Env = var.env }
  }
}

provider "kubernetes" {
  config_path = "~/.kube/config"
}
```

```bash
# credentials via environment (never end up in the repo/state)
export AWS_PROFILE=dev
export AWS_REGION=ap-southeast-1
# CI/cloud: OIDC role, not static keys

# use an alternate provider per region / per account
# provider "aws" { alias = "replica"; region = "ap-northeast-1" }
```

| Rule | Why |
| :--- | :--- |
| Credentials via env/OIDC | static keys in files = leaked in git history |
| `alias` for multi-region/account | one root module, many provider instances |
| `default_tags` on the provider | consistent tagging without repeating it on every resource |
| Pin providers per major | major upgrade = breaking change + force-new |
| `insecure` / `skip_credentials_validation` | only for local/self-hosted endpoints, never production |

## Variables, types, validation

```hcl
# variables.tf
variable "env" {
  description = "Environment name"
  type        = string

  validation {
    condition     = contains(["staging", "production"], var.env)
    error_message = "env must be staging or production."
  }
}

variable "network" {
  type = object({
    cidr    = string
    azs     = list(string)
    nat_gw  = bool
  })
  default = { cidr = "10.0.0.0/16", azs = ["a", "b"], nat_gw = true }
}

variable "instances" {
  description = "Instance per application. Key = unique name."
  type = map(object({
    size    = string
    count   = optional(number, 1)
    spot    = optional(bool, false)
    ports   = optional(list(number), [80])
  }))
}

variable "db_password" {
  type      = string
  sensitive = true            # hidden in CLI output/logs
}
```

```hcl
# terraform.tfvars (real values — do not commit if they contain sensitive data)
env  = "production"
region = "ap-southeast-1"

instances = {
  api = { size = "t3.small", count = 2 }
  web = { size = "t3.micro", ports = [80, 443] }
}
```

| Value source (low → high) | Note |
| :--- | :--- |
| `default` in `variable` | safe value |
| `terraform.tfvars` / `*.auto.tfvars` | read automatically |
| `-var-file=...` | explicit per environment |
| `TF_VAR_name` | CI & secret injection |
| `-var name=value` | quick override in the terminal |
| `TF_CLI_ARGS_plan="-var-file=x"` | affects all invocations |

> **Pitfall #1:** `sensitive = true` only hides the value in **CLI output** — the value is still
> stored in plaintext in state. Don't store passwords in variables if you can reference
> a secret manager instead.

## `for_each`, `count`, `locals`, `dynamic`

```hcl
locals {
  common_tags = {
    Project = var.project
    Env     = var.env
    Owner   = var.owner
  }

  # flatten: list of objects -> map with stable keys
  subnets = {
    for s in var.subnets : "${s.az}-${s.tier}" => s
  }

  # resolve defaults + label
  apps = {
    for name, cfg in var.instances : name => merge(cfg, {
      name = "${var.env}-${name}"
      tags = merge(local.common_tags, { App = name })
    })
  }
}

# for_each = stable addresses (keys), safe to add/remove
resource "aws_instance" "app" {
  for_each = local.apps

  ami           = data.aws_ami.app.id
  instance_type = each.value.size
  count         = each.value.count   # <- this is WRONG: count cannot come from a for_each item
}

# count = numeric index, for "N copies of" a resource
resource "aws_iam_user" "ci" {
  count = 3
  name  = "ci-runner-${count.index + 1}"
}

# dynamic block: repeating block from a list
resource "aws_security_group" "app" {
  name   = "${var.env}-app"
  vpc_id = module.network.vpc_id

  dynamic "ingress" {
    for_each = var.allowed_ports
    content {
      from_port   = ingress.value
      to_port     = ingress.value
      protocol    = "tcp"
      cidr_blocks = ["10.0.0.0/8"]
    }
  }
}
```

| Pattern | Result |
| :--- | :--- |
| `for_each` with a map/set | keyed addresses; removing one item does not shift the others |
| `count` | index-based addresses; removing a middle element shifts everything after it |
| `merge()` | merge maps; right-hand values win |
| `flatten()` / `tolist()` / `toset()` | type normalization for `for_each` |
| `lookup(map, key, default)` | value with a fallback |
| `try(expr, fallback)` | safe for attributes that may not exist |
| `for ... : k => v` | collection projection/transformation |
| `one(list)` | take one element / null (replacement for `[0]` which errors when empty) |

> **Pitfall #2:** `count` must not depend on a value that is unknown at plan time
> ("The 'count' value depends on resource attributes that cannot be determined until apply").
> Fix: move the decision into a variable/locals or use `for_each`.
> **Pitfall #3:** `for_each` does not accept a list — use `toset()` or a map.

## Resources, data sources, dependencies

```hcl
data "aws_ami" "app" {
  most_recent = true
  owners      = ["self"]

  filter {
    name   = "name"
    values = ["app-${var.app_version}-*"]
  }
}

resource "aws_instance" "app" {
  for_each = local.apps

  ami                    = data.aws_ami.app.id
  instance_type          = each.value.size
  subnet_id              = module.network.private_subnet_ids[0]
  vpc_security_group_ids = [aws_security_group.app.id]

  user_data = templatefile("${path.module}/templates/init.sh.tftpl", {
    env     = var.env
    app     = each.key
    version = var.app_version
  })

  # explicit: wait for other resources to finish first
  depends_on = [aws_iam_role_policy.app]

  tags = each.value.tags

  lifecycle {
    create_before_destroy = true
    ignore_changes        = [user_data, tags["LastModified"]]
  }
}
```

| Mechanism | When |
| :--- | :--- |
| **Implicit dependency** | references between resources (`module.x.y`, `aws_x.y.id`) — most recommended |
| **Explicit `depends_on`** | side effects that are not visible in attributes (IAM propagation, DNS) |
| `data` | read an existing object (AMI, VPC, secret) — always refreshed at plan time |
| `ephemeral` (1.10+) | sensitive data that must not enter state |
| `terraform_data` | no-op resource to trigger `triggers_replace` / local provisioners |
| `provisioner` | **avoid**; use cloud-init/user_data or configuration management |

> **Pitfall #4:** a `data` source that references a resource in the same module may be read
> **before** that resource is created on the first apply — resulting in an error or an empty value.
> Don't mix `data` and `resource` for the same object within one root module.

## Modules

```hcl
# modules/network/variables.tf
variable "cidr_block" { type = string }
variable "az_count"   { type = number, default = 2 }

# modules/network/outputs.tf
output "vpc_id"              { value = aws_vpc.this.id }
output "private_subnet_ids"  { value = aws_subnet.private[*].id }
```

```hcl
# root — use a local module
module "network" {
  source = "../../modules/network"

  cidr_block = "10.0.0.0/16"
  az_count   = 3
}

# registry module (pin the version!)
module "eks" {
  source  = "terraform-aws-modules/eks/aws"
  version = "~> 20.24"

  cluster_name    = "${var.env}-eks"
  cluster_version = "1.30"
  vpc_id          = module.network.vpc_id
}
```

```bash
terraform init                      # fetch modules
terraform init -upgrade             # upgrade modules according to constraints
terraform get -update
```

| Rule | Why |
| :--- | :--- |
| `source` + `version` for registry | no version = non-reproducible build |
| `providers = { aws = aws.replica }` | module uses a specific provider instance |
| Modules must not write their own state | `terraform` inside a module = two sources of truth |
| `count`/`for_each` on modules is allowed | careful: changing the key = recreating module contents |
| `terraform-docs` | automatic input/output documentation |
| Small, specific modules | "does everything" modules are hard to test & upgrade |

> **Pitfall #5:** changing `source` from local to registry (or vice versa) without
> `state mv` makes Terraform treat all module contents as new resources.

## `terraform_remote_state` & cross-stack dependencies

```hcl
# network stack: exposes outputs
output "vpc_id" { value = aws_vpc.this.id }

# app stack: reads another stack's outputs
data "terraform_remote_state" "network" {
  backend = "s3"
  config = {
    bucket = "tfstate-prod"
    key    = "network/terraform.tfstate"
    region = "ap-southeast-1"
  }
}

resource "aws_instance" "app" {
  subnet_id = data.terraform_remote_state.network.outputs.private_subnet_ids[0]
}
```

| Approach | When |
| :--- | :--- |
| `terraform_remote_state` | separate stack but you need its outputs (loose coupling) |
| Provider `data` (SSM/VPC lookup) | avoid state coupling entirely — more refactor-proof |
| Single root module | for small systems; avoid if the blast radius is large |
| `dependency` in Terragrunt / orchestration | automatic apply ordering across stacks |

> **Pitfall #6:** `terraform_remote_state` makes the reader stack depend on the writer stack's
> **state format**. Renaming an output = the reader stack breaks on the next plan.

## Import & `moved`

```hcl
# 1.9+: import block — the resource is written manually, then adopted
import {
  to = aws_instance.app["api"]
  id = "i-0123456789abcdef0"
}

# change the address without destroying (refactor)
moved {
  from = aws_instance.old_name
  to   = aws_instance.app["api"]
}

moved {
  from = module.legacy_app
  to   = module.app
}
```

```bash
# CLI: one at a time
terraform import 'aws_instance.app["api"]' i-0123456789abcdef0
terraform plan                       # match the config until "No changes"

# unmanage a resource that is about to be deleted
terraform state rm 'aws_instance.legacy'   # stop managing it, does NOT delete it
```

| Scenario | Tool |
| :--- | :--- |
| Adopt a manually created resource | `import` block / `terraform import` |
| Rename a resource / module | `moved` block (1.1+) |
| Move a `for_each` key | `moved` from `["a"]` to `["b"]` |
| Stop managing | `state rm` |
| Move between states | `terraform state pull/push` or `import` in the new stack |
| Bulk import | generator (`former2`/`terraformer`) then clean up |

> **Pitfall #7:** import does not write configuration. After `import`, you must write a
> resource block that is **identical** to reality — any attribute difference = a diff that tries to change
> the real infrastructure on the next `apply`.

## `lifecycle` (meta-argument)

```hcl
lifecycle {
  prevent_destroy       = true                     # refuse destroy (important data)
  create_before_destroy = true                     # zero-downtime replace
  ignore_changes        = [tags["LastModified"], user_data]
  replace_triggered_by  = [null_resource.version]  # recreate when the trigger changes
  precondition {                                    # 1.2+: validate before the operation
    condition     = var.env != "production" || var.multi_az
    error_message = "production requires multi_az."
  }
  postcondition {
    condition     = self.private_ip != ""
    error_message = "instance must have a private IP."
  }
}
```

| Attribute | Effect | Risk |
| :--- | :--- | :--- |
| `prevent_destroy` | apply fails when it plans a destroy | must be removed manually for an intentional destroy |
| `ignore_changes` | attribute diffs are ignored | drift goes undetected (intentional) |
| `create_before_destroy` | new resource first | unique name/ID conflicts & temporary double cost |
| `replace_triggered_by` | recreate when a reference changes | chained recreations |
| `precondition` / `postcondition` | validation gate | plan fails earlier (good) |

> **Pitfall #8:** `prevent_destroy` does not protect against `terraform destroy -target` on the
> **parent** resource, and does not block changes made outside Terraform (manual deletion in the
> console). It only guards destroys planned by Terraform.

## Outputs & secrets

```hcl
output "app_endpoints" {
  value = { for k, v in aws_instance.app : k => v.public_dns }
}

output "db_connection" {
  value     = "postgres://${aws_db_instance.this.address}:5432/app"
  sensitive = false
}

output "admin_password" {
  value     = random_password.admin.result
  sensitive = true            # still plaintext in state!
}
```

| Rule | Why |
| :--- | :--- |
| Outputs = the contract between stacks/modules | rename = breaking change |
| `sensitive` is cosmetic only | state stays plaintext — encrypt the backend |
| Never output secrets | use a secret manager + `data`/`ephemeral` |
| `terraform output -json` | used by CI scripts & tooling |
| `precondition` in modules | fail fast when the output contract is not met |

## State, backend, workspaces

```hcl
# backend.tf — remote state with locking
terraform {
  backend "s3" {
    bucket         = "tfstate-prod"
    key            = "app/terraform.tfstate"
    region         = "ap-southeast-1"
    dynamodb_table = "tf-locks"        # locking
    encrypt        = true
  }
}
```

```bash
terraform state list
terraform state show 'aws_instance.app["api"]'
terraform state mv 'aws_instance.a' 'aws_instance.b'
terraform state rm 'aws_instance.c'
terraform state pull > backup.tfstate          # backup before refactoring

terraform workspace list
terraform workspace new staging
terraform workspace select production
```

| Topic | Practice |
| :--- | :--- |
| Backend | remote (S3+GCS+Azure) + **locking**; never local for a team |
| Encryption | mandatory — state contains sensitive attributes |
| Bucket versioning | fast & safe state rollback |
| Workspaces | only for identical, small environments; for different structures use separate directories |
| `terraform.tfstate.backup` | not a substitute for versioning |
| Manual state edits | only via `state mv/rm`, never edit the JSON |

> **Pitfall #9:** workspaces share **code** — if staging needs different resources,
> `count`/`for_each` will change and can delete resources in another workspace when the
> environment is differentiated with `terraform.workspace` inside `count`.

## Drift & reconciliation

```bash
# detect in CI
terraform plan -detailed-exitcode -lock=false; echo "exit=$?"   # 2 = drift

# see what is outside the code
terraform plan -refresh-only        # show drift without changing resources
terraform apply -refresh-only       # accept reality into state
```

| Drift | Ideal response |
| :--- | :--- |
| Small manual change that is correct | accept it into the code (update config), then `plan` → no changes |
| Manual change that is wrong | `apply` to restore it to the code |
| Resource created outside Terraform | `import` + write config |
| Resource deleted outside | decide: recreate (apply) or `state rm` |
| Attributes that are genuinely dynamic | `ignore_changes` with a written rationale |

> **Pitfall #10:** a `plan` without refresh (`-refresh=false`) hides
> drift. Only use it when you are sure state was just refreshed (e.g. plan and apply back to back).

## Testing & validation

```bash
terraform fmt -check -recursive
terraform validate
tflint                                 # provider-aware lint
checkov -d .                           # security scan
trivy config .                         # alternative security scan
terraform plan -lock=false -input=false   # gate in CI
```

```hcl
# terraform test (1.6+)
# tests/app.tftest.hcl
variables {
  env  = "staging"
  region = "ap-southeast-1"
}

run "plan_app" {
  command = plan

  assert {
    condition     = aws_instance.app["api"].instance_type == "t3.small"
    error_message = "api instance must be t3.small"
  }
}

run "apply_and_check" {
  command = apply

  assert {
    condition     = output.app_endpoints["web"] != ""
    error_message = "web endpoint is empty"
  }
}
```

| Test layer | Needs cloud? | Coverage |
| :--- | :--- | :--- |
| `validate` + `fmt` | no | syntax, types |
| `tflint` / `checkov` | no | provider & security practices |
| `terraform test` (`command = plan`) | no | variable & plan logic |
| `terraform test` (`command = apply`) | yes (or localstack) | real behavior |
| Terratest / kitchen-terraform | yes | end-to-end integration |

## CI/CD

```yaml
# example flow (generic format)
plan:      terraform init -> validate -> plan -out=tf.plan -> save artifact
review:    comment the plan to the PR (the plan must be read by a human)
apply:     terraform apply tf.plan        # only on the main branch, after approval
cleanup:   terraform destroy -auto-approve (ephemeral environments)
```

| CI rule | Why |
| :--- | :--- |
| `plan` and `apply` use the **same plan file** | apply cannot differ from what was reviewed |
| State locking enabled | two pipelines don't overwrite each other |
| `-input=false` | CI must not wait for input |
| OIDC/short-lived credentials | no static keys in the runner |
| `TF_IN_AUTOMATION=1` | quieter, more consistent output |
| Plan commented to the PR | review = a conscious decision, not blind auto-approve |

## Pitfalls (must read)

| Pitfall | Symptom | Fix |
| :--- | :--- | :--- |
| `count` from an unknown attribute | "depends on resource attributes that cannot be determined" | move it to a variable/locals or `for_each` |
| Change a `for_each` key | destroy + create everything | `moved` block |
| `for_each` given a list | error "must be a map or set" | `toset(list)` |
| Import without writing config | plan wants to change/delete resources | write identical config, plan → No changes |
| `sensitive` mistaken for encryption | secrets readable in state | encrypt the backend + secret manager |
| Local state for a team | conflicts & lost resources | remote backend + locking |
| Excessive `ignore_changes` | drift is invisible | limit it to dynamic attributes |
| `create_before_destroy` on a unique name | name/ID conflict during replace | `name_prefix` / unique address |
| `data` + `resource` for the same object | empty value on the first apply | use the resource reference |
| Upgrading a provider without pinning | unexpected force-new | `~>` + commit the lock file |
| `apply` without reading the plan | destructive changes | `plan -out` → review → `apply plan` |
| Provider inside a child module | two competing provider configs | providers only at the root |
