## A01 Broken Access Control

Symptom: user A can read/modify user B's data, or an ordinary user can perform admin actions.

```java
// WRONG: IDOR — trusting the id from the client
@GetMapping("/api/orders/{id}")
public Order get(@PathVariable Long id) {
    return repo.findById(id).orElseThrow();
}

// RIGHT: scope to the principal
@GetMapping("/api/orders/{id}")
public Order get(@PathVariable Long id, @AuthenticationPrincipal UserPrincipal user) {
    return repo.findByIdAndOwnerId(id, user.id())
               .orElseThrow(() -> new AccessDeniedException("not found"));  // 404, not 403
}
```

```java
// centralized authorization, not scattered ifs
@Component
public class OrderPolicy {
    public boolean canRead(UserPrincipal p, Order o) {
        return p.admin() || o.ownerId().equals(p.id());
    }
}
```

```yaml
# DEFAULT-DENY in the framework (Spring Security)
security:
  endpoints:
    - path: "/api/public/**"     # explicit allowlist
      permitAll: true
    - path: "/api/admin/**"
      roles: [ADMIN]
    - path: "/**"
      authenticated: true
```

| Control | Implementation |
| :--- | :--- |
| Object-level authz | check ownership in the query, not after fetching |
| Function-level authz | `@PreAuthorize`, per-route middleware |
| Do not rely on the UI | admin endpoints are still validated |
| 404 vs 403 | do not leak resource existence |
| `CORS` | origin allowlist, never `*` with credentials |
| Directory traversal | normalize the path, reject `..` (`/files?name=../../etc/passwd`) |
| JWT claim | take the role from a verified token, not from the `X-Role` header |

```java
// path traversal
Path base = Path.of("/srv/files").toRealPath();
Path target = base.resolve(name).normalize();
if (!target.startsWith(base)) throw new IllegalArgumentException("invalid path");
```

> **Pitfall:** `@PreAuthorize` on a controller is often bypassed because another endpoint
> (internal, actuator, graphql) maps the same service without the annotation. Test every route.

## A02 Cryptographic Failures

| What fails | Fix |
| :--- | :--- |
| HTTP for sensitive data | HTTPS + HSTS, permanent redirect |
| MD5/SHA1 for passwords | Argon2id / bcrypt / scrypt |
| Rolling your own encryption | use AES-GCM/ChaCha20-Poly1305 from a standard library |
| IV/nonce reused | unique random nonce per message |
| Keys in repo/config | KMS / Vault / env + rotation |
| Sensitive data in logs | redaction, do not log bodies/credentials |
| Data at rest without encryption | disk/column encryption + separate key |

```java
// password hashing (Spring Security)
PasswordEncoder encoder = new Argon2PasswordEncoder(16, 32, 1, 1 << 16, 3);
String hash = encoder.encode(rawPassword);
boolean ok = encoder.matches(rawPassword, hash);
// bcrypt (alternative): new BCryptPasswordEncoder(12)
```

```java
// symmetric encryption: AES-256-GCM, 12-byte random nonce per message
byte[] nonce = new byte[12];
SecureRandom rnd = new SecureRandom();
rnd.nextBytes(nonce);

Cipher c = Cipher.getInstance("AES/GCM/NoPadding");
c.init(Cipher.ENCRYPT_MODE, new SecretKeySpec(key, "AES"), new GCMParameterSpec(128, nonce));
byte[] ct = c.doFinal(plaintext);
// store the nonce together with the ciphertext; DO NOT use the same nonce twice
```

| Rule | Detail |
| :--- | :--- |
| TLS | TLS 1.2+ (prefer 1.3), HSTS `max-age` ≥ 6 months |
| Random | `SecureRandom` / `crypto/rand` — not `Math.random`/`rand()` |
| Hash | SHA-256+ for integrity; passwords use a salted KDF |
| Comparison | constant-time (`MessageDigest.isEqual`, `hmac.Equal`) |
| Key rotation | key id (`kid`) in the ciphertext/JWT |
| Certificates | `curl`/client verify — never `InsecureSkipVerify` |

> **Pitfall:** encryption that accepts `insecure=true`/`skipVerify` usually spreads into
> production through a single debug flag. Block it at the configuration level.

## A03 Injection

Injection = user data executed as **code/query** (SQL, OS, LDAP, template, log).

```java
// SQL — WRONG
String q = "SELECT * FROM users WHERE email = '" + email + "'";
// SQL — RIGHT: prepared statement
jdbcTemplate.query("SELECT * FROM users WHERE email = ?", rs -> ..., email);

// JPA: parameter binding, not concat
@Query("select u from User u where u.email = :email")
Optional<User> byEmail(@Param("email") String email);

// dynamic JPQL: avoid string concat; use Criteria/Specification
```

```java
// OS command injection
// WRONG
Runtime.getRuntime().exec("convert " + userFile + " out.png");
// RIGHT: separate arguments, no shell
new ProcessBuilder("convert", userFile, "out.png").start();
```

```javascript
// NoSQL injection (MongoDB) — the object {$gt: ""} slips past the string check
// WRONG
users.find({ email: req.body.email });
// RIGHT: force the type
const email = String(req.body.email);
if (!/^[^@\s]+@[^@\s]+\.[a-z]{2,}$/i.test(email)) throw new Error("invalid");
users.find({ email: email });
```

```html
<!-- XSS: escape output according to context -->
<!-- framework templates auto-escape; DO NOT bypass -->
<div th:text="${comment}"></div>       <!-- safe -->
<div th:utext="${comment}"></div>      <!-- WRONG: raw HTML -->
```

| Type | Main control |
| :--- | :--- |
| SQL/JPQL | parameter binding; parameterized ORM queries; least-privilege DB user |
| NoSQL | type validation; reject operators in input; `$where` forbidden |
| OS command | avoid the shell; `ProcessBuilder` with arguments; allowlist |
| Template (SSTI) | never render templates from input; sandbox |
| XSS | escape by context, CSP, `HttpOnly` cookie |
| Log injection | sanitize newlines in input before logging |
| LDAP/XML | escape/parameterize, disable external entities (XXE) |
| Path/header | allowlist validation, do not forward raw headers |

```http
Content-Security-Policy: default-src 'self'; script-src 'self'; object-src 'none'; base-uri 'none'
```

> **Pitfall:** `PreparedStatement` does not protect table/column names that are concatenated.
> For dynamic identifiers use an allowlist, not escaping.

## A04 Insecure Design

Different from a wrong implementation: the **design** itself is insecure.

```text
insecure design examples:
  - password reset without expiry & without a single-use token
  - no quota/rate limit → brute force & scraping
  - a checkout flow that trusts the price from the client
  - an "admin panel" hidden in the URL (security by obscurity)
  - no limit on the number of OTP attempts
```

| Domain | Design control |
| :--- | :--- |
| Auth | rate limit per account + per IP, progressive lockout, MFA |
| Password reset | random token ≥128 bit, 15–60 minute expiry, single use, invalidate session |
| Business flow | validate price/stock on the server, idempotency key |
| Multi-tenant | tenant id from the session, not from the request body |
| File upload | size limit, type allowlist, scan, store outside the webroot |
| Anti-automation | CAPTCHA on sensitive endpoints, pattern detection |
| Privacy | minimize data, limited retention |

```java
// rate limit per account+IP (concept example)
if (!limiter.tryAcquire("login:" + username + ":" + ip, 5, Duration.ofMinutes(5))) {
    throw new TooManyRequestsException();
}
```

> **Pitfall:** a UI that hides a button is not access control. Every limit must be
> enforced on the server and tested with direct requests.

## A05 Security Misconfiguration

```bash
# container & host: no root, no privileged
docker run --user 10001 --read-only --cap-drop ALL --security-opt no-new-privileges app
```

| Area | Wrong | Right |
| :--- | :--- | :--- |
| Default account | `admin/admin` active | must change + disable |
| Debug | `DEBUG=true`, stack trace to the client | off in production, generic error |
| Actuator | `/actuator/env` exposed | limited exposure + auth |
| CORS | `Access-Control-Allow-Origin: *` + credentials | origin allowlist |
| Cloud storage | public bucket | private + pre-signed URL |
| Header | no CSP/HSTS | see the header table |
| Container | `privileged: true` | `CAP_DROP ALL`, read-only FS |
| Port | DB exposed to the internet | internal bind + firewall |
| Error | `e.printStackTrace()` in the response | server log, generic message |

```properties
# Spring Boot: disable dangerous exposure
management.endpoints.web.exposure.include=health,info,prometheus
management.endpoint.env.enabled=false
server.error.include-stacktrace=never
server.error.include-message=never
```

```yaml
# security headers example (nginx)
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "DENY" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Content-Security-Policy "default-src 'self'" always;
```

> **Pitfall:** `X-Frame-Options` does not apply across subdomains with `SAMEORIGIN`
> ambiguous — use `frame-ancestors` in CSP.

## A06 Vulnerable & Outdated Components

```bash
# Java
./mvnw org.owasp:dependency-check-maven:check
./mvnw versions:display-dependency-updates

# Node
npm audit --omit=dev
npm outdated

# Go
go run golang.org/x/vuln/cmd/govulncheck@latest ./...

# Rust
cargo audit

# container & image
trivy image app:latest --severity HIGH,CRITICAL
trivy fs .
grype dir:.

# SBOM
syft app:latest -o spdx-json > sbom.json
```

| Practice | Why |
| :--- | :--- |
| Pin versions + lockfile | reproducible builds |
| Renovate/Dependabot | fast & scheduled patching |
| SCA in CI (fail on HIGH) | no waiting for a manual audit |
| SBOM per release | know what is affected when a new CVE lands |
| Minimal, updated base image | attacks via unused components |
| Remove unused dependencies | reduced attack surface |

> **Pitfall:** an automatic `npm audit fix` can pull in major versions that change behavior.
> Review the diff, and separate patch from major upgrades.

## A07 Identification & Authentication Failures

```java
// JWT: verify the signature + the REQUIRED claims
Jws<Claims> jws = Jwts.parser()
    .verifyWith(publicKey)                 // public key, not the client's secret
    .requireIssuer("https://issuer")
    .requireAudience("order-api")
    .build()
    .parseSignedClaims(token);

Claims c = jws.getPayload();
if (c.getExpiration().before(new Date())) throw new ExpiredException();
```

| Control | Detail |
| :--- | :--- |
| Password | minimum length (12+), check against breach lists, not truncated to 72 bytes (bcrypt) |
| Session | `Secure; HttpOnly; SameSite=Lax/Strict`, rotate on login |
| Logout | invalidate server-side (not just delete the cookie) |
| MFA | TOTP/WebAuthn; single-use recovery codes |
| Brute force | rate limit, progressive delay, alert |
| Credential stuffing | device/IP detection, breached password check |
| JWT | pin `alg` (never `none`), `exp``+`nbf`, `aud``+`iss`, do not store in `localStorage` if XSS is a concern |
| Credentials | never in the URL/query string |

```java
// set the cookie with secure attributes
ResponseCookie c = ResponseCookie.from("sid", id)
    .httpOnly(true).secure(true).sameSite("Lax").path("/")
    .maxAge(Duration.ofHours(8)).build();
```

> **Pitfall:** decoding a JWT without verification (`parseClaimsJwt` vs `parseSignedClaims`) is
> the most frequently found auth bug in reviews.

## A08 Software & Data Integrity Failures

| Area | Control |
| :--- | :--- |
| Dependency | lockfile + checksum, private registry, never `latest` |
| CI/CD | signed artifacts, provenance (SLSA), scoped deploy keys |
| Update | signatures (official apt/dnf repos), checksum verification |
| Deserialization | no `ObjectInputStream` for external data; use a JSON schema |
| Webhook | verify HMAC signature + timestamp |
| Plugin/upload | allowlist, sandbox, never execute from the upload directory |
| Backup | integrity (checksum) + tested restore |

```java
// webhook verification (HMAC-SHA256)
String expected = HexFormat.of().formatHex(
    hmac("HmacSHA256", secret, body.getBytes(StandardCharsets.UTF_8)));
if (!MessageDigest.isEqual(expected.getBytes(), signature.getBytes())) {
    throw new UnauthorizedException("bad signature");
}
// reject timestamps that are too old (5-minute replay window)
```

```yaml
# CI: pin actions to a commit SHA, not a tag
- uses: actions/checkout@8ade135a41bc03ea155e62e844d188df1ea18608
```

> **Pitfall:** mutable `dependsOn`/tags in the pipeline enable a supply-chain attack without
> touching your repo. Pin to a digest/SHA.

## A09 Security Logging & Monitoring Failures

```java
// useful logs: authz/authn events + identity + outcome
log.warn("authz.denied user={} resource={} action={} ip={}",
         principal.id(), resource, action, clientIp);
log.info("authn.success user={} mfa={} ip={}", user, mfaUsed, clientIp);
log.warn("authn.fail user={} reason={} ip={}", user, "bad_password", clientIp);
```

| Must be logged | Must be avoided |
| :--- | :--- |
| successful/failed login, logout | passwords, tokens, cookies |
| permission & role changes | full PII (national ID, cards) |
| denied access (403) | request bodies containing secrets |
| creation/deletion of sensitive data | the Authorization header |
| 5xx errors + correlation id | stack traces to the client |
| admin & configuration events | logs without user/tenant |

| Control | Detail |
| :--- | :--- |
| Structured log | JSON + `trace_id`, `user_id`, `tenant` |
| Retention | enough for investigation (30–90 days) |
| Tamper-proof | send to a central system, read-only for the app |
| Alert | mass login failures, 403 spikes, privilege changes |
| Time sync | NTP — skewed timestamps make forensics impossible |
| Detection | alerts on patterns (credential stuffing, scraping) |

> **Pitfall:** logging a token or password "for debugging" sends that credential into
> the logging system, whose access is far broader than the database.

## A10 SSRF

The server is asked to fetch a URL that targets the internal network (cloud metadata, admin panel).

```java
// WRONG: forward the raw URL from the client
return restTemplate.getForObject(req.url(), String.class);

// RIGHT: allowlist + resolve + reject internal IPs + redirects off
URI target = URI.create(url);
if (!"https".equals(target.getScheme())) throw new BadRequest("scheme");
if (!ALLOWED_HOSTS.contains(target.getHost())) throw new BadRequest("host");

InetAddress addr = InetAddress.getByName(target.getHost());
if (addr.isLoopbackAddress() || addr.isSiteLocalAddress()
        || addr.isLinkLocalAddress() || addr.isAnyLocalAddress()) {
    throw new BadRequest("blocked address");
}
// HttpClient with followRedirects(NEVER), timeout, bounded response size
```

| Attack target | Example |
| :--- | :--- |
| Cloud metadata | `http://169.254.169.254/latest/meta-data/` |
| Internal admin | `http://localhost:8080/admin` |
| Internal service mesh | `http://service.namespace.svc` |
| File protocol | `file:///etc/passwd` |
| DNS rebinding | a public domain resolving to an internal IP |

| Control | Detail |
| :--- | :--- |
| Domain allowlist | not a blocklist |
| Resolve & check IP | reject private/loopback/link-local/multicast |
| Redirects | disable or validate every hop |
| Timeout & size limit | prevent resource exhaustion |
| Egress firewall | deny outbound to metadata & internal by default |
| Alternative | do not proxy client URLs; use an object id |

> **Pitfall:** validating the host **before** DNS resolution is not enough — DNS rebinding can
> return an internal IP. Validate the resolved IP, and pin the connection to that IP.

## Header & cookie checklist

| Header | Value |
| :--- | :--- |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains; preload` |
| `Content-Security-Policy` | source allowlist; `frame-ancestors 'none'` |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | disable unused features (camera, geolocation) |
| `Cache-Control` | `no-store` for sensitive responses |
| `Server` / `X-Powered-By` | remove (version information) |

```http
Set-Cookie: sid=...; Path=/; Secure; HttpOnly; SameSite=Lax; Max-Age=28800
```

| Cookie | Why |
| :--- | :--- |
| `Secure` | only over HTTPS |
| `HttpOnly` | not readable by JS (XSS mitigation) |
| `SameSite=Lax/Strict` | CSRF mitigation; `None` requires `Secure` |
| `__Host-` prefix | locks it to the host & the `/` path |

## Testing: SAST / DAST / SCA / threat model

```bash
# SAST (source)
semgrep --config=p/owasp-top-ten .
./mvnw spotbugs:check

# SCA (dependency)
trivy fs --scanners vuln,secret,misconfig .
grype .

# DAST (runtime) — only against permitted environments
zap-baseline.py -t https://staging.example.com
nuclei -u https://staging.example.com

# secret scanning
gitleaks detect --no-git -v
```

| Activity | When |
| :--- | :--- |
| Threat model | during feature design (STRIDE/LINDDUN) |
| SAST | every PR (gate for HIGH) |
| SCA | every build + daily (new CVEs) |
| DAST | nightly against staging |
| Pen test | before a major release / yearly |
| Security code review | auth, upload, payment, integration features |

| OWASP Resource | Contents |
| :--- | :--- |
| Top 10 | risk list (this sheet) |
| ASVS | technical verification checklist (L1–L3) |
| Cheat Sheet Series | per-topic guides (JWT, session, file upload) |
| Dependency-Check / ZAP | SCA & DAST tools |
| Juice Shop / WebGoat | practice (only in your own lab) |

> **Pitfall:** DAST against a production environment without permission is an unauthorized act, even
> for a "check". Always use a dedicated staging environment and written permission.

## Pitfalls (must read)

| Pitfall | Impact | Fix |
| :--- | :--- | :--- |
| Authorization only in the UI | IDOR (A01) | check ownership in the server query |
| Role from header/body | privilege escalation | take it from a verified token |
| Inconsistent `@PreAuthorize` | leaked endpoints | test every route |
| SQL without binding | injection (A03) | prepared statement |
| Concatenated dynamic identifiers | injection still possible | allowlist |
| HTML escaped in the wrong context | XSS | escape per context + CSP |
| MD5/SHA1 passwords | credentials cracked quickly | Argon2id/bcrypt |
| Reused nonce/IV | leaked key | random nonce per message |
| `insecureSkipVerify` | MITM | certificate verification |
| JWT without signature verification | forged auth | `parseSignedClaims` |
| Accepting `alg: none` | forged token is valid | pin the algorithm |
| Token in `localStorage` | XSS steals the session | HttpOnly cookie |
| Logout only deletes the cookie | session stays alive | invalidate server-side |
| No rate limit | brute force/stuffing | limit per account+IP |
| Reset token without expiry | permanent access | single-use + expiry |
| Exposed actuator/debug | info & RCE | minimal exposure + auth |
| CORS `*` + credentials | data theft | origin allowlist |
| Public bucket | data leak | private + signed URL |
| Blind `npm audit fix` | production regression | review patch vs major |
| Dependencies without a lockfile | non-reproducible builds | commit the lock + SBOM |
| Deserializing external objects | RCE | JSON schema |
| Webhook without HMAC | forged events | verify signature + timestamp |
| SSRF without an allowlist | internal metadata access | allowlist + check the resolved IP |
| Redirects followed freely | SSRF via redirect | manual/off redirects |
| Logs containing tokens/PII | leak in the logging system | redaction & structured logs |
| No alerts on failed logins | invisible attacks | alert + retention |
| DAST against production | illegal & risky | staging + permission |
