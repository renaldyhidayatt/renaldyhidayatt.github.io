## Mental model 5 menit

| Concept | Summary |
| :--- | :--- |
| Image | read-only template (stacked layers) |
| Container | running instance of an image (thin writable layer on top) |
| Layer | each Dockerfile instruction = 1 layer; cache per instruction |
| Context | folder sent to the daemon during `build` (mind `.dockerignore`) |
| Volume | storage outside the container, persists after the container is deleted |
| Bind mount | host folder mounted into the container (development) |
| Network | default bridge; containers reach each other by service name |
| Registry | where images are stored (Docker Hub, GHCR, ECR, GCR) |
| Multi-stage | several `FROM` in one Dockerfile; only the last stage becomes the image |
| Entrypoint vs CMD | `ENTRYPOINT` = executable, `CMD` = default arguments (can be overridden) |

## Dockerfile: multi-stage

```dockerfile
# ---- build stage: heavy toolchain, does NOT end up in the final image ----
FROM golang:1.26-alpine AS build
WORKDIR /src

# dependency cache separate from source
COPY go.mod go.sum ./
RUN go mod download

COPY . .

# CGO_ENABLED=0 → static binary, runs on scratch/distroless
RUN CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
    go build -trimpath -ldflags="-s -w" -o /out/app ./cmd/api

# ---- runtime stage: small, non-root ----
FROM gcr.io/distroless/static-debian12:nonroot
WORKDIR /app
COPY --from=build /out/app /app
USER nonroot:nonroot
EXPOSE 8080
ENTRYPOINT ["/app"]
```

| Practice | Why |
| :--- | :--- |
| Multi-stage | Final image without a compiler, shell, or package manager |
| Copy manifests first (`go.mod`, `pom.xml`) | Layer cache is not lost every time source changes |
| `USER` non-root | Blocks container escape |
| Exec form `ENTRYPOINT` | PID 1 = the app → SIGTERM reaches the JVM → graceful shutdown |
| `COPY --from=build` | Take only what is needed, not the whole stage |
| Instruction order | The thing that changes often (source) goes **last** |

## Dockerfile: Java (Spring Boot)

```dockerfile
# ---- build ----
FROM maven:3.9-eclipse-temurin-21 AS build
WORKDIR /build

# dependency layer cached separately
COPY pom.xml .
RUN mvn -B dependency:go-offline

COPY src ./src
RUN mvn -B clean package -DskipTests

# ---- runtime ----
FROM eclipse-temurin:21-jre-alpine
WORKDIR /app

RUN addgroup -S app && adduser -S app -G app
USER app

COPY --from=build /build/target/*.jar app.jar

ENV JAVA_TOOL_OPTIONS="-XX:MaxRAMPercentage=75 -XX:+ExitOnOutOfMemoryError -Duser.timezone=UTC" \
    TZ=UTC \
    SPRING_PROFILES_ACTIVE=prod

EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

```dockerfile
# if you need a shell for the healthcheck, use alpine (not distroless)
FROM eclipse-temurin:21-jre-alpine
RUN apk add --no-cache curl
HEALTHCHECK --interval=30s --timeout=3s --start-period=40s --retries=3 \
  CMD curl -fsS http://localhost:8080/actuator/health/readiness || exit 1
```

> **Note:** `distroless`/`scratch` has no shell and no `curl` → a shell-based
> `HEALTHCHECK` cannot run. Pick one: distroless (safe, no shell) **or** Alpine
> (has a shell, ~70 MB larger).

## Layer cache & build context

```dockerignore
target
.git
.gitignore
.env
.env.*
*.log
node_modules
.idea
.vscode
docs/
tests/
```

```dockerfile
# ❌ WRONG: one big layer, cache lost every time source changes
COPY . .
RUN mvn package

# ✅ RIGHT: separate dependency & source
COPY pom.xml .
RUN mvn -B dependency:go-offline
COPY src ./src
RUN mvn -B package -DskipTests
```

```bash
docker build --no-cache .            # force a rebuild (troubleshooting)
docker build --progress=plain .     # full logs without the progress bar
docker build --target build -t app:build .   # build the stage only
DOCKER_BUILDKIT=1 docker build .    # BuildKit (default in Docker 23+)
```

## Image: build, tag, push

```bash
# build + tag
docker build -t superapp/order-service:v1.4.2 .

# another tag for the same image (no rebuild)
docker tag superapp/order-service:v1.4.2 superapp/order-service:latest

# login & push
docker login ghcr.io
docker push ghcr.io/sanedge/order-service:v1.4.2

# list local images
docker images
docker images --filter "dangling=true"      # untagged images (to throw away)
docker image prune -a                        # remove unused images

# remove
docker rmi superapp/order-service:v1.4.2
docker system df                            # check disk usage
docker system prune -a --volumes             # clean everything (careful)
```

| Tag convention | Meaning |
| :--- | :--- |
| `v1.4.2` | exact, reproducible version |
| `v1.4` | major.minor (floating) |
| `latest` | **do not** use in production — it can point to anything |
| `sha-abc123` | commit hash — the most deterministic |
| `main-<timestamp>` | unversioned build, unique per build |

## Registry & multi-arch

```bash
# multi-arch build (amd64 + arm64) & push straight to the registry
docker buildx create --use --name multiarch
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t ghcr.io/sanedge/order-service:v1.4.2 \
  --push .

# inspect the multi-arch manifest
docker buildx imagetools inspect ghcr.io/sanedge/order-service:v1.4.2
```

```dockerfile
# or use QEMU for emulation (slower)
FROM --platform=$BUILDPLATFORM golang:1.26-alpine AS build
ARG TARGETOS TARGETARCH
RUN CGO_ENABLED=0 GOOS=$TARGETOS GOARCH=$TARGETARCH go build -o /out/app ./cmd/api
```

## Compose for local stacks

```yaml
services:
  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: DRAGON
      POSTGRES_PASSWORD: DRAGON
      POSTGRES_MULTIPLE_DATABASES: pos_identity,pos_merchant,pos_catalog,pos_sales
    ports: ["5432:5432"]
    volumes:
      - pgdata:/var/lib/postgresql/data
      - ./docker/init-multiple-db.sh:/docker-entrypoint-initdb.d/init-multiple-db.sh:ro
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U DRAGON"]
      interval: 5s
      timeout: 3s
      retries: 10
      start_period: 10s
    networks: [superapp]

  kafka:
    image: apache/kafka:3.8.0
    environment:
      KAFKA_NODE_ID: 1
      KAFKA_PROCESS_ROLES: broker,controller          # KRaft, no ZooKeeper
      KAFKA_CONTROLLER_QUORUM_VOTERS: 1@kafka:9093
      KAFKA_LISTENERS: PLAINTEXT://:9092,CONTROLLER://:9093
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka:9092
      KAFKA_CONTROLLER_LISTENER_NAMES: CONTROLLER
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
      KAFKA_TRANSACTION_STATE_LOG_REPLICATION_FACTOR: 1
      KAFKA_TRANSACTION_STATE_LOG_MIN_ISR: 1
      KAFKA_GROUP_INITIAL_REBALANCE_DELAY_MS: 0
    ports: ["9092:9092"]
    healthcheck:
      test: ["CMD-SHELL", "/opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list"]
      interval: 10s
      timeout: 5s
      retries: 12
    networks: [superapp]

  order-service:
    build: ./order-service
    depends_on:
      postgres: { condition: service_healthy }   # REQUIRED for anything that needs the DB
      kafka:   { condition: service_healthy }
    environment:
      DB_HOST: postgres           # SERVICE NAME, not localhost
      KAFKA_BROKERS: kafka:9092
      SPRING_PROFILES_ACTIVE: local
    ports: ["8083:8083"]
    networks: [superapp]
    restart: unless-stopped

volumes:
  pgdata:

networks:
  superapp:
    driver: bridge
```

```bash
docker compose up -d --build        # start everything + build
docker compose ps                   # status + health
docker compose logs -f order-service
docker compose up -d postgres       # start a single service
docker compose exec postgres psql -U DRAGON -d pos_sales
docker compose restart order-service
docker compose down                 # stop, volumes kept
docker compose down -v              # stop + DELETE volumes
docker compose config               # render the final configuration (debug)
```

## Compose: advanced features

```yaml
services:
  # profile: the service only runs when the profile is enabled
  mailhog:
    image: mailhog/mailhog
    profiles: ["dev"]
    ports: ["8025:8025"]

  # per-environment override
  order-service:
    environment:
      SPRING_PROFILES_ACTIVE: ${SPRING_PROFILE:-local}
    env_file:
      - .env.local
    secrets:
      - db_password
    volumes:
      - ./logs:/app/logs          # bind mount for logs
    deploy:
      resources:
        limits: { cpus: "1.0", memory: 1G }

secrets:
  db_password:
    file: ./secrets/db_password.txt
```

```bash
docker compose --profile dev up -d      # enable the profile
docker compose run --rm order-service mvn test   # one-off command
docker compose --profile dev up -d --no-deps order-service
```

| Feature | When |
| :--- | :--- |
| `profiles` | extra services (mailhog, profiler) that are not needed in prod |
| `env_file` | per-environment configuration |
| `secrets` | secret file mount (Swarm; in Compose = file mount) |
| `depends_on.condition` | wait for another service to be **healthy**, not just started |
| `deploy.resources` | local CPU/memory limits (limit-supported) |
| `!reset` / `!override` | Compose 2.24+: reset/override a key from another file |

## Daily CLI

```bash
# container
docker ps                       # running
docker ps -a                    # including stopped ones
docker stop <nama> && docker start <nama>
docker rm -f <nama>
docker exec -it <nama> sh
docker logs -f --tail=100 <nama>
docker inspect <nama>           # full JSON
docker stats                    # realtime CPU/RAM/net

# image
docker images
docker history <image>          # layer by layer
docker inspect --format '{{.Config.Env}}' <image>
docker inspect --format '{{.Size}}' <image>

# system
docker system df
docker system prune
docker volume ls && docker volume prune
docker network ls
```

## Debug & troubleshoot

```bash
# the container will not start
docker logs <nama> --tail=200
docker inspect <nama> --format '{{.State.ExitCode}} {{.State.Error}}'

# get into a dead container (to debug startup)
docker run --rm -it --entrypoint sh <image>

# check connectivity between services
docker compose exec order-service sh -c "nc -zv postgres 5432"

# resource real-time
docker stats --no-stream

# disk
docker system df -v
du -sh /var/lib/docker/*

# registry
docker manifest inspect <image>      # check multi-arch
docker buildx imagetools inspect <image>
```

```bash
# clean everything (careful: volumes go too)
docker system prune -a --volumes
```

## Image hygiene

| Practice | Command |
| :--- | :--- |
| Scan the image | `docker scout cves <image>` / `trivy image <image>` |
| Label metadata | `LABEL org.opencontainers.image.source="https://github.com/..."` |
| Pin the base image by digest | `FROM eclipse-temurin:21-jre-alpine@sha256:...` |
| Non-root | `USER app` / `USER 10001` |
| Healthcheck | `HEALTHCHECK CMD ...` (needs a shell) |
| Shrink the image | multi-stage, `apt-get purge`, `--no-install-recommends` |
| Signal handling | exec form + app handles SIGTERM |

```dockerfile
LABEL org.opencontainers.image.title="order-service" \
      org.opencontainers.image.version="1.4.2" \
      org.opencontainers.image.source="https://github.com/sanedge/order-service"
```

## Pitfalls (must read)

| Pitfall | Symptom | Solution |
| :--- | :--- | :--- |
| `COPY . .` up front | Cache lost on every build | Copy manifests first, source later |
| No `.dockerignore` | Slow builds, `target/` & `.env` end up in the image | Create `.dockerignore` |
| `latest` as the tag | Non-deterministic deploys | Tag a version or commit SHA |
| Shell form `ENTRYPOINT` | SIGTERM never reaches the JVM | Exec form `["java","-jar","app.jar"]` |
| Root by default | Container escape is easier | Non-root `USER` |
| Big image (alpine + build tools) | Slow pulls, large attack surface | Multi-stage, distroless |
| `depends_on` without `condition: service_healthy` | App starts before the DB is ready → crash loop | Add `condition: service_healthy` |
| `localhost` to reach a DB host from the container | "connection refused" | Use the **service name** |
| Secret in `environment` | Leaks via `docker inspect` | Use Docker/Swarm secrets or file mounts |
| Is the volume backed up? | Data lost on `down -v` | Back up volumes, do not run `prune -a --volumes` carelessly |
| `HEALTHCHECK` in distroless | Command not found | Healthcheck outside the image (compose/probe) |
| Building on the host = not reproducible | "it doesn't run on my other laptop" | Build inside a container / CI |
| Many layers from separate `RUN`s | Big image | Combine related consecutive `RUN`s |
| The image has a `CMD` that gets overridden | Arguments are lost | Understand the order: `ENTRYPOINT` + `CMD` = `ENTRYPOINT CMD` |
| Port mapping conflicts | "port is already allocated" | Check `docker ps`, change the host port |
