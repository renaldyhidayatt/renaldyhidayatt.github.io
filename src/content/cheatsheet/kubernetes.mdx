# Kubernetes — Cheat Sheet

> Target: **Kubernetes 1.28+**, namespace per platform, manifest **Kustomize** (base + overlay),
> deploy via **ArgoCD** (see the separate sheet). Used for E-Commerce, POS, and Payment

## 5-minute mental model

| Concept | Summary |
| :--- | :--- |
| Pod | smallest scheduling unit; 1+ container |
| Deployment | manages ReplicaSet → stateless pods |
| StatefulSet | ordered pods, persistent volumes, stable identity |
| DaemonSet | one pod per node (agents, exporters) |
| Service | selector → pods; ClusterIP by default, LoadBalancer/NodePort optional |
| Ingress | HTTP routing → Service (needs a controller) |
| ConfigMap / Secret | non-secret / secret configuration (base64, not encryption) |
| Namespace | logical isolation + RBAC + quota per team |
| ReplicaSet | keeps the pod count |
| Resource request vs limit | request = guaranteed minimum; limit = ceiling (and can cause OOMKill) |
| Probe | contract between the controller and the application |
| HPA | metric-driven horizontal autoscaling |
| PDB | cap on pods that may go down at once (voluntary disruption) |
| Kustomize | templating + overlays without a template engine |

## Workload: Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: order-service
  labels: { app: order-service, tier: backend }
spec:
  replicas: 2
  revisionHistoryLimit: 5
  selector:
    matchLabels: { app: order-service }
  strategy:
    type: RollingUpdate
    rollingUpdate: { maxSurge: 1, maxUnavailable: 0 }
  template:
    metadata:
      labels: { app: order-service, tier: backend }
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/actuator/prometheus"
        prometheus.io/port: "8083"
    spec:
      terminationGracePeriodSeconds: 45
      securityContext:
        runAsNonRoot: true
        runAsUser: 10001
        fsGroup: 10001
      containers:
        - name: order-service
          image: superapp/order-service:v1.4.2     # DO NOT use :latest
          imagePullPolicy: IfNotPresent
          ports:
            - { name: http, containerPort: 8083 }
          envFrom:
            - configMapRef: { name: order-service-config }
            - secretRef: { name: order-service-secrets }
          env:
            - name: JAVA_TOOL_OPTIONS
              value: "-XX:MaxRAMPercentage=75 -XX:+ExitOnOutOfMemoryError"
          resources:
            requests: { cpu: 250m, memory: 512Mi }
            limits:   { cpu: "1",  memory: 1Gi }
          startupProbe:
            httpGet: { path: /actuator/health/readiness, port: http }
            failureThreshold: 30
            periodSeconds: 5
          readinessProbe:
            httpGet: { path: /actuator/health/readiness, port: http }
            periodSeconds: 10
            failureThreshold: 3
          livenessProbe:
            httpGet: { path: /actuator/health/liveness, port: http }
            periodSeconds: 20
            failureThreshold: 3
          lifecycle:
            preStop:
              exec: { command: ["sh", "-c", "sleep 10"] }   # let the pod drain
---
apiVersion: v1
kind: Service
metadata:
  name: order-service
spec:
  type: ClusterIP
  selector: { app: order-service }
  ports:
    - { name: http, port: 8083, targetPort: http }
```

| Field | Meaning | Pitfall |
| :--- | :--- | :--- |
| `selector` | which pods are served | must match `template.metadata.labels` |
| `maxSurge` / `maxUnavailable` | controls rollout speed | `maxUnavailable: 0` = zero downtime, needs surge room |
| `terminationGracePeriodSeconds` | time for the pod to finish after receiving SIGTERM | default 30 → requests get cut off |
| `preStop` | delay before SIGTERM | for load balancer draining |
| `imagePullPolicy` | `Always` for `:latest` | `IfNotPresent` is the default for immutable tags |

## Other workloads: StatefulSet, DaemonSet, Job, CronJob

```yaml
# StatefulSet: stateful app (DB, Kafka broker, queue) — volume per pod
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: kafka-broker
spec:
  serviceName: kafka-headless
  replicas: 3
  selector: { matchLabels: { app: kafka } }
  template:
    metadata: { labels: { app: kafka } }
    spec:
      containers:
        - name: kafka
          image: apache/kafka:3.8.0
          ports: [{ containerPort: 9092 }]
  volumeClaimTemplates:
    - metadata: { name: data }
      spec:
        accessModes: ["ReadWriteOnce"]
        resources: { requests: { storage: 20Gi } }
---
# DaemonSet: one pod per node (node-exporter, ebpf agent)
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: node-exporter
spec:
  selector: { matchLabels: { app: node-exporter } }
  template:
    metadata: { labels: { app: node-exporter } }
    spec:
      hostNetwork: true
      containers:
        - name: node-exporter
          image: prom/node-exporter:v1.8.2
          args: ["--path.rootfs=/host"]
          volumeMounts:
            - { name: host, mountPath: /host, readOnly: true }
      volumes:
        - name: host
          hostPath: { path: / }
---
# Job: one-off task (database migration)
apiVersion: batch/v1
kind: Job
metadata:
  name: db-migration
spec:
  backoffLimit: 3
  ttlSecondsAfterFinished: 3600
  template:
    spec:
      restartPolicy: Never
      containers:
        - name: migrate
          image: superapp/order-service:v1.4.2
          args: ["migrate", "up"]
          envFrom:
            - secretRef: { name: db-credentials }
---
# CronJob: scheduled
apiVersion: batch/v1
kind: CronJob
metadata:
  name: stats-backfill
spec:
  schedule: "0 3 * * *"            # 03:00 every day
  concurrencyPolicy: Forbid
  successfulJobsHistoryLimit: 3
  jobTemplate:
    spec:
      template:
        spec:
          restartPolicy: Never
          containers:
            - name: backfill
              image: superapp/stats-backfill:v1.0.0
```

| Workload | Use for | Typical traits |
| :--- | :--- | :--- |
| Deployment | stateless services | horizontal scaling, rolling update |
| StatefulSet | stateful services | ordinals, volume per pod (`volumeClaimTemplates`) |
| DaemonSet | agent per node | 1 pod/node, must tolerate `nodeAffinity` |
| Job | one-off run | `ttlSecondsAfterFinished` so they don't pile up |
| CronJob | scheduled | `concurrencyPolicy: Forbid` so runs don't overlap |

## Service & Ingress

```yaml
apiVersion: v1
kind: Service
metadata:
  name: order-service
spec:
  type: ClusterIP
  clusterIP: None          # headless (for StatefulSet)
  selector: { app: order-service }
  ports:
    - { name: http, port: 8083, targetPort: http }
---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: superapp
  annotations:
    nginx.ingress.kubernetes.io/proxy-body-size: "10m"
    nginx.ingress.kubernetes.io/proxy-read-timeout: "300"
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
spec:
  ingressClassName: nginx
  tls:
    - hosts: [api.example.com]
      secretName: api-tls
  rules:
    - host: api.example.com
      http:
        paths:
          - path: /api/orders
            pathType: Prefix
            backend:
              service:
                name: order-service
                port: { name: http }
```

| Service type | ClusterIP | NodePort | LoadBalancer | ExternalName |
| :--- | :--- | :--- | :--- | :--- |
| Access | internal cluster | node:port | cloud LB | CNAME to another service |
| When | default | minikube/dev | production (if there is no Ingress) | migration |

> **Pitfall:** `pathType: Prefix` with the path `/api/orders` also matches `/api/orders-legacy`.
> Use `pathType: Exact` or an explicit trailing slash if you need precision.

## ConfigMap & Secret

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: order-service-config
data:
  SPRING_PROFILES_ACTIVE: "prod"
  LOG_LEVEL: "INFO"
  KAFKA_BROKERS: "kafka:9092"
  application.yaml: |
    server:
      port: 8083
    management:
      endpoints.web.exposure.include: health,prometheus
---
apiVersion: v1
kind: Secret
metadata:
  name: order-service-secrets
type: Opaque
stringData:                    # stringData = plaintext (converted to base64)
  DB_PASSWORD: "rahasia"
  JWT_SECRET: "..."
```

```bash
# create a secret from a file
kubectl create secret generic order-service-secrets \
  --from-literal=DB_PASSWORD="$(cat secret.txt)" \
  --dry-run=client -o yaml | kubectl apply -f -

# hash to trigger a rollout when config changes
kubectl create secret generic order-service-secrets --from-literal=DB_PASSWORD=... --dry-run=client -o yaml
```

> **Pitfall:** Secrets in K8s are **not** encrypted (base64 only). Use **SealedSecrets**,
> External Secrets Operator, or a CSI driver for encryption at rest. `stringData` vs
> `data`: `stringData` is written as plaintext then encoded by the API server; `data` must be base64.

## Probes: liveness, readiness, startup

| Probe | When it runs | Failure → |
| :--- | :--- | :--- |
| `startupProbe` | While the container starts | Container is **restarted** |
| `readinessProbe` | Periodically | Pod is **removed from the Service** (pod keeps running) |
| `livenessProbe` | Periodically | Pod is **restarted** |

```yaml
startupProbe:
  httpGet: { path: /actuator/health/readiness, port: http }
  failureThreshold: 30        # 30 × 5s = 150s tolerance for slow startup
  periodSeconds: 5
readinessProbe:
  httpGet: { path: /actuator/health/readiness, port: http }
  periodSeconds: 10
  timeoutSeconds: 2
  failureThreshold: 3
livenessProbe:
  httpGet: { path: /actuator/health/liveness, port: http }
  periodSeconds: 20
  timeoutSeconds: 2
  failureThreshold: 3
```

| Probe type | When to use |
| :--- | :--- |
| `httpGet` | HTTP endpoint (most common) |
| `tcpSocket` | open port (services without HTTP) |
| `exec` | command inside the container (requires a shell) |
| `grpc` | gRPC health service (K8s 1.24+) |

> **Pitfall:** `readiness` and `liveness` must be **different**. If liveness uses an endpoint
> that depends on a dependency (DB), a DB hiccup → every pod restarts → cascading outage.

## Resource, HPA, PDB

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: order-service
spec:
  scaleTargetRef: { apiVersion: apps/v1, kind: Deployment, name: order-service }
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target: { type: Utilization, averageUtilization: 70 }
    - type: Resource
      resource:
        name: memory
        target: { type: Utilization, averageUtilization: 80 }
  behavior:
    scaleUp:
      stabilizationWindowSeconds: 30
    scaleDown:
      stabilizationWindowSeconds: 300     # anti-thrash
---
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: order-service
spec:
  minAvailable: 1
  selector:
    matchLabels: { app: order-service }
```

> **Pitfall:** HPA **requires `resources.requests`** to be set. Without requests, HPA cannot
> compute utilization. And `limits` too close to `requests` → OOMKill when
> traffic rises. Rule of thumb: request ≈ average usage, limit ≈ 2× request.

## NetworkPolicy

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
spec:
  podSelector: {}
  policyTypes: [Ingress, Egress]
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: order-service-egress
spec:
  podSelector:
    matchLabels: { app: order-service }
  policyTypes: [Egress]
  egress:
    - to: [{ podSelector: { matchLabels: { app: postgres } } }]
      ports: [{ protocol: TCP, port: 5432 }]
    - to: [{ namespaceSelector: {} }]
      ports:
        - { protocol: UDP, port: 53 }     # DNS
        - { protocol: TCP, port: 53 }
        - { protocol: TCP, port: 9092 }   # Kafka
    - to: [{ ipBlock: { cidr: 10.0.0.0/8 } }]   # egress into the VPC
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-metrics-scrape
spec:
  podSelector:
    matchLabels: { app: order-service }
  policyTypes: [Ingress]
  ingress:
    - from: [{ namespaceSelector: { matchLabels: { name: monitoring } } }]
      ports: [{ protocol: TCP, port: 8083 }]
```

> **Pitfall:** after `default-deny-all`, **DNS is blocked too** if egress does not
> allow port 53. The symptom: pods in `CrashLoopBackOff` with
> `Temporary failure in name resolution`.

## Kustomize: base & overlay

```
production/kubernetes/
├── base/
│   ├── order-service/
│   │   ├── kustomization.yaml
│   │   ├── deployment.yaml
│   │   └── service.yaml
│   └── postgres/
└── overlays/
    └── production/
        ├── kustomization.yaml
        ├── patches/
        │   └── replicas.yaml
        └── configmap-generator.yaml
```

```yaml
# base/order-service/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - deployment.yaml
  - service.yaml
commonLabels:
  app: order-service
  tier: backend
images:
  - name: superapp/order-service
    newTag: v1.4.2
```

```yaml
# overlays/production/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
namespace: pos
resources:
  - ../../base/order-service
patches:
  - path: patches/replicas.yaml
configMapGenerator:
  - name: order-service-config
    literals:
      - SPRING_PROFILES_ACTIVE=prod
    options:
      disableNameSuffixHash: false      # hash = rollout when config changes
secretGenerator:
  - name: order-service-secrets
    envs: [secrets.env]
    options:
      disableNameSuffixHash: true
```

```bash
kubectl kustomize production/kubernetes/overlays/production   # render without applying
kubectl diff -k production/kubernetes/overlays/production      # compare against the cluster
kubectl apply -k production/kubernetes/overlays/production
```

| Overlay | Contents |
| :--- | :--- |
| `base` | minimal manifests, no environment values |
| `overlays/production` | namespace, replicas, resources, per-env config |
| `components` | reusable snippets (ingress, TLS) to `include` |

> **Pitfall:** `commonLabels` in base overrides the `selector` labels → Deployment no longer
> matches the Service. Use the new `labels:` field + `commonAnnotations` if you need new labels.

## Daily kubectl

```bash
# resources & status
kubectl get pods -n pos -o wide
kubectl get deploy,svc,ingress -n pos
kubectl get events -n pos --sort-by=.lastTimestamp | tail -20
kubectl top pods -n pos

# logs
kubectl logs -n pos <pod> --tail=200
kubectl logs -n pos <pod> --previous          # logs before the restart
kubectl logs -n pos <pod> -c <container> --follow

# describe & edit
kubectl describe pod <pod> -n pos
kubectl get pod <pod> -n pos -o yaml
kubectl edit deploy order-service -n pos      # fights ArgoCD (selfHeal)

# apply & delete
kubectl apply -f manifest.yaml
kubectl delete -f manifest.yaml
kubectl rollout restart deploy/order-service -n pos
kubectl rollout status deploy/order-service -n pos
kubectl rollout history deploy/order-service -n pos
kubectl rollout undo deploy/order-service -n pos

# scale & expose
kubectl scale deploy/order-service --replicas=3 -n pos
kubectl port-forward -n pos svc/order-service 8083:8083

# context & config
kubectl config get-contexts
kubectl config use-context minikube
kubectl get secret order-service-secrets -n pos -o jsonpath='{.data.DB_PASSWORD}' | base64 -d
```

## Debug pod

```bash
# debug a container in a running pod
kubectl debug -it -n pos <pod> --image=nicolaka/netshoot --target=order-service

# debug a pod that failed to start (using the old image)
kubectl debug -it -n pos <pod> --image=busybox --target=order-service

# check networking from outside the pod
kubectl run netcheck -n pos --rm -it --image=alpine -- \
  sh -c "nc -zv postgres 5432 && nc -zv kafka 9092"

# list resources in the namespace
kubectl api-resources --namespaced=true | head -30
kubectl get <resource> -n pos -o wide

# check RBAC
kubectl auth can-i get deployments -n pos
kubectl auth can-i --list -n pos
```

## Pitfalls (required reading)

| Pitfall | Symptom | Solution |
| :--- | :--- | :--- |
| Image tag `:latest` | Non-deterministic deploys, stale cache | Version tag / commit SHA |
| No `resources.requests` | HPA dead, unbounded Burstable QoS | Set request & limit |
| `default-deny-all` without DNS rules | Pods `CrashLoopBackOff`, DNS fails | Allow egress UDP/TCP 53 |
| Readiness = liveness | Traffic diverted while the app is slow, pods restart too | Separate probe endpoints |
| `terminationGracePeriodSeconds` default 30 | Requests cut off during rollout | Raise it + `preStop` sleep |
| Migration runs alongside the app | Schema conflicts | Separate migration Job (sync wave) |
| Secrets in ConfigMap / plain Git | Leaked | SealedSecrets + encryption at rest |
| Manual `kubectl apply` | Fights GitOps, ArgoCD reverts it | Everything through Git |
| Aggressive HPA scale-down | Pod thrash, cold start | `stabilizationWindowSeconds` |
| Health check `GET /` | 404 → pods restart constantly | Dedicated health endpoint |
| Exec form missing in the image | SIGTERM never arrives | `ENTRYPOINT ["java","-jar","app.jar"]` |
| Ingress default 60s timeout | Long requests cut off | Set timeout + annotation |
| `commonLabels` overrides the selector | Service doesn't match pods | Use `labels:` + `commonAnnotations` |
| StatefulSet without a headless Service | Unstable pod DNS | `clusterIP: None` + `serviceName` |
| CronJob default `concurrencyPolicy` | Overlapping Jobs | Set `Forbid` |
| Jobs pile up | Old Jobs fill things up | `ttlSecondsAfterFinished` |
| Pod `Pending` | Node full / PVC not ready | `kubectl describe` → check Events |
| Pod `CrashLoopBackOff` | App crashes on start | `kubectl logs --previous` |
| `imagePullBackOff` | Wrong or missing image/tag | Check registry & tag |
| Service `ExternalIP` pending | LoadBalancer not provisioned | Wait for the cloud provider IP, or use Ingress |
