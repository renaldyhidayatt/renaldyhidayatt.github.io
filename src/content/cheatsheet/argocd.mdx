# ArgoCD — Cheat Sheet

> Target: **ArgoCD 2.9+** with the **App-of-Apps** pattern for deploying all microservices
> (E-Commerce, POS, Payment Gateway) in per-platform namespaces. All manifests below

## Mental model 5 menit

| Concept | Summary |
| :--- | :--- |
| ArgoCD = GitOps control plane | Git = source of truth, not the cluster |
| Application | CRD pointing to 1 target (path/repo/ref) |
| App-of-Apps | root Application manages child Applications |
| Sync | apply manifests from Git to the cluster |
| Diff | compare desired (Git) vs live (cluster) |
| Health | Healthy/Progressing/Degraded status |
| Sync wave | sync order between Applications (annotation) |
| selfHeal | manual cluster changes are **reverted** |
| prune | resources missing from Git are **deleted** from the cluster |
| project | permission boundary: repo, cluster, namespace, resource |
| repo-server | the one that clones the repo & renders manifests (can be scaled) |
| ApplicationSet | generate Applications from git/helm/list |

## Arsitektur komponen

```
┌──────────────┐   ┌──────────────┐   ┌────────────────┐
│ argocd-server│   │ repo-server  │   │  application   │
│  (API/UI/    │   │ (git clone + │   │  controller    │
│   controller)│   │  render)     │   │ (sync & health)│
└──────┬───────┘   └──────┬───────┘   └───────┬────────┘
       │                  │                   │
       └──────────────────┴───────────────────┘
                    Redis (cache & state)
```

| Component | Job | Scaling |
| :--- | :--- | :--- |
| `argocd-server` | API, UI, gRPC | horizontal (behind ingress) |
| `repo-server` | clone repo, render manifests | horizontal (heaviest) |
| `application-controller` | sync + health check | horizontal (sharding by name) |
| `redis` | cache, lock, state | required (not optional) |

## App-of-Apps

```yaml
# root-app.yaml — bootstrap: manages the list of child Applications
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: pos-root
  namespace: argocd
  finalizers:
    - resources-finalizer.argocd.argoproj.io   # delete children when the root is deleted
spec:
  project: pos
  source:
    repoURL: https://github.com/sanedge/pos-k8s.git
    targetRevision: main
    path: deployments/gitops/argocd/apps       # folder containing child Application manifests
    directory:
      recurse: true
  destination:
    server: https://kubernetes.default.svc
    namespace: argocd
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
      allowEmpty: false
    syncOptions:
      - CreateNamespace=true
      - ServerSideApply=true
      - ApplyOutOfSyncOnly=true
```

```bash
# bootstrap: create namespace + install ArgoCD + root app
kubectl create namespace argocd
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
kubectl apply -n argocd -f root-app.yaml
```

## Application: full spec

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: service-order
  namespace: argocd
  finalizers:
    - resources-finalizer.argocd.argoproj.io
  annotations:
    argocd.argoproj.io/sync-wave: "3"        # sync order
    argocd.argoproj.io/sync-options: "Prune=true;ServerSideApply=true"
spec:
  project: pos
  source:
    repoURL: https://github.com/sanedge/pos-k8s.git
    targetRevision: main
    path: deployments/kubernetes/base/order-service
    helm:
      valueFiles: [values/prod.yaml]
      parameters:
        - name: image.tag
          value: v1.4.2
    kustomize:
      images:
        - name: superapp/order-service
          newTag: v1.4.2
    directory:
      recurse: true
      include: '{*.yaml,*.yml}'
  destination:
    server: https://kubernetes.default.svc
    namespace: pos
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
      - ServerSideApply=true
      - RespectIgnoreDifferences=true
    retry:
      limit: 5
      backoff: { duration: 10s, factor: 2, maxDuration: 5m }
  ignoreDifferences:
    - group: apps
      kind: Deployment
      jsonPointers: [/spec/replicas]        # HPA owns replicas
  revisionHistoryLimit: 5
```

| `spec` field | Meaning |
| :--- | :--- |
| `source.repoURL` | git repo |
| `source.targetRevision` | branch/tag/commit |
| `source.path` | folder inside the repo |
| `source.helm` / `source.kustomize` / `source.directory` | how to render (only one) |
| `destination.server` | target cluster (`https://kubernetes.default.svc` = the same cluster) |
| `destination.namespace` | target namespace |
| `syncPolicy.automated` | `prune`, `selfHeal`, `allowEmpty` |
| `syncPolicy.syncOptions` | flags at sync time |
| `syncPolicy.retry` | exponential backoff when sync fails |
| `ignoreDifferences` | fields allowed to differ (HPA vs replicas) |
| `ignoreDifferences` | with `jsonPointers` | ignores a specific field |

## Sync policy & sync options

```yaml
syncPolicy:
  automated:
        prune: true          # delete resources that disappeared from Git
    selfHeal: true       # revert manual changes in the cluster
    allowEmpty: false    # do not delete every resource when Git is empty
  syncOptions:
    - CreateNamespace=true
    - ServerSideApply=true
    - ApplyOutOfSyncOnly=true
    - RespectIgnoreDifferences=true
    - PruneLast=true
    - Replace=true            # REPLACE the resource (not patch) — for immutable fields
    - FailOnSharedResourceWarning=true
```

| Sync option | Meaning | Warning |
| :--- | :--- | :--- |
| `CreateNamespace` | create the target namespace | safe |
| `ServerSideApply` | SSA, conflict resolution | recommended |
| `ApplyOutOfSyncOnly` | only apply what is OutOfSync | faster |
| `RespectIgnoreDifferences` | honor `ignoreDifferences` | enable if you use ignore |
| `PruneLast` | prune after apply | safer for services |
| `Replace` | delete & recreate | **causes downtime** |
| `FailOnSharedResourceWarning` | fail if the resource is used by another app | good for shared DB |

| `automated` | Effect |
| :--- | :--- |
| `prune: true` | Resources deleted in Git are also deleted in the cluster |
| `selfHeal: true` | Manual changes (`kubectl edit`) are **reverted** |
| `allowEmpty: false` | If Git is empty, do not delete everything |

## Sync waves

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: service-order
  namespace: argocd
  annotations:
    argocd.argoproj.io/sync-wave: "3"
```

| Wave | Contents | Example |
| :--- | :--- | :--- |
| 0 | CRDs & controllers | cert-manager, sealed-secrets |
| 1 | Namespace & infra | postgres, redis, kafka |
| 2 | Database migrations | Flyway migration `Job` |
| 3 | Domain services | order, payment, auth |
| 4 | Gateway & ingress | api-gateway, nginx |
| 5 | Observability | prometheus, grafana, loki |

> Sync waves = order **between Applications** in App-of-Apps. The same wave runs
> **in parallel** (not sequentially). If B needs A to finish → A must be in a lower wave.

## Project, RBAC, namespace

```yaml
apiVersion: argoproj.io/v1alpha1
kind: AppProject
metadata:
  name: pos
  namespace: argocd
spec:
  description: "Platform Point of Sale"
  sourceRepos:
    - https://github.com/sanedge/pos-k8s.git
  destinations:
    - server: https://kubernetes.default.svc
      namespace: pos
    - server: https://kubernetes.default.svc
      namespace: pos-observability
  clusterResourceWhitelist:
    - group: "*"
      kind: "*"
  namespaceResourceWhitelist:
    - group: "*"
      kind: "*"
  namespaceResourceBlacklist:
    - group: ""
      kind: Secret
      name: "*-vault-token"      # special secret that ArgoCD must not touch
  roles:
    - name: ci-bot
      policies:
        - p, proj:pos:deploy, applications, sync, pos/*, allow
        - p, proj:pos:read, applications, pos/*, allow
      jwtTokens:
        - my-jwt-token
```

```yaml
# RBAC for users (using groupoidc / OIDC)
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: argocd-reader
  namespace: pos
rules:
  - apiGroups: ["argoproj.io"]
    resources: ["applications", "applicationsets"]
    verbs: ["get", "list", "watch"]
  - apiGroups: [""]
    resources: ["pods", "services", "configmaps"]
    verbs: ["get", "list", "watch"]
```

| Object | Function |
| :--- | :--- |
| `AppProject` | boundary: repo, cluster, namespace, resource types |
| `role` in project | policy per token/JWT |
| `ClusterRole` | access to cluster resources (namespace, CRD) |
| `namespaceResourceBlacklist` | resources ArgoCD must not sync (e.g. RA secrets) |

## Argo CD Image Updater

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: service-order
  namespace: argocd
  annotations:
    argocd.argoproj.io/refresh: normal
spec:
  source:
    repoURL: https://github.com/sanedge/pos-k8s.git
    targetRevision: main
    path: deployments/kubernetes/base/order-service
  imageUpdater:
    # Image Updater v1 (argo-cd-image-updater) uses this spec
    updateStrategy: semver
    allowTags: "regexp:^v\\d+\\.\\d+\\.\\d+$"
    imageList:
      - superapp/order-service
```

```bash
# manual tracking (alternative: bot commits a PR)
argocd app get service-order --output wide
```

> Image Updater writes the new tag **straight to Git** (commit) → triggers a sync.
> The safer alternative: a bot opens a PR that needs human review.

## Notifications

```yaml
apiVersion: argoproj.io/v1alpha1
kind: AppProject
metadata:
  name: pos
  namespace: argocd
spec:
  notifications:
    - type: webhook
      webhook:
        url: https://hooks.slack.com/services/xxx
        jira:
          enabled: false
      when:
        - sync-status.succeeded
        - sync-status.failed
        - sync-status.orphaned
        - degraded
      channels:
        - slack-pos
```

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: service-order
  namespace: argocd
  annotations:
    notifications.argoproj.io/subscribe.on-sync-succeeded: slack-pos
    notifications.argoproj.io/subscribe.on-sync-failed: slack-pos
    notifications.argoproj.io/subscribe.on-deployed: slack-pos
```

| Trigger | Meaning |
| :--- | :--- |
| `on-sync-succeeded` | Sync succeeded |
| `on-sync-failed` | Sync failed |
| `on-sync-status-unknown` | Timeout while checking status |
| `on-deployed` | Resource deployed successfully |
| `on-health-degraded` | Health-Degraded |

## Daily CLI & UI

```bash
# install CLI
brew install argocd           # macOS
# or: kubectl -n argocd port-forward svc/argocd-server 8080:80 & argocd login localhost:8080

# login & context
argocd login localhost:8080 --username admin --password $(kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath='{.data.password}' | base64 -d)
argocd context list

# applications
argocd app list
argocd app get service-order
argocd app get service-order --output wide          # health & sync columns
argocd app get service-order --show-operation
argocd app history service-order
argocd app logs service-order --tail 100

# manual sync
argocd app sync service-order
argocd app sync service-order --prune
argocd app rollback service-order 3

# diff & resources
argocd app diff service-order
argocd app resources service-order
argocd app manifests service-order

# projects & settings
argocd proj list
argocd proj get pos
argocd settings
```

```bash
# quickest way to port-forward the UI
kubectl port-forward -n argocd svc/argocd-server 8080:80
kubectl port-forward -n argocd svc/argocd-repo-server 8081:8081   # for helm/OCI rendering
```

| Command | Use when |
| :--- | :--- |
| `argocd app list` | check all health |

| `argocd app sync` | manual sync after a Git update |
| `argocd app history` / `rollback` | roll back to a previous version |
| `argocd app logs` | logs of deployed pods |
| `argocd app resources` | resources owned by the app (tree) |

## Rollback & dry-run

```bash
# view revision history
argocd app history service-order

# roll back to a specific revision
argocd app rollback service-order 5

# dry-run: render without applying
argocd app diff service-order --local
kubectl diff -k production/kubernetes/overlays/production

# preview the manifest that will be applied
argocd app manifests service-order
```

```yaml
# ArgoCD UI: Sync with "Dry Run" — render + compare without applying
spec:
  syncPolicy:
    automated: { prune: true, selfHeal: true }
```

> **Pitfall:** `argocd app rollback` *syncs* the old revision → **Deployments** get
> rolled back, but **ConfigMaps/Secrets** change too. If a DB migration has already
> run, rolling back the app = old code against a new schema.

## Pitfalls (must read)

| Pitfall | Symptom | Solution |
| :--- | :--- | :--- |
| `selfHeal: true` + `kubectl edit` | Manual changes vanish within minutes | Use `ignoreDifferences` for fields that are allowed to differ |
| `prune: true` + wrong path | All resources are deleted | Check `argocd app diff` before the first sync |
| `targetRevision: main` | What gets deployed changes without review | Use immutable tags/commits |
| Sync waves out of order | Pods crash because the CRD does not exist yet | Raise the CRD wave to 0 |
| `ignoreDifferences` without `RespectIgnoreDifferences` | The field is still reverted | Add the sync option |
| Sync without `ServerSideApply` | Field manager conflict | Use SSA |
| `Replace=true` | Service downtime | Avoid; fix the immutable field in the manifest |
| Secret sync without encryption | Secrets in Git | SealedSecrets / External Secrets |
| `sourceRepos` too loose | An app can deploy from any repo | Lock it per project |
| Target namespace does not exist | Sync fails | `CreateNamespace=true` or create it manually |
| `appProject` in a different namespace | Project not found | `spec.project` must be the **name**, not `ns/name` |
| Image Updater commits straight to `main` | Deploy without review | Use a PR-based updater |
| Redundant sync (2 controllers) | Object ownership conflict | One controller per cluster, or sharding |
| `prune` + CRD deleted | Unmanaged resources | Be careful when deleting CRDs |
| Sync timeout too short | Sync is reported failed while still running | Increase `timeout.reconciliation` |
