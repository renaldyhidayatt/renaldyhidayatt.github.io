# Quarkus 3.x — Cheat Sheet

> Target: **Java 21 (Temurin)** + **Quarkus 3.17** + **GraalVM 21**.
> Quarkus is fundamentally different from Spring: **most of the work happens at build time**, not
> at boot. Without this mental model, almost every error will be confusing.

## CLI & toolchain

```bash
# new project — pick extensions up front, not later
quarkus create app com.example:order-service \
  --extension='rest-jackson,rest-qute,hibernate-orm-panache,jdbc-postgresql,flyway,smallrye-health,micrometer-registry-prometheus,opentelemetry'

cd order-service && ./mvnw quarkus:dev      # dev mode + live reload + Dev UI at /q/dev

# add / remove extensions (edits pom.xml directly)
quarkus extension add hibernate-validator
quarkus extension remove resteasy-classic

# build
./mvnw clean package                        # regular jar (JVM mode)
./mvnw clean package -Dnative               # native executable (requires GraalVM)
```

| Command | Purpose |
| :--- | :--- |
| `quarkus dev` | live reload, continuous testing, Dev UI, Dev Services (DB/Kafka automatically) |
| `quarkus build` | regular build (Maven/Gradle under the hood) |
| `quarkus info` | Quarkus, Java, GraalVM versions |
| `quarkus ext ls` | installed extensions |

> **Dev mode is the first place to debug.** When code changes, Quarkus only re-runs the
> affected augmentation — not a full reboot. Above 10 seconds per reload, there is usually
> a problem in an extension/build step, not in your machine.

## Build-time mental model (read this first)

Quarkus shifts work from **runtime** to **build time**: the classpath is fixed, CDI is resolved,
config is read, reflection is replaced by generated code. The consequences:

| What happens at build | Consequence at runtime |
| :--- | :--- |
| CDI bean discovery (`@ApplicationScoped`, etc.) | A bean unknown at build = **nonexistent** at runtime |
| REST endpoint scanning | An endpoint missing at build = 404, with no error |
| Jackson serialization (reflection-free) | An unknown DTO = missing fields / deserialization error |
| Configuration mapped to `@ConfigMapping` | Env values are read at boot, some at build |
| Bytecode transformed / reflection registered | A library without Quarkus metadata = fails in native |

```text
mvn package  ──> augmentation ──> quarkus-app/quarkus-run.jar  (JVM)
                               └> <app>-runner (native)
```

> **Pitfall #1:** almost every "why doesn't it work" in Quarkus stems from something that is
> **invisible at build**. If the runtime cannot find something, check the build log —
> which extensions are active and what got augmented.

## Simplified CDI & injection

Quarkus uses Jakarta CDI, but with simplified building blocks. No
`beans.xml`, no proxy-heavy beans, and default scopes that differ from Jakarta EE.

```java
@ApplicationScoped                        // the default used 90% of the time
public class OrderService {

    private final PaymentGateway gateway;

    @Inject                                 // a single constructor = implicit @Inject
    public OrderService(PaymentGateway gateway) {
        this.gateway = gateway;
    }
}
```

| Annotation | Scope | Notes |
| :--- | :--- | :--- |
| `@ApplicationScoped` | singleton | default choice; lazy proxy |
| `@Singleton` | singleton | no proxy at all — fastest, don't store mutable state |
| `@RequestScoped` | per request | requires an active context (Vert.x HTTP) |
| `@Dependent` | per injection point | **the default for a plain CDI class** — new instance per injection |
| `@IfBuildProperty` / `@UnlessBuildProperty` | conditional bean | bean exists/doesn't exist based on a property **at build time** |
| `@LookupIfProperty` | conditional bean | checked at runtime, bean still exists at build |

```java
// Alternative bean based on a build property — not an if-else at runtime
@ApplicationScoped
@IfBuildProperty(name = "app.payment.provider", stringValue = "midtrans", enableIfMissing = true)
public class MidtransGateway implements PaymentGateway { ... }
```

> **Pitfall #2:** `@Dependent` (the default scope for a plain class) creates a new instance every time
> it is injected. A library that keeps a cache in a `@Dependent` bean will never actually use
> that cache. If you need state, use `@ApplicationScoped`.

## REST (RESTEasy Reactive / Jackson)

```java
@Path("/api/orders")
@Produces(MediaType.APPLICATION_JSON)
@Consumes(MediaType.APPLICATION_JSON)
public class OrderResource {

    @Inject OrderQueryService query;

    @GET
    @Path("/{id}")
    public OrderResponse findById(@PathParam("id") long id) {
        return query.findById(id);
    }

    @POST
    public RestResponse<OrderResponse> create(@Valid CreateOrderRequest request) {
        OrderResponse created = query.create(request);
        return RestResponse.status(Status.CREATED, created);   // 201 + body
    }

    @GET
    @Path("/stream")
    public Multi<OrderResponse> stream() {                     // streaming, not a list
        return query.streamAll();
    }
}
```

```java
// REST Client (MicroProfile) — declare it, don't use RestTemplate
@RegisterRestClient(configKey = "payment-api")
@Path("/v1/charges")
public interface PaymentClient {

    @POST
    Uni<ChargeResponse> charge(ChargeRequest request);

    @GET @Path("/{id}")
    ChargeResponse find(@PathParam("id") String id);
}
```

```properties
# application.properties
payment-api/mp-rest/url=https://api.payment.example
payment-api/mp-rest/timeout=5000
```

| Item | Quarkus | Spring MVC |
| :--- | :--- | :--- |
| Resource method invocation | runs on the **event loop** by default | servlet thread pool |
| Blocking DB call in a resource | must be `@Blocking` or `@Transactional` | safe (thread per request) |
| Large body / streaming | `Multi<T>` / `InputStream` | `StreamingResponseBody` |
| Client | MicroProfile REST Client | `RestClient` / `WebClient` |

> **Pitfall #3:** a non-`Uni` resource that calls JDBC must be `@Blocking`
> (a `@Transactional` method is usually treated as blocking automatically). Without that, a
> blocking request on the event loop → every other request on the same worker is stalled too.

## Validation & error handling

```java
public record CreateOrderRequest(
    @NotNull Long productId,
    @Min(1) @Max(100) int quantity
) {}

// Global exception mapper — one class for the whole application
@Provider
public class DomainExceptionMapper implements ExceptionMapper<DomainException> {

    @Override
    public Response toResponse(DomainException e) {
        return Response.status(Status.UNPROCESSABLE_ENTITY)
            .entity(Map.of("error", e.code(), "message", e.getMessage()))
            .build();
    }
}

// Mapper for Bean Validation failures
@Provider
public class ValidationExceptionMapper implements ExceptionMapper<ConstraintViolationException> {
    @Override
    public Response toResponse(ConstraintViolationException e) {
        Map<String, String> fields = e.getConstraintViolations().stream()
            .collect(Collectors.toMap(
                v -> v.getPropertyPath().toString(),
                ConstraintViolation::getMessage,
                (a, b) -> a));
        return Response.status(400).entity(Map.of("fields", fields)).build();
    }
}
```

## Panache (Active Record & Repository)

Panache removes CRUD boilerplate. Pick **one** style per bounded context — don't mix them.

```java
// Style A - Active Record: the entity knows how to load itself
@Entity
public class Order extends PanacheEntity {          // the id field (Long) is already there

    public Long merchantId;
    @Enumerated(EnumType.STRING) public OrderStatus status;
    public BigDecimal totalPrice;

    public static List<Order> byMerchantAndStatus(Long merchantId, OrderStatus status) {
        return list("merchantId = ?1 and status = ?2", merchantId, status);
    }

    public static Optional<Order> byIdWithItems(Long id) {
        return find("select o from Order o join fetch o.items where o.id = ?1", id)
            .singleResultOptional();
    }
}

// Style B - Repository (use it when the entity is shared across services)
@ApplicationScoped
public class OrderRepository implements PanacheRepository<Order> {

    public List<Order> byStatus(OrderStatus status) {
        return list("status", status);
    }
}
```

```java
@ApplicationScoped
public class OrderService {

    @Inject OrderRepository repository;

    @Transactional                              // required for write operations
    public OrderResponse create(CreateOrderRequest req) {
        Order order = new Order();
        order.merchantId = req.productId();
        order.status = OrderStatus.PENDING;
        order.persist();                        // Active Record
        return OrderResponse.from(order);
    }
}
```

| Item | Active Record | Repository |
| :--- | :--- | :--- |
| Boilerplate | the least | one class per entity |
| Unit testing | hard (static) | easy (mock) |
| Entity in other layers | the entity "knows the DB" | the entity stays dumb |
| Good for | small services, CRUD | complex domains |

> **Pitfall #4:** Panache performs **bytecode rewriting** at build time — that is why
> `order.persist()` works without an `EntityManager`. That is also why a Panache entity cannot be
> used as a plain Hibernate entity in another module; everything must go through the Quarkus build.

## Configuration & profiles

```properties
# application.properties
quarkus.http.port=8083
quarkus.datasource.db-kind=postgresql
quarkus.datasource.jdbc.url=jdbc:postgresql://${DB_HOST:localhost}:5432/${DB_NAME:pos_sales}
quarkus.datasource.username=${DB_USER:mqr_user}
quarkus.datasource.password=${DB_PASS:mqr_pass}
quarkus.hibernate-orm.database.generation=validate
quarkus.flyway.migrate-at-start=true
quarkus.flyway.baseline-on-migrate=true

# profiles: %dev / %test / %prod%
%dev.quarkus.datasource.jdbc.url=jdbc:postgresql://localhost:5432/pos_sales_dev
%dev.quarkus.hibernate-orm.log.sql=true
%prod.quarkus.datasource.jdbc.max-size=20
%prod.quarkus.http.header."Strict-Transport-Security".value=max-age=31536000
```

```java
// Typed config — validated at boot, not an NPE in the middle of a request
@ConfigMapping(prefix = "app.ratelimit")
public interface RateLimitConfig {

    @WithDefault("true") boolean enabled();
    @WithDefault("60") int maxPerMinute();

    Optional<String> allowlist();        // no default = optional
}

@ApplicationScoped
public class RateLimiter {
    @Inject RateLimitConfig config;
}
```

| Rule | Why |
| :--- | :--- |
| Use `@ConfigMapping` (interface), not scattered `@ConfigProperty` | validated at boot, one place |
| Env var = `APP_RATELIMIT_MAXPERMINUTE` | Quarkus maps it automatically (uppercase + `_`) |
| Some `quarkus.*` settings are **fixed at build time** | changing them at deploy time = no effect |
| Don't put secrets in `application.properties` | use env / Vault / a secret manager |
| `%prod` overrides the profile-less value | re-audit when upgrading Quarkus |

> **Pitfall #5:** telling build-time from runtime config is mandatory. `quarkus.datasource.db-kind`
> and `quarkus.hibernate-orm.database.generation` are read **at build time** — changing them at
> deployment has no effect; the image must be rebuilt. Usually runtime: connection URL, port,
> credentials, log level.

## Reactive vs virtual threads

Quarkus 3 supports two styles; **choose per endpoint**, don't mix them in one method.

```java
// Style 1 - Reactive (Uni/Multi). Non-blocking, one event loop for many requests.
@GET
public Uni<List<OrderResponse>> list() {
    return Order.<Order>listAll()
        .map(orders -> orders.stream().map(OrderResponse::from).toList());
}

// Style 2 - Virtual threads (Java 21). Ordinary blocking code, without exhausting the thread pool.
@RunOnVirtualThread
@Transactional
@GET
@Path("/heavy")
public List<ReportRow> heavyReport() {
    return reportService.compute();        // may block
}
```

| Style | When | Trade-off |
| :--- | :--- | :--- |
| `Uni`/`Multi` | heavy I/O, high throughput, streaming | mutation chains; longer stack traces |
| `@RunOnVirtualThread` | blocking/legacy code, plain JDBC drivers | pinning if there is a long `synchronized` block |
| `@Blocking` | blocking on the worker pool | throughput limited by `quarkus.vertx.worker-pool-size` |

> **Pitfall #6:** mixing `Uni` with a blocking call does not produce an error — the
> event loop just stalls and the latency of every endpoint goes up. The rule: **the event loop must
> not block, period.**

## Testing

```java
// 1. Pure unit test — no Quarkus at all
@ExtendWith(MockitoExtension.class)
class OrderServiceTest {
    @Mock OrderRepository repository;
    @InjectMocks OrderService service;
}

// 2. Integration test — Quarkus starts once for the whole class
@QuarkusTest
class OrderResourceTest {

    @Test
    void shouldReturn400OnInvalidQuantity() {
        given()
            .contentType(ContentType.JSON)
            .body("{\"productId\": 1, \"quantity\": 0}")
        .when()
            .post("/api/orders")
        .then()
            .statusCode(400);
    }
}

// 3. Native test — run the same suite against the binary (requires GraalVM)
// @QuarkusIntegrationTest
```

```properties
# Dev Services: DB/Kafka automatically during dev & test (requires Docker)
%test.quarkus.datasource.devservices.enabled=true
%test.quarkus.datasource.devservices.init-script-path=src/test/resources/seed.sql
```

| Test | Cost | Used for |
| :--- | :--- | :--- |
| Unit (Mockito) | milliseconds | business logic |
| `@QuarkusTest` | 1 JVM boot | resources, repositories, config, wiring |
| `@QuarkusIntegrationTest` | native/jar boot | ensures the native image doesn't lose reflection |
| Continuous testing (`quarkus dev` → `r`) | automatic on save | fast loop |

> **Pitfall #7:** `@QuarkusTest` does **not** reload the context between test classes. A stateful
> `@ApplicationScoped` bean carries over into the next test — reset it in
> `@BeforeEach`, or use `@TestProfile` for different configuration.

## Native image

```bash
# Native build (container build, no local GraalVM)
./mvnw package -Dnative -Dquarkus.native.container-build=true

# Realistic size & startup
ls -lh target/*-runner
./target/*-runner      # starts in ~20-60 ms, RSS ~40-80 MB for a small REST service
```

```properties
# Native: anything accessed via reflection / as a resource must be registered
quarkus.native.resources.includes=db/migration/*.sql,templates/**
quarkus.native.additional-build-args=-H:+ReportExceptionStackTraces
```

| Native problem source | Symptom | Fix |
| :--- | :--- | :--- |
| Reflection into a library class | `ClassNotFoundException` only in native | `@RegisterForReflection` / config |
| Resources (files, templates) | empty template, migrations don't run | `quarkus.native.resources.includes` |
| Dynamic proxy / ServiceLoader | `ServiceConfigurationError` | the extension usually handles it; third-party libraries need config |
| Jackson serialization | missing fields / parse error | register the DTO or use a plain-class DTO |
| Fast startup but errors | passes on JVM, fails in native | run `@QuarkusIntegrationTest` |

> **Pitfall #8:** green tests on the JVM do not guarantee native works. **Always** run the native
> integration test suite in CI before release — the only way to catch missing reflection
> is to run the binary.

## Observability & health

```properties
quarkus.smallrye-health.liveness-path=/q/health/live
quarkus.smallrye-health.readiness-path=/q/health/ready
quarkus.micrometer.export.prometheus.path=/q/metrics
quarkus.otel.exporter.otlp.endpoint=http://alloy:4317
quarkus.otel.service.name=order-service
quarkus.log.console.json=true
quarkus.log.category."org.hibernate".level=INFO
```

| Endpoint | Contents |
| :--- | :--- |
| `/q/health/live` | process is alive — don't check dependencies here |
| `/q/health/ready` | ready to take traffic — DB, Kafka, cache |
| `/q/metrics` | Micrometer → Prometheus |
| `/q/dev` | Dev UI (dev only) |
| `/q/openapi` | OpenAPI + Swagger UI (extension `smallrye-openapi`) |

> **Pitfall #9:** a readiness check that opens a new connection every second from Kubernetes will
> drain a small pool. Use the extension's built-in health check (it already shares the pool) or cache it.

## Container & JVM tuning

```dockerfile
# Multi-stage: build in a Maven image, run on a minimal JRE
FROM maven:3.9-eclipse-temurin-21 AS build
WORKDIR /src
COPY pom.xml .
RUN mvn -q dependency:go-offline
COPY src src
RUN mvn -q clean package -DskipTests

FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
COPY --from=build /src/target/quarkus-app/ /app/
EXPOSE 8080
ENTRYPOINT ["java", "-XX:MaxRAMPercentage=75", "-jar", "/app/quarkus-run.jar"]
```

| Mode | Startup | RSS | Image |
| :--- | :--- | :--- | :--- |
| JVM (`quarkus-run.jar`) | ~300-800 ms | ~120-200 MB | ~200 MB (JRE) |
| Native executable | ~20-60 ms | ~40-80 MB | ~80-120 MB |
| Native distroless/scratch | ~20 ms | ~40 MB | ~50 MB |

> **Pitfall #10:** `quarkus-app/` is a **directory**, not a single fat jar. Copying only
> `quarkus-run.jar` will fail (`lib/` and `quarkus/` are missing). Copy the whole directory,
> or use `quarkus.package.jar.type=uber-jar` if it really has to be one file.

## Quick comparison with Spring Boot

| Aspect | Quarkus | Spring Boot |
| :--- | :--- | :--- |
| JVM boot time | hundreds of ms | 1-5 seconds |
| Native image | first-class | supported, needs extra hints |
| DI | CDI, mostly build-time | Spring container, runtime proxies |
| HTTP model | Vert.x event loop, reactive-first | servlet thread-per-request (or WebFlux) |
| Live reload | built-in Dev Mode | DevTools (limited restarts) |
| Ecosystem | smaller, enough for REST/DB/messaging | the largest |
| Debugging "bean not found" | check the build output | check component scanning |

## Pitfalls (must read)

| Pitfall | Symptom | Solution |
| :--- | :--- | :--- |
| Bean not discovered | `UnsatisfiedResolutionException` at boot | check `@ApplicationScoped`, don't make the class `private`, check `quarkus.index-dependency` |
| Blocking on the event loop | Latency rises on every endpoint, BlockedThreadChecker warning | `@Blocking` / `Uni` / `@RunOnVirtualThread` |
| `@Transactional` on a non-public method | Transaction silently inactive | put it on a public bean method |
| Missing `@Transactional` on a Panache write | `TransactionRequiredException` | annotate at the service boundary |
| Changing build-time config at deploy | No effect | rebuild the image |
| Reflection in native | works on JVM, fails in native | `@RegisterForReflection` + integration test |
| Dev Services in production | Unexpected DB containers | disable explicitly in `%prod` |
| `record` DTO in native | empty response | register reflection or use a plain-class DTO |
| Expecting a fat jar | `quarkus-run.jar` fails to start | copy `quarkus-app/` or set `jar.type=uber-jar` |
| State in a `@Dependent` bean | Cache is never hit | `@ApplicationScoped` |
| `database.generation=update` | Schema changes silently | `validate` + Flyway |
| Health check hammering the DB | Pool exhausted, requests fail | lightweight readiness / cache it |
