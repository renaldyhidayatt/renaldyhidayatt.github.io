## CLI & diagnostics

## What's new in 9.0

```js
// per-operation memory limit (default: 1 GB or 20% of server memory, whichever is larger)
// queries that exceed it → ExceededMemoryLimit (146) / QueryExceededMemoryLimitNoDiskUseAllowed (292)
db.adminCommand({
  setParameter: 1,
  internalQueryMaxMemoryUsageBytesPerOperation: 512 * 1024 * 1024
});

// per-single-expression memory limit (default 100 MB)
db.adminCommand({
  setParameter: 1,
  internalQueryMaxSingleExpressionMemoryUsageBytes: 64 * 1024 * 1024
});
```

```js
// $queryStats is now enabled by default, sampling 1% of operations
// (internalQueryStatsSampleRate & internalQueryStatsWriteCmdSampleRate default to 0.01)
db.aggregate([
  { $queryStats: {} },
  { $group: { _id: "$queryShape", count: { $sum: 1 }, totalTime: { $sum: "$metrics.queryExec.time" } } },
  { $sort: { totalTime: -1 } },
  { $limit: 10 }
]);
```

```js
// new validation level: "constraint" — guarantees ALL documents satisfy the rules
db.createCollection("orders", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["orderId", "status", "total"],
      properties: {
        orderId: { bsonType: "string" },
        status: { enum: ["PENDING", "PAID", "FAILED"] },
        total: { bsonType: "decimal", minimum: 0 }
      }
    }
  },
  validationLevel: "constraint",     // new in 9.0
  validationAction: "error"
});
```

| 9.0 feature | Meaning |
| :--- | :--- |
| Per-operation memory limit | Heavy queries fail **rather than** crashing the server's RAM |
| `internalQueryMaxSingleExpressionMemoryUsageBytes` | Limit per expression (default 100 MB) |
| `maxConcurrentMultiDocumentTransactions` | Default 10000 open transactions → `TooManyOpenTransactions` error |
| Validation level `constraint` | Guarantees all documents (not just new ones) are valid |
| `$queryStats` enabled by default | Query statistics without manual enabling (1% sampling) |
| `querySettings` as a command field | `find`/`distinct`/`aggregate` can accept `querySettings` |
| `queryKnobs` | Override internal parameters per *query shape* (FCV 9.0+) |
| `maxTimeMS` per query shape | Time limit per shape via `setQuerySettings` (FCV 9.0+) |
| Server-side JS is back | `$accumulator`, `$function`, `$where` — WASM-based engine, stricter sandbox |
| Time series reworked | Stored as a single namespace containing compressed buckets |
| `mongocryptd` deprecated | Replaced by the Automatic Encryption Shared Library |
| QEC prefix/suffix/substring | Encrypted strings can be partially searched (GA) |

> 9.0 upgrade warning: clusters with **more than 5,000 time series collections** per
> database will upgrade more slowly — remove the unused ones first.

## 5-minute mental model

| Concept | Summary |
| :--- | :--- |
| Document | BSON data unit, self-contained, max 16 MB |
| Collection | a set of documents; no fixed schema required |
| `_id` | automatic primary key (ObjectId: 12 bytes) |
| Embedded vs reference | embed = data inside the document; reference = `_id` to another document |
| Replica set | ≥3 nodes for HA + transactions + change streams |
| Sharding | horizontal scale via a **shard key** |
| WiredTiger | default storage engine; cache + checkpoints |
| MVCC | snapshot reads; no locks while reading |
| Write concern | how "deep" a write must land (majority, w:majority, j) |
| Read concern | how "fresh" the data being read may be |
| Read preference | which node is read (primary, secondary, nearest) |
| Aggregation pipeline | query framework: array of stages, output becomes new documents |
| BSON | binary JSON: supports Date, Decimal128, ObjectId, Array |

## Modelling: embed vs reference

```js
// EMBED — data always read together & with a 1:1 or 1:small ratio
{
  _id: ObjectId("..."),
  orderId: "ORD-2026-0001",
  status: "PENDING",
  total: NumberDecimal("450000.00"),
  items: [                                // embedded array
    { productId: "P-1", qty: 2, price: NumberDecimal("125000.00") },
    { productId: "P-2", qty: 1, price: NumberDecimal("200000.00") }
  ],
  createdAt: ISODate("2026-10-21T10:00:00Z")
}

// REFERENCE — large data, shared, or many-to-many relationships
{
  _id: ObjectId("..."),
  merchantId: ObjectId("..."),   // do not embed the merchant
  customerId: ObjectId("...")
}
```

| Question | Embed | Reference |
| :--- | :--- | :--- |
| Always read together? | yes | no |
| Ratio | 1:1 or 1:few | 1:N / N:N |
| Data size | < 1–2 MB | large / unbounded |
| Changing one part | rewrite the whole document | only that document |
| Array growth | **dangerous** (16 MB limit) | safe |

> **Pitfall:** an embedded array that grows without bound (e.g. order history) = the document
> grows, `$push` becomes expensive, and it quickly hits the 16 MB limit. Move it to a separate collection
> once the 1:N ratio changes.

**Practical guidance:**
- Embed limit: ideally an array of < 100 elements, < 1000 is still reasonable.
- Only embed data that does **not** grow on its own (transactions, items, snapshots).
- References that are often read together → denormalize a compact field (e.g. keep `merchantName`
  on the order) and sync it via change streams/outbox.

## Schema validation

```js
// per-collection validator
db.createCollection("payments", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["paymentId", "amount", "status"],
      properties: {
        paymentId: { bsonType: "string", pattern: "^PAY-" },
        amount: { bsonType: "decimal", minimum: 0, maximum: NumberDecimal("1000000000") },
        status: { enum: ["PENDING", "SUCCESS", "FAILED"] },
        channel: { enum: ["VA", "QRIS", "CARD"] },
        idempotencyKey: { bsonType: "string" },
        createdAt: { bsonType: "date" },
        metadata: { bsonType: "object" }
      }
    }
  },
  validationLevel: "strict",      // "moderate" = only new documents are checked
  validationAction: "error"      // or "warn" (log only)
});

// 9.0 validation level: "constraint" — all documents are guaranteed to satisfy the rules
db.runCommand({ collMod: "payments", validator: { $jsonSchema: { ... } }, validationLevel: "constraint" });

// validator with $expr (cross-field computation)
db.runCommand({
  collMod: "orders",
  validator: {
    $expr: {
      $lte: [{ $size: { $ifNull: ["$items", []] } }, 1000]
    }
  }
});
```

| `validationLevel` | Meaning |
| :--- | :--- |
| `strict` | every insert & update is validated (default) |
| `moderate` | only **changed** documents are validated; old documents may be invalid |
| `constraint` | (9.0) guarantees the entire collection satisfies the rules |

> **Pitfall:** `moderate` = old invalid documents are **not** cleaned up automatically.
> Use `constraint` if you need a full guarantee, but throttle it on large collections.

## CRUD & queries

```js
// insert
db.orders.insertOne({ orderId: "ORD-1", total: NumberDecimal("1000.00"), createdAt: new Date() });
db.orders.insertMany([{ orderId: "ORD-2" }, { orderId: "ORD-3" }], { ordered: false });

// upsert — idempotent, MUST use a unique index
db.orders.updateOne(
  { orderId: "ORD-1" },
  { $set: { status: "PAID", updatedAt: new Date() },
    $setOnInsert: { createdAt: new Date() } },
  { upsert: true }
);

// bulk write
db.orders.bulkWrite([
  { updateOne: { filter: { orderId: "ORD-1" }, update: { $set: { status: "PAID" } } } },
  { insertOne: { document: { orderId: "ORD-9" } } }
], { ordered: false });

// query
db.orders.find({ status: "PAID", "total": { $gte: 100000 } })
        .sort({ createdAt: -1 })
        .limit(20)
        .skip(0)
        .project({ orderId: 1, total: 1, _id: 0 });

// operators
db.orders.find({
  createdAt: { $gte: ISODate("2026-10-01"), $lt: ISODate("2026-11-01") },
  status: { $in: ["PENDING", "PAID"] },
  "items.productId": "P-1"
});

// distinct & count
db.orders.distinct("merchantId");
db.orders.countDocuments({ status: "PAID" });      // accurate, may be slow
db.orders.estimatedDocumentCount();               // fast, estimate

// update with array operators
db.orders.updateOne({ orderId: "ORD-1" }, { $inc: { revision: 1 } });
db.orders.updateOne({ orderId: "ORD-1" }, { $push: { history: { at: new Date(), event: "PAID" } } });
db.orders.updateOne({ orderId: "ORD-1" }, { $set: { "items.0.qty": 3 } });
db.orders.updateMany({ status: "PENDING" }, { $unset: { note: "" } });

// delete
db.orders.deleteOne({ orderId: "ORD-1" });
db.orders.deleteMany({ createdAt: { $lt: ISODate("2020-01-01") } });
```

| Operator | Meaning |
| :--- | :--- |
| `$eq` `$ne` `$gt` `$gte` `$lt` `$lte` | comparison |
| `$in` `$nin` | set membership |
| `$exists` | whether the field exists |
| `$regex` | pattern (slow; use a text index if it fits) |
| `$and` `$or` `$nor` | logic |
| `$not` | negation |
| `$elemMatch` | match several fields within a single array element |
| `$all` | array contains all values |
| `$type` | check BSON type |

## Indexes

```js
// single field
db.orders.createIndex({ merchantId: 1 });

// compound — column order matters
db.orders.createIndex({ merchantId: 1, status: 1, createdAt: -1 });

// unique (upsert requires this)
db.orders.createIndex({ orderId: 1 }, { unique: true });

// partial — only documents matching the filter
db.orders.createIndex(
  { merchantId: 1, createdAt: -1 },
  { partialFilterExpression: { status: "PENDING" } }
);

// TTL — automatic deletion after a time
db.sessions.createIndex({ createdAt: 1 }, { expireAfterSeconds: 3600 });

// multikey — index over an array
db.orders.createIndex({ "items.productId": 1 });      // multikey

// wildcard — index every field
db.products.createIndex({ "attributes.$**": 1 });

// text index — full-text search
db.products.createIndex({ name: "text", description: "text" }, { weights: { name: 10 } });
db.products.find({ $text: { $search: "sepatu sport" } });

// sparse — only documents that have the field
db.users.createIndex({ phone: 1 }, { sparse: true });

// collation — case-insensitive
db.users.createIndex({ email: 1 }, { collation: { locale: "en", strength: 2 } });

// hidden — ignored by the optimizer, but present for sorting
db.orders.createIndex({ internalCode: 1 }, { hidden: true });
```

| Type | For | Note |
| :--- | :--- | :--- |
| Single field | equality, sort | default |
| Compound | multi-field queries | **order matters** |
| Multikey | arrays | one multikey index per collection |
| Text | full text | one text index per collection |
| Wildcard | schemaless (document store) | includes every subfield |
| TTL | expiring data | not precise, cleaned up after ~60 seconds |
| Unique | guarantees | duplicates rejected |
| Partial | small subsets | most efficient for terminal states |
| Sparse | fields often missing | does not index documents without the field |
| Hidden | internal sorting | ignored by the optimizer |

```js
// index prefix: index {a:1, b:1} can serve queries {a}, {a,b}
db.orders.find({ merchantId: "M1", status: "PAID" }).explain("executionStats")
// check: IXSCAN + winning plan

// unused indexes → drop them
db.orders.getIndexes();
db.orders.dropIndex("merchantId_1_status_1_createdAt_-1");
```

## Aggregation pipeline

```js
// lookup: join across collections
db.orders.aggregate([
  { $match: { status: "PAID", createdAt: { $gte: ISODate("2026-10-01") } } },  // 1. filter first!
  { $lookup: {
      from: "merchants",
      localField: "merchantId",
      foreignField: "_id",
      as: "merchant"
  } },
  { $unwind: "$merchant" },
  { $project: { orderId: 1, total: 1, merchantName: "$merchant.name" } },
  { $group: {
      _id: "$merchantName",
      revenue: { $sum: "$total" },
      orders: { $sum: 1 },
      avg: { $avg: "$total" }
  } },
  { $sort: { revenue: -1 } },
  { $limit: 20 }
]);

// facet: multiple results from one pipeline
db.orders.aggregate([
  { $facet: {
      byStatus: [{ $group: { _id: "$status", count: { $sum: 1 } } }],
      byMerchant: [{ $group: { _id: "$merchantId", total: { $sum: "$total" } } }, { $limit: 5 }]
  } }
]);

// $unwind + $group for top products
db.orders.aggregate([
  { $unwind: "$items" },
  { $group: { _id: "$items.productId", qty: { $sum: "$items.qty" } } },
  { $sort: { qty: -1 } },
  { $limit: 10 }
]);

// $set / $addFields
{ $set: { totalWithTax: { $multiply: ["$total", 1.11] } } }

// $bucket — histogram
{ $bucket: { groupBy: "$total", boundaries: [0, 100000, 500000, 1000000], default: "other" } }

// $graphLookup — recursive (nested categories)
{ $graphLookup: {
    from: "categories",
    startWith: "$parentId",
    connectFromField: "_id",
    connectToField: "_id",
    as: "descendants"
} }
```

| Stage | Meaning |
| :--- | :--- |
| `$match` | filter — **always first** |
| `$project` | select/rename fields |
| `$addFields` / `$set` | add fields |
| `$unset` | remove fields |
| `$group` | aggregation + `$sum` `$avg` `$min` `$max` `$push` `$addToSet` |
| `$sort` | sort |
| `$limit` / `$skip` | trim the result set |
| `$unwind` | split an array into documents |
| `$lookup` | join (equi-join) |
| `$facet` | several pipelines at once |
| `$replaceRoot` | replace the root document |
| `$merge` / `$out` | write results to a collection |
| `$graphLookup` | recursive lookup |
| `$bucketAuto` | automatic histogram |

> **Pitfall:** `$lookup` **cannot** use an index on `foreignField` unless it is the same field
> as `localField` and there is a pipeline. Use `allowDiskUse: true` for large pipelines,
> but 9.0 enforces stricter per-operation memory limits.

## Transactions

```js
// multi-document transaction — requires a replica set
const session = db.getMongo().startSession();
session.startTransaction();
try {
  db.accounts.updateOne(
    { _id: "ACC-1", balance: { $gte: 500000 } },
    { $inc: { balance: -500000 } },
    { session }
  );
  db.orders.insertOne(
    { orderId: "ORD-1", total: NumberDecimal("500000.00"), status: "PAID" },
    { session }
  );
  session.commitTransaction();
} catch (e) {
  session.abortTransaction();
  throw e;
} finally {
  session.endSession();
}
```

```js
// transaction with retry (write conflict / transient error)
function withTransaction(fn, maxRetry = 3) {
  const session = db.getMongo().startSession();
  session.startTransaction();
  let attempt = 0;
  while (true) {
    try {
      const r = fn(session);
      session.commitTransaction();
      return r;
    } catch (e) {
      if (e.hasErrorLabel("TransientTransactionError") && attempt++ < maxRetry) {
        session.abortTransaction();
        session.startTransaction();
        continue;
      }
      session.abortTransaction();
      throw e;
    }
  }
}
```

| Rule | Detail |
| :--- | :--- |
| Requires | a replica set (not standalone) |
| Limit | `maxConcurrentMultiDocumentTransactions` defaults to **10000** (9.0) |
| Error | `TooManyOpenTransactions` when the limit is exceeded |
| Size | large transactions (>16 MB) fail |
| Lifetime | open transactions hold the oplog — do not hold them for long |
| Retriable | errors labeled `TransientTransactionError` → retry |
| Unknown commit | label `UnknownTransactionCommitResult` → retry the **commit**, not the whole transaction |

> **Pitfall:** transactions are **not** suited to long cross-request flows (e.g.
> waiting for user approval). Transactions hold locks & the oplog — for those use a **saga** +
> idempotency key.

## Read concern, write concern, read preference

```js
// write concern — how deep a write must land
db.orders.insertOne(doc, { writeConcern: { w: "majority", j: true, wtimeout: 5000 } });
// w:"majority" = written to a majority of nodes, j:true = written to the journal
// wtimeout = do not wait more than 5 seconds

// read concern
db.orders.find({}).readConcern("majority");    // data already on a majority
db.orders.find({}).readConcern("linearizable"); // freshest read (expensive)

// read preference
db.orders.find({}).readPreference("primaryPreferred");
db.orders.find({}).readPreference("secondaryPreferred", { maxStalenessSeconds: 90 });
```

| Write concern | Trade-off |
| :--- | :--- |
| `w: 1` | primary only (default) — can be lost on failover |
| `w: "majority"` | safe, but slower |
| `j: true` | written to the journal (durable) |
| `wtimeoutMS` | wait limit, then error — **never** leave it unbounded |

| Read concern | Trade-off |
| :--- | :--- |
| `local` | latest data on that node (default) |
| `available` | whichever node has the data |
| `majority` | data already on a majority |
| `linearizable` | freshest, expensive, primary only |

| Read preference | Read from |
| :--- | :--- |
| `primary` | primary only (default, freshest) |
| `primaryPreferred` | primary, fallback to secondary |
| `secondary` | secondary only (may be stale) |
| `secondaryPreferred` | secondary, fallback to primary |
| `nearest` | nearest node (low latency) |

> **Pitfall:** `w:1` + a dead pod = permanently lost data. For financially
> critical data, `w:"majority"` is not optional.

## Change streams

```js
// watch changes on a collection
const stream = db.orders.watch([
  { $match: { operationType: { $in: ["insert", "update", "delete"] } } }
], { fullDocument: "updateLookup", maxAwaitTimeMS: 1000 });

while (const change of stream) {
  if (change.operationType === "insert") {
    outbox.push({ event: "order.created", doc: change.fullDocument });
  }
}
```

```js
// resume from the last position (you MUST persist the resume token!)
const token = lastChange._id;      // persist it
const stream2 = db.orders.watch([], { resumeAfter: token });

// pre-image (9.0: pre-image metrics changed, but the feature remains)
db.createCollection("audit", { changeStreamPreImages: { enabled: true } });
```

| Option | Meaning |
| :--- | :--- |
| `fullDocument: "updateLookup"` | full document on update (extra query) |
| `fullDocument: "whenAvailable"` | only when available |
| `resumeAfter` | continue from a token |
| `startAfter` | start after an event (for invalidate) |
| `startAtOperationTime` | start from a timestamp |
| `maxAwaitTimeMS` | heartbeat wait limit |

> **Pitfall:** change streams do **not** survive a restart. Persist the `resume token` (or
> `startAtOperationTime`) in durable storage, otherwise events during downtime
> are lost. The oplog also has a window limit — a stream idle for too long **cannot**
> be resumed.

## Connections & pooling

```
App (driver pool) ──▶ mongod (replica set)
```

```js
// connection string
mongodb://user:pass@host1:27017,host2:27017,host3:27017/appdb?replicaSet=rs0&retryWrites=true&w=majority
mongodb+srv://cluster.mongodb.net/            // Atlas, TLS otomatis
```

```go
// Go — mongo-driver
import "go.mongodb.org/mongo-driver/v2/mongo"

client, err := mongo.Connect(options.Client().
    ApplyURI(uri).
    SetMaxPoolSize(100).
    SetMinPoolSize(10).
    SetMaxConnIdleTime(30 * time.Second).
    SetRetryWrites(true))
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
err = client.Ping(ctx, nil)
```

```java
// Java — connection string + pooling
MongoClientSettings settings = MongoClientSettings.builder()
    .applyConnectionString(new ConnectionString(uri))
    .applyToConnectionPoolSettings(b -> b.maxSize(100).minSize(10).maxConnectionIdleTime(30, SECONDS))
    .build();
MongoClient client = MongoClients.create(settings);
```

| Parameter | Meaning |
| :--- | :--- |
| `maxPoolSize` | maximum connections per app |
| `minPoolSize` | connections kept prewarmed |
| `waitQueueTimeoutMS` | queue wait limit (REQUIRED) |
| `connectTimeoutMS` | connection timeout |
| `socketTimeoutMS` | socket timeout |
| `retryWrites` | retry writes that can be retried |
| `appName` | identifies the app in server logs |
| `serverSelectionTimeoutMS` | time limit for finding a suitable node |

> **Pitfall:** modern drivers **already** manage the pool. Adding your own pool on top
> (e.g. `maxPoolSize=0`, _meaning unlimited) = thousands of connections → the server is overwhelmed.

## Migrations & Mongock

```java
// Mongock — Java-based migrations (Spring Boot)
// src/test/resources/mongo/...
@When("now")
@Then("there are ${count} documents in the '${collection}' collection")
public void thereAreDocuments(String collection, int count) {
    MongoTemplate template = ...;
    assertThat(template.getCollection(collection).countDocuments()).isEqualTo(count);
}

@When("the '${collection}' collection is empty")
public void collectionIsEmpty(String collection) { ... }
```

```js
// manual migration — collection versioning
db.createCollection("schema_migrations");
db.schema_migrations.insertOne({ version: 1, appliedAt: new Date(), script: "init" });

// apply idempotently
db.runCommand({ collMod: "orders", validator: { ... } });
```

| Approach | Fits |
| :--- | :--- |
| Mongock | Spring Boot, tests + Java-based migrations |
| Mongock Standalone | CLI for migrations outside Spring |
| Manual JS script | Small collections, simple migrations |
| Flyway/Liquibase | Relational only (not MongoDB) |

> **Pitfall:** MongoDB migrations do **not** have cross-collection transactions by default
> (multi-collection transactions are possible in 4.2+, but not every operation is supported).
> Write **idempotent** migrations — running twice must yield the same result.

## Pitfalls (required reading)

| Pitfall | Symptom | Solution |
| :--- | :--- | :--- |
| Embedded array grows unbounded | Doc nearing 16 MB, `$push` slow | Split into another collection |
| Custom `_id` random strings | Not iterable, large | Leave ObjectId, or use UUIDv7 |
| ObjectId as a URL param | Index changes characters | ObjectId hex strings are safe, but still time-ordered |
| `find()` without a filter | Scans the whole collection | Always filter + index |
| `$lookup` inside `$match` | Full scan | Filter first in an early stage |
| Large pipeline without `allowDiskUse` | Query fails | `allowDiskUse: true` + 9.0 memory limit |
| `w:1` on important data | Data lost on failover | `w: "majority"` + `j: true` |
| `Number` (double) fields for money | Rounding errors | `NumberDecimal` / `Decimal128` |
| Schema changes without a validator | Heterogeneous documents | `$jsonSchema` + validation level |
| `countDocuments` in paging | Slow | `estimatedDocumentCount` or count via `$group` |
| Regex without an index | Full scan | `$text` index or prefix anchor `^` |
| Too many indexes | Slow writes | Drop indexes with `idx_scan = 0` |
| Long transactions | Locks & oplog held | Short transactions, or a saga |
| Change streams without a resume token | Events lost on restart | Persist the token |
| `unique: true` without `upsert` | Duplicates still get in | Upsert + unique filter |
| Sharding without a proper shard key | Slow scatter-gather | Shard key matching the access pattern |
| `ObjectId` sorting | Timestamp-based, fine | If you need other ordering, use a separate field |
| `moderate` validation | Old documents invalid | Use `constraint` (9.0) or clean up manually |
| Connection string without `retryWrites` | Writes fail on failover | `retryWrites=true` |
