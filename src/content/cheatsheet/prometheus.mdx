## Mental model

| Concept | Summary |
| :--- | :--- |
| Pull-based | Prometheus **pulls** metrics from targets (not push) |
| Time series | unique identity = `metric_name{label="value", ...}` |
| TSDB | local storage, chunk + index, default retention 15 days |
| Scrape | request `/metrics` per target, according to `scrape_interval` |
| Federation | Prometheus takes metrics from another Prometheus (hierarchy) |
| Remote write | send samples to a remote backend (Mimir/Thanos/VictoriaMetrics) |
| Exemplar | pointer from metric to trace (OpenMetrics) |
| Staleness | series disappears 5 minutes after last scrape → gaps in graph |
| Pushgateway | for batch jobs, **not** for long-running services |

```
targets ──scrape──▶ Prometheus (TSDB) ──query──▶ Grafana
                        │
                        ├──remote_write──▶ Mimir/Thanos (long-term)
                        ├──alert rules──▶ Alertmanager ──▶ Slack/PagerDuty
                        └──federation──▶ Prometheus (other cluster)
```

## Metric types & naming

```
<namespace>_<subsystem>_<unit>          # convention: base unit, snake_case
http_server_request_duration_seconds    # histogram (seconds)
http_server_requests_total              # counter
db_pool_connections_active              # gauge
process_resident_memory_bytes           # gauge
```

| Type | Behavior | Example | Use when |
| :--- | :--- | :--- | :--- |
| **Counter** | only goes up | `requests_total` | event_rate, error_rate |
| **Gauge** | goes up and down | `connections_active` | queue depth, temperature |
| **Histogram** | latency buckets | `request_duration_seconds_bucket` | p50/p95/p99 |
| **Summary** | quantiles on the client | `request_duration_seconds{quantile="0.99"}` | rare (cannot be aggregated) |

| Naming rule | Correct | Wrong |
| :--- | :--- | :--- |
| Base unit | `_seconds`, `_bytes`, `_celsius` | `_ms`, `_kb`, `_millis` |
| Counter suffix `_total` | `http_requests_total` | `http_request_count` |
| Label key names the object | `service`, `method`, `status` | `myAppName`, `path` |
| Label value lowercase & stable | `status="200"`, `method="GET"` | `status="OK Success"`, `method="get"` |

```java
// Micrometer: counter + timer
private final Counter requests = Counter.builder("http.server.requests")
        .description("Total HTTP requests").register();

private final Timer latency = Timer.builder("http.server.request.duration")
        .publishPercentileHistogram()      // REQUIRED so histogram_quantile works
        .register();

public void record(String status, long ms) {
    requests.tag("status", status).increment();
    latency.record(ms, TimeUnit.MILLISECONDS);
}
```

> **Pitfall:** a Micrometer timer **without** `publishPercentileHistogram()` only produces
> a summary (quantile), not buckets → `histogram_quantile()` in PromQL **cannot** be used.

## Labels & cardinality budget

```promql
# number of active series for one metric
count({__name__="http_server_requests_total"})

# series with the most labels
topk(10, count by (__name__) ({__name__=~".+"}))

# which labels appear on one metric
count by (label) ({__name__="http_server_requests_total"})
```

**Budget calculation:**

```text
number of series = number of label value combinations
example: service(10) × method(5) × status(8) × path_template(30) = 12,000 series
```

| Rule | Why |
| :--- | :--- |
| **DO NOT** use `user_id`, `order_id`, `email` | unbounded cardinality → OOM |
| **Template** path | `path="/api/orders/{id}"`, not `path="/api/orders/8821"` |
| Time **must not** be a label | use a timestamp, not a label |
| **Low-cardinality** label value | `status="500"`, not `status="Internal Server Error on /x"` |
| Reasonable limit | ~10,000 series per metric is still safe; > 100,000 needs review |
| Drop `labels` on aggregation | `sum by (service) (...)` discards other labels |

```promql
# reduce before querying: drop high-cardinality labels
sum by (service, status) (rate(http_server_requests_total[5m]))
```

> **Pitfall:** `topk(10, count by (__name__)({__name__=~".+"}))` is the first query
> you should run when Prometheus starts to slow down. Almost always the answer:
> one metric with unnecessary labels.

## PromQL: basics

```promql
# selector + matching
http_server_requests_total
http_server_requests_total{job="order-service"}
http_server_requests_total{job=~"order-.*|payment-.*"}    # regex
http_server_requests_total{job!="batch-worker"}              # negation
http_server_requests_total{status=~"5.."}                     # 500-599
http_server_requests_total{instance=~"10\\..*"}               # regex needs escaping

# range & offset
rate(http_server_requests_total[5m])
http_server_requests_total offset 1h          # value from 1 hour ago
rate(http_server_requests_total[5m] offset 1d)

# time modifier (experimental)
http_server_requests_total @ 1729622400
rate(http_server_requests_total[5m] @ start())

# subquery
max_over_time(rate(http_server_requests_total[1m])[30m:1m])
```

| Function | Meaning |
| :--- | :--- |
| `rate(v[5m])` | per **second** across the window (for counters) |
| `irate(v[5m])` | **instant** per second (jumpy graph, don't use for alerts) |
| `increase(v[1h])` | total increase over the window |
| `delta(v[1h])` | difference for gauges |
| `changes(v[1h])` | how many times the value changed |
| `idelta(v[1h])` | instant delta |
| `absent(v)` | 1 if the series **is absent** (for alerts) |
| `absent_over_time(v[1h])` | 1 if there is no sample within 1 hour |
| `histogram_quantile(0.95, ...)` | quantile from buckets |
| `clamp_max(v, 100)` / `clamp_min(v, 0)` | bound the value |
| `scalar(v)` | turn a 1-series into a number |
| `vector(1)` | 1-series vector |

> **Pitfall:** `rate()` needs **at least 2 samples** in the window. With a `scrape_interval`
> of 30s, a `[1m]` window only gets 2–3 samples → frequently `NaN` on scrape hiccups. Rule:
> **window ≥ 4× scrape_interval**.

## PromQL: aggregations & functions

```promql
# aggregation
sum(http_server_requests_total)
sum by (service) (http_server_requests_total)
sum without (instance, pod) (http_server_requests_total)
count(http_server_requests_total)          # number of series
count_values("version", build_info)      # number of series per label value
avg by (service) (http_server_request_duration_seconds_sum)
max by (service) (node_memory_MemAvailable_bytes)

# top-k & bottom-k
topk(5, sum by (path) (rate(http_server_requests_total[5m])))
bottomk(5, sum by (pod) (rate(container_cpu_usage_seconds_total[5m])))

# ratio
sum(rate(http_server_requests_total{status=~"5.."}[5m]))
  / sum(rate(http_server_requests_total[5m]))

# redistribute percentiles from a histogram
histogram_quantile(0.50, sum by (le) (rate(http_server_request_duration_seconds_bucket[5m])))
histogram_quantile(0.95, sum by (le, service) (rate(http_server_request_duration_seconds_bucket[5m])))
histogram_quantile(0.99, sum by (le) (rate(http_server_request_duration_seconds_bucket{cluster="pos"}[10m])))

# quantiles from a summary (per-series only, cannot be aggregated)
histogram_quantile(0.95, sum by (le) (rate(http_server_request_duration_seconds{quantile="0.95"}[5m])))
```

| Window function | Meaning |
| :--- | :--- |
| `rate/irate/increase/delta` | counter/gauge kinematics |
| `avg_over_time`, `max_over_time`, `min_over_time`, `sum_over_time` | aggregate values over the window |
| `stddev_over_time`, `stdvar_over_time` | variation |
| `quantile_over_time(0.99, v[5m])` | quantile of sample values (not histogram) |
| `last_over_time(v[5m])` | last value |
| `present_over_time(v[5m])` | 1 if a sample exists |

> **Pitfall:** `quantile_over_time()` aggregates **raw samples** — its value is inaccurate
> for data that is already bucketed. For a correct p99 latency, use
> `histogram_quantile()` over buckets.

## PromQL: operators & vector matching

```promql
# operators between instant vectors
http_server_requests_total{status="500"} / http_server_requests_total{status="200"}

# explicit vector matching (on / ignoring)
node_filesystem_avail_bytes / node_filesystem_size_bytes
node_filesystem_avail_bytes / on(instance) node_filesystem_size_bytes
sum by (instance) (node_memory_MemAvailable_bytes) / on(instance) group_left
  sum by (instance) (node_memory_MemTotal_bytes)

# comparison with a threshold
up == 0
process_resident_memory_bytes > 1e9
histogram_quantile(0.99, ...) > 0.5

# set operator
up{job="a"} or up{job="b"}
up unless on(instance) up{job="b"}
```

| Modifier | Meaning |
| :--- | :--- |
| `on(label)` | match only on that label |
| `ignoring(label)` | match on everything except that label |
| `group_left` / `group_right` | the side that may have **more** labels |
| `bool` modifier | the comparison yields 0/1 instead of keeping the value |

> **Pitfall:** `group_left` without `on()`/`ignoring()` = error. And `or` is **not** a union —
> matching labels make the right-hand series **not** used (like a `left join`).

## Recording & alerting rules

```yaml
# prometheus/rules/recording.yml
groups:
  - name: order-service
    interval: 30s
    rules:
      - record: order:http_requests:rate5m
        expr: sum by (service, status) (rate(http_server_requests_total{job="order-service"}[5m]))

      - record: order:request_duration_seconds:p95_5m
        expr: histogram_quantile(0.95,
          sum by (le) (rate(http_server_request_duration_seconds_bucket{job="order-service"}[5m])))

      - record: order:error_ratio:rate5m
        expr: |
          sum(rate(http_server_requests_total{job="order-service",status=~"5.."}[5m]))
            / sum(rate(http_server_requests_total{job="order-service"}[5m]))
```

```yaml
# prometheus/rules/alerting.yml
groups:
  - name: backend-slo
    interval: 30s
    rules:
      - alert: OrderServiceHighErrorRate
        expr: order:error_ratio:rate5m > 0.05
        for: 5m
        keep_firing_for: 5m
        labels:
          severity: critical
          service: order-service
          team: backend
        annotations:
          summary: "order-service error ratio > 5% for 5 minutes"
          description: "Current error ratio: {{ $value | humanizePercentage }}"
          runbook_url: "https://github.com/sanedge/pos-k8s/blob/main/docs/runbook/alert-runbook.md"

      - alert: ConsumerLagHigh
        expr: sum(kafka_consumergroup_lag{consumergroup="payment-bridge"}) > 1000
        for: 10m
        labels: { severity: warning, service: payment-bridge }
        annotations:
          summary: "Kafka lag payment-bridge > 1000"
```

| Rule | Why |
| :--- | :--- |
| Recording rules for expensive queries | saves CPU & keeps queries consistent |
| `for:` + `keep_firing_for:` | anti-flapping + time to recover |
| `severity` + `service` + `team` | Alertmanager routing & ownership |
| `summary` + `description` (using `{{ $value }}`) | on-call knows the actual number |
| `runbook_url` | there is an action at 3 AM |

```bash
# test rules before deploying
promtool check rules prometheus/rules/*.yml
promtool test rules tests/rules_test.yml      # unit test for rules
promtool query instant http://localhost:9090 'up == 0'
```

## Server configuration

```yaml
# prometheus.yml
global:
  scrape_interval: 30s
  scrape_timeout: 10s            # MUST be < scrape_interval
  evaluation_interval: 30s
  external_labels:
    cluster: pos
    env: prod

rule_files:
  - /etc/prometheus/rules/*.yml

scrape_configs:
  - job_name: order-service
    metrics_path: /actuator/prometheus
    static_configs:
      - targets: ["order-service.pos.svc.cluster.local:8083"]
        labels:
          service: order-service
          team: backend

  - job_name: kubernetes-pods
    kubernetes_sd_configs:
      - role: pod
    relabel_configs:
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: "true"
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_path]
        action: replace
        target_label: __metrics_path__
        regex: (.+)
      - source_labels: [__address__, __meta_kubernetes_pod_annotation_prometheus_io_port]
        action: replace
        regex: ([^:]+)(?::\d+)?;(\d+)
        replacement: $1:$2
        target_label: __address__
      - action: labelmap
        regex: __meta_kubernetes_pod_label_(.+)
      - source_labels: [__meta_kubernetes_namespace]
        action: replace
        target_label: kubernetes_namespace
      - source_labels: [__meta_kubernetes_pod_name]
        action: replace
        target_label: kubernetes_pod_name
```

```bash
# important server flags
prometheus \
  --config.file=/etc/prometheus/prometheus.yml \
  --storage.tsdb.path=/prometheus \
  --storage.tsdb.retention.time=30d \
  --storage.tsdb.retention.size=80GB \
  --storage.tsdb.wal-compression \
  --storage.tsdb.max-block-duration=2h \
  --web.enable-lifecycle \
  --web.enable-admin-api \
  --log.level=info
```

| Flag | Meaning |
| :--- | :--- |
| `--storage.tsdb.retention.time` | default **15d** |
| `--storage.tsdb.retention.size` | disk limit (overrides the time one) |
| `--storage.tsdb.max-block-duration` | 2h default; trade-off between query and compression |
| `--storage.tsdb.wal-compression` | saves WAL I/O |
| `--web.enable-lifecycle` | allows `POST /-/reload` when config changes |
| `--web.enable-admin-api` | delete series (dangerous) |
| `--enable-feature=agent` | agent mode (remote write only, no local querying) |
| `--enable-feature=native-histograms` | native histograms |
| `--enable-feature=exemplar-storage` | store exemplars |

```bash
# reload config without restarting
curl -X POST http://localhost:9090/-/reload
```

> **Pitfall:** restarting Prometheus = a **1–2 minute gap** in data (TSDB is closed, series go
> stale). Use `--web.enable-lifecycle` + `/-/reload` for config changes.

## Service discovery

| SD | For |
| :--- | :--- |
| `static_configs` | static targets (VM, docker compose) |
| `file_sd_configs` | generated YAML files (Prometheus Operator, VMSS) |
| `kubernetes_sd_configs` | pod/service/endpoint (role: pod, service, endpoints, node) |
| `consul_sd_configs` | Consul |
| `docker_sd_configs` | Docker Swarm |
| `ec2_sd_configs`, `gce_sd_configs`, `openstack_sd_configs` | cloud |

```yaml
  - job_name: kubernetes-services
    kubernetes_sd_configs:
      - role: endpointslice
    relabel_configs:
      - source_labels: [__meta_kubernetes_service_annotation_prometheus_io_scrape]
        action: keep
        regex: "true"
      - source_labels: [__meta_kubernetes_namespace]
        target_label: namespace
      - source_labels: [__meta_kubernetes_service_name]
        target_label: job
      - source_labels: [__meta_kubernetes_endpoint_slice_port_name]
        target_label: __address__
        regex: (.+)(?::\d+)?;(\d+)
        replacement: $1:$2
```

> **Pitfall:** using `role: service` → Prometheus scrapes the **ClusterIP**, which changes
> when pods restart. Use `role: pod` (with `__address__` from annotations) or
> `role: endpointslice`.

## Relabeling

```yaml
    relabel_configs:
      # 1. filter targets
      - source_labels: [__meta_kubernetes_pod_phase]
        action: keep
        regex: Running

      # 2. replace a label
      - source_labels: [__meta_kubernetes_pod_label_app]
        target_label: service

      # 3. create a new label (replacing a missing label = create)
      - target_label: env
        replacement: prod

      # 4. drop unused built-in labels
      - action: labeldrop
        regex: __meta_kubernetes_pod_label_(.+)

      # 5. join several labels into one
      - source_labels: [__meta_kubernetes_namespace, __meta_kubernetes_pod_name]
        separator: /
        target_label: pod_path
        replacement: $1
```

| Action | When |
| :--- | :--- |
| `keep` / `drop` | filter targets (must come **first**) |
| `replace` | change/create a label |
| `labelmap` | copy all labels with a given prefix |
| `labeldrop` | drop a set of labels |
| `lowercase` / `uppercase` | normalize |
| `hashmod` | sharding for HA |

> **Pitfall:** the order of `relabel_configs` matters — `keep` must come before `replace`, otherwise
> the filter matches on labels that do not exist yet.

## Remote write, federation, advanced TSDB

```yaml
# remote write to Mimir/Thanos
remote_write:
  - url: https://mimir.example.com/api/v1/push
    name: mimir
    remote_timeout: 30s
    queue_config:
      capacity: 10000
      max_shards: 10
      min_shards: 1
    metadata_config:
      send: true
      send_interval: 1m
```

```yaml
# federation: pull from another Prometheus
scrape_configs:
  - job_name: federation
    honor_labels: true
    metrics_path: /federate
    params:
      match[]: ["{job=~'order-.*'}"]
    static_configs:
      - targets: ["prometheus-2.pos:9090"]
```

| Strategy | When |
| :--- | :--- |
| Remote write | long-term storage, HA multi-region |
| Federation | hierarchy: cluster → regional → global |
| Thanos sidecar | object storage + deduplication, cost-effective |
| Mimir | multi-tenant, scalable, long-term |
| VictoriaMetrics | drop-in, high compression, simple |
| Exemplar storage | links a metric → trace |

## Native histograms & exemplars

```promql
# native histogram: WITHOUT a "le" label
histogram_quantile(0.99, sum by (service) (rate(http_server_request_duration_seconds[5m])))

# classic histogram: with a "le" label
histogram_quantile(0.99, sum by (le, service) (rate(http_server_request_duration_seconds_bucket[5m])))
```

```yaml
scrape_configs:
  - job_name: order-service
    scrape_protocols: [OpenMetricsText1.0.0, PrometheusText1.0.0]   # exemplars need OpenMetrics
```

| Concept | Meaning |
| :--- | :--- |
| Classic histogram | fixed buckets, `le` label per bucket (many series) |
| Native histogram | dynamic buckets, **without** an `le` label (more efficient) |
| Exemplar | `trace_id` label on some samples → link to trace |
| `scrape_protocols` | use OpenMetricsText1.0.0 to get exemplars |

> **Pitfall:** exemplars are **only** sent if the scrape uses the OpenMetrics protocol.
> If it's still `PrometheusText1.0.0`, exemplars never arrive.

## SLO & burn rate

```
Availability SLO : 99.9%  → error budget 0.1% per 30 days
Latency SLO      : p95 < 500ms for 99% of requests
```

```yaml
# multi-window burn rate (short + long), from Google SRE
- alert: OrderServiceErrorBudgetBurn
  expr: |
    (
      sum(rate(http_server_requests_total{job="order-service",status=~"5.."}[1h]))
      / sum(rate(http_server_requests_total{job="order-service"}[1h]))
      > (14.4 * 0.001)
    )
    and
    (
      sum(rate(http_server_requests_total{job="order-service",status=~"5.."}[5m]))
      / sum(rate(http_server_requests_total{job="order-service"}[5m]))
      > (14.4 * 0.001)
    )
  for: 2m
  labels: { severity: critical }
  annotations:
    summary: "Burn rate 14.4x — error budget exhausted in ~2 days"
```

| Burn rate | Error budget exhausted in | Response |
| :--- | :--- | :--- |
| 1× | 30 days | ticket |
| 3× | 10 days | observe |
| 6× | 5 days | priority ticket |
| 14.4× | ~2 days | **page** |
| 36× | ~20 hours | **page**, major investigation |

```bash
# status & hit ratio
curl -s http://localhost:9090/api/v1/status/tsdb | jq '{
  headStats: .headStats,

}'

curl -s 'http://localhost:9090/api/v1/label/__name__/values' | jq '.data | length'

# series per metric via TSDB status
curl -s http://localhost:9090/api/v1/status/tsdb | jq '.headStats.seriesCountByMetricName' | head -20

# label values with the most entries
curl -s 'http://localhost:9090/api/v1/label/instance/values' | jq '.data | length'
```

```promql
# find metrics that produce many series
topk(10, count by (__name__) ({__name__=~".+"}))

# find labels with the most values
count by (path) (http_server_requests_total)
```

| Symptom | Check | Solution |
| :--- | :--- | :--- |
| Slow queries | `count by (__name__)` | record rules, drop labels |
| Prometheus OOM | TSDB status | reduce cardinality, lower retention |
| Gaps in series | `up == 0` | target down / scrape timeout |
| Duplicate samples | `scrape_interval` < `scrape_timeout` | make them equal |
| Frequent restarts | `--storage.tsdb.max-block-duration` | don't set it too small |

## Troubleshooting

```bash
# target status
curl -s 'http://localhost:9090/api/v1/targets?state=active' | jq '.data.activeTargets[] | {job: .labels.job, health, lastError, lastScrape}'

# manual scrape
curl -s http://order-service:8083/actuator/prometheus | head -20

# reload config
curl -X POST http://localhost:9090/-/reload

# rule status
curl -s http://localhost:9090/api/v1/rules | jq '.data.groups[].rules[] | {name, health, lastError}'

# log
docker logs prometheus | grep -i "error\|scrape"
```

| Symptom | Common cause | Fix |
| :--- | :--- | --- |
| `up == 0` | wrong path, pod not ready, NetworkPolicy | check `lastError` in `/api/v1/targets` |
| Metrics don't show up | endpoint is not `/metrics` | set `metrics_path` |
| Scrape timeout | slow target | raise `scrape_timeout`, fix the app |
| Series stops | app restart | `rate()` will smoothly go to 0 |
| `NaN` in rate | window < 2 samples | enlarge the window |
| Labels keep changing | target uses pod IP | use `role: pod` + annotation |

## Pitfalls (must read)

| Pitfall | Symptom | Solution |
| :--- | :--- | :--- |
| `user_id` / `order_id` labels | OOM, slow queries | logs & traces for detail |
| Raw path as a label | Cardinality explodes | Template path `{id}` |
| `rate()` window < 2× scrape | `NaN` / gaps in data | window ≥ 4× scrape interval |
| `scrape_timeout` > `scrape_interval` | Target always `down` | timeout < interval |
| `irate()` for alerts | Jumpy numbers, flapping | Use `rate()` |
| `quantile_over_time` for p99 | Inaccurate value | `histogram_quantile()` over buckets |
| `summary` for latency | Cannot aggregate across instances | Use a histogram |
| `or` mistaken for union | Right-hand series dropped | `or` = left-join |
| `group_left` without `on()` | Error | Specify `on`/`ignoring` |
| Exemplars don't show up | Scrape protocol isn't OpenMetrics | `scrape_protocols: [OpenMetricsText1.0.0]` |
| Restarting Prometheus | 1–2 minute data gap | Use `/-/reload` |
| `sum by` without key labels | Too many series | Add aggregation labels |
| Alert without `for:` | Flapping on deploy | `for:` + `keep_firing_for:` |
| Pushgateway for services | Metrics pile up | Pushgateway only for batch jobs |
| Remote write without retry | Data lost when backend is down | Set `queue_config` & retry |
