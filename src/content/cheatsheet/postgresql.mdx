## CLI & diagnostics

```sql
-- status server
SELECT version();
SELECT current_database(), current_user, now();

-- slow queries: enable duration logging (session)
SET log_min_duration_statement = 200;      -- log queries > 200ms
SET log_min_duration_statement = -1;        -- turn it off again

-- per-statement statistics
SELECT calls, mean_exec_time, total_exec_time, query
FROM pg_stat_statements
ORDER BY total_exec_time DESC LIMIT 10;

-- statements with the most scans
SELECT schemaname, relname, seq_scan, idx_scan,
       seq_scan::float / NULLIF(seq_scan + idx_scan, 0) AS seq_ratio
FROM pg_stat_user_tables
ORDER BY seq_scan DESC LIMIT 10;

-- cache hit ratio
SELECT sum(heap_blks_hit) / NULLIF(sum(heap_blks_hit + heap_blks_read), 0) AS hit_ratio
FROM pg_statio_user_tables;

-- waiting locks
SELECT pid, locktype, relation::regclass, mode, granted,
       pg_blocking_pids(pid) AS blocked_by
FROM pg_locks WHERE NOT granted;

-- active sessions
SELECT pid, usename, state, wait_event_type, wait_event,
       now() - xact_start AS xact_age, left(query, 100) AS query
FROM pg_stat_activity
WHERE state <> 'idle' ORDER BY xact_start;
```

```bash
# sizes
psql -c "SELECT relname, pg_size_pretty(pg_total_relation_size(relid))
         FROM pg_catalog.pg_statio_user_tables ORDER BY pg_total_relation_size(relid) DESC LIMIT 10;"

# manual vacuum & analyze
psql -c "VACUUM (VERBOSE, ANALYZE) orders;"
psql -c "REINDEX INDEX CONCURRENTLY idx_orders_merchant_status;"

# dump & restore
pg_dump -Fc -d pos_sales -f pos_sales.dump
pg_restore -d pos_sales_restore --jobs=4 pos_sales.dump

# explain analyze
psql -c "EXPLAIN (ANALYZE, BUFFERS, VERBOSE) SELECT ...;"
```

## Data types

| Type | Use for | Notes |
| :--- | :--- | :--- |
| `bigint` / `integer` | ids, counters | `bigserial`/`GENERATED ... AS IDENTITY` |
| `numeric(p,s)` | money, precise numbers | **no need** for float for money |
| `double precision` | FLOAT | rounding is not guaranteed |
| `real` | FLOAT | 7 digits of precision, not for money |
| `money` | legacy | locale-dependent; **don't** use it |
| `text` | strings | `varchar(n)` == `text` + CHECK |
| `varchar(n)` | bounded string | `n` is never truncated automatically |
| `char(n)` | fixed codes | space padding — avoid |
| `bytea` | binary | hex or base64 |
| `boolean` | flags | `t/f/true/false/yes/no/1/0` |
| `date` | date without time | |
| `timestamp` | no time zone | **don't** use for absolute moments |
| `timestamptz` | absolute moment | stored as UTC, displayed per `TimeZone` |
| `interval` | durations | `interval '1 day 3 hours'` |
| `uuid` | external ids | `gen_random_uuid()` (built in since PG13) |
| `json` | raw JSON | text, **not** indexed | 
| `jsonb` | structured JSON | binary, indexable, unique keys |
| `xml` | XML | needs the `xml` extension for operators |
| `inet` / `cidr` | IP addresses | `inet '10.0.0.0/8'` |
| `macaddr` | MAC address | |
| `bit(n)` / `bit varying(n)` | fixed bits | rarely used |
| `tsvector` / `tsquery` | full-text search | create a generated column |
| `int4range`, `tstzrange` | ranges | multirange in PG14+ |
| `ARRAY` | 1-dimensional arrays | multidimensional (arrays) are slow |
| `enum` | closed status sets | adding a value = `ALTER TYPE ... ADD VALUE` (not inside a transaction before PG12) |
| `composite` | anonymous record | for functions |
| `domain` | typedef + constraint | like CHECK but reusable |

**Rules of thumb:**

| Situation | Choice |
| :--- | :--- |
| Money | `numeric(18,2)` |
| Event timestamp | `timestamptz` |
| Status | `text` + CHECK, or `enum` |
| Flexible config | `jsonb` + GIN index |
| Arrays | sparingly; if > 20 elements → child table |
| UUID | `uuid` v4 (random) or v7 (time-ordered) |

```sql
-- generated column: computed automatically, always consistent
ALTER TABLE orders
  ADD COLUMN total_with_tax numeric(18,2)
  GENERATED ALWAYS AS (total * 1.11) STORED;   -- STORED = computed on write

-- generated from jsonb
ALTER TABLE products
  ADD COLUMN brand text
  GENERATED ALWAYS AS (attributes ->> 'brand') STORED;

-- identity column (replaces serial, more modern)
CREATE TABLE orders (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  order_no text NOT NULL
);
-- GENERATED BY DEFAULT = allows inserting manual values (useful for restore/migration)
```

> **Pitfall:** `numeric` without a precision (`numeric`) can store different scales across rows
> (e.g. `1.5` and `1.50`) — `=` is still true but `ORDER BY` and unique indexes can behave
> unexpectedly. Always write the precision explicitly.

## DDL, constraints, naming

```sql
CREATE TABLE orders (
  id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  order_no      text        NOT NULL,
  merchant_id   bigint      NOT NULL REFERENCES merchants (id) ON DELETE RESTRICT,
  customer_id   bigint           NULL REFERENCES customers (id) ON DELETE SET NULL,
  status        text        NOT NULL DEFAULT 'PENDING',
  total         numeric(18,2) NOT NULL DEFAULT 0,
  notes         text,
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now(),

  CONSTRAINT orders_total_non_negative CHECK (total >= 0),
  CONSTRAINT orders_status_valid CHECK (status IN ('PENDING','PAID','FAILED','CANCELLED')),
  CONSTRAINT orders_total_upper CHECK (total <= 1000000000000)
);

-- unique
CREATE UNIQUE INDEX orders_order_no_key ON orders (order_no);

-- deferrable FK (for insert order)
ALTER TABLE orders ADD CONSTRAINT orders_merchant_fk
  FOREIGN KEY (merchant_id) REFERENCES merchants (id)
  DEFERRABLE INITIALLY DEFERRED;

-- exclude constraint: prevent overlapping ranges
ALTER TABLE reservations
  ADD CONSTRAINT no_overlap
  EXCLUDE USING gist (room_id WITH =, during WITH &&);

-- trigger: automatic updated_at
CREATE OR REPLACE FUNCTION set_updated_at() RETURNS trigger AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER orders_set_updated_at
  BEFORE UPDATE ON orders
  FOR EACH ROW EXECUTE FUNCTION set_updated_at();
```

| Constraint | Purpose | Notes |
| :--- | :--- | :--- |
| `NOT NULL` | must be present | enforced |
| `CHECK` | value rules | enforced (also checked during `COPY`) |
| `UNIQUE` | no duplicates | enforced |
| `PRIMARY KEY` | identity + index | enforced |
| `FOREIGN KEY` | referential integrity | enforced |
| `EXCLUDE` | no overlap (ranges) | enforced |

**Naming conventions** (consistent = easier debugging):

| Object | Pattern | Example |
| :--- | :--- | :--- |
| Table | plural, snake_case | `order_items` |
| PK column | `id` | `orders.id` |
| FK | `<table>_id` | `merchant_id` |
| Index | `idx_<table>_<column>` | `idx_orders_merchant_status` |
| Unique | `uq_<table>_<column>` | `uq_orders_order_no` |
| Check | `ck_<table>_<rule>` | `ck_orders_total_non_negative` |
| FK | `fk_<table>_<reference>` | `fk_orders_merchant` |
| Trigger | `trg_<table>_<action>` | `trg_orders_set_updated_at` |

> **Pitfall:** `ON DELETE CASCADE` on a large table = deleting millions of rows in a single
> statement → long locks & bloated WAL. Use `ON DELETE SET NULL` + soft delete if
> the data needs to be kept.

## Index

```sql
-- B-tree: default. equality, range, ORDER BY
CREATE INDEX idx_orders_merchant_created ON orders (merchant_id, created_at DESC);

-- Unique
CREATE UNIQUE INDEX uq_orders_order_no ON orders (order_no);

-- Partial: only a subset of rows (most efficient for non-terminal statuses)
CREATE INDEX idx_orders_pending ON orders (created_at)
  WHERE status = 'PENDING';

-- Covering (INCLUDE): index-only scan
CREATE INDEX idx_orders_cover ON orders (merchant_id, created_at DESC)
  INCLUDE (status, total);

-- Expression: index on an expression result
CREATE INDEX idx_orders_lower_order_no ON orders (lower(order_no));

-- Hash: equality only
CREATE INDEX idx_users_token_hash ON users USING hash (token);

-- BRIN: for naturally ordered data (time series, logs) — very small
CREATE INDEX idx_logs_created_brin ON logs USING brin (created_at) WITH (pages_per_range = 64);

-- GIN: arrays, jsonb, full text
CREATE INDEX idx_products_attrs ON products USING gin (attributes);
CREATE INDEX idx_products_name_trgm ON products USING gin (name gin_trgm_ops);

-- GiST: range types, geometry, full text
CREATE INDEX idx_reservations_during ON reservations USING gist (during);

-- SP-GiST: prefixes, nearest neighbor
CREATE INDEX idx_docs_trie ON documents USING spgist (body);

-- partial index with sorting support
CREATE INDEX idx_orders_merchant_partial ON orders (merchant_id, created_at DESC)
  WHERE deleted_at IS NULL;

-- custom opclass
CREATE INDEX idx_orders_status ON orders (status COLLATE "C");
```

| Type | Best for | Size | Notes |
| :--- | :--- | :--- | :--- |
| B-tree | `=`, `>`, `<`, `ORDER BY` | large | 1 index = 1 column (composite columns) |
| Hash | `=` only | small | cannot sort |
| BRIN | ranges on ordered data | **very small** | for logs/time-series |
| GIN | arrays, jsonb, full-text | large | slow to build |
| GiST | ranges, geometry, FTS | large | lossy, needs recheck |
| SP-GiST | prefixes, nearest | medium | long text |

**Index rules that are often broken:**

| Rule | Why |
| :--- | :--- |
| Composite columns: **order = query order** | `INDEX (a,b)` does not serve `WHERE b=?` |
| Index every `WHERE` and `ORDER BY` | the planner needs it |
| Partial index when the subset is small | saves writes & disk |
| Don't index columns with few distinct values | `status` with 4 values → index is short |
| Don't index both (prefix) | `idx(a)` already serves `WHERE a=?` |
| `CREATE INDEX CONCURRENTLY` in production | no write lock, but slower & can fail → invalid |

```sql
-- unused indexes (idx_scan = 0)
SELECT s.relname AS table_name, s.indexrelname AS index_name, s.idx_scan
FROM pg_stat_user_indexes s
WHERE s.idx_scan = 0 AND s.indexrelname NOT LIKE '%_pkey';

-- invalid indexes (CONCURRENTLY build failed)
SELECT n.nspname, c.relname FROM pg_index i
JOIN pg_class c ON c.oid = i.indexrelid
JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE NOT i.indisvalid;
```

> **Pitfall:** `CREATE INDEX` (not CONCURRENTLY) locks the table for **writes** during the build.
> On a large table that can take minutes. In production: `CREATE INDEX CONCURRENTLY`.
> If it fails, the index becomes `invalid` — drop it and retry.

## EXPLAIN & reading plans

```sql
EXPLAIN (ANALYZE, BUFFERS, VERBOSE, SETTINGS) SELECT ...;
EXPLAIN (COSTS OFF) SELECT ...;      -- plan only, no execution
```

| Plan line | Meaning | Action |
| :--- | :--- | :--- |
| `Seq Scan` | full table scan | Normal on small tables (< 10k rows). On large tables → needs an index |
| `Index Scan` | read index then row | Good |
| `Index Only Scan` | read index only | **Best** — needs a covering index |
| `Bitmap Index Scan` | index → bitmap → heap | Good for low selectivity |
| `Bitmap Heap Scan` | random heap pages | Pairs with the above |
| `Nested Loop` | loop per outer row | Good when the inner side is small; **expensive** when the outer side is large |
| `Hash Join` | build a hash table | Good for large joins |
| `Merge Join` | merge two sorted streams | Both sides must be sorted |
| `Sort Method: external merge` | sort spilled to disk | Increase `work_mem` or use an index |
| `rows=1` but actual 50000 | Stale statistics | `ANALYZE` |
| `Buffers: shared hit=0 read=900` | Lots of reads from disk | Add an index / enlarge the cache |
| `Heap Blocks: exact=… lossy=…` | Lossy bitmap (approximate) | `work_mem` too small |
| `Planning Time` >> `Execution Time` | Query is "planning-heavy" (many variants) | Simplify the query, reduce parameters |
| `JIT` | Just-in-time compilation | Can be slower for short queries |

```sql
-- logical reads reset: EXPLAIN (ANALYZE) SELECT pg_stat_reset_single_table_counters('pg_stat_user_tables');
-- lock contention
SELECT pid, wait_event_type, wait_event, state, query FROM pg_stat_activity WHERE wait_event IS NOT NULL;
```

> **Pitfall:** `EXPLAIN ANALYZE` **executes** the statement. For `UPDATE`/`DELETE`, wrap it
> in `BEGIN; ... ROLLBACK;`.

## Query optimization

```sql
-- keyset pagination (MUCH better than OFFSET)
SELECT id, order_no, total FROM orders
WHERE (created_at, id) < ($1, $2)
ORDER BY created_at DESC, id DESC
LIMIT 20;

-- EXISTS is better than IN for large subqueries
SELECT id FROM orders o
WHERE EXISTS (SELECT 1 FROM order_items i WHERE i.order_id = o.id);

-- NOT IN + NULL = empty results (classic pitfall!)
-- ❌ SELECT id FROM t WHERE id NOT IN (SELECT id FROM u WHERE flag = false)
-- ✅ use NOT EXISTS
SELECT id FROM orders o
WHERE NOT EXISTS (SELECT 1 FROM deleted_items d WHERE d.order_id = o.id);

-- rewrite OR as UNION ALL (the planner is often better)
SELECT ... WHERE status = 'PAID'
UNION ALL
SELECT ... WHERE status = 'PENDING';

-- lateral join — per-row correlation
SELECT o.id, p.name
FROM orders o
CROSS JOIN LATERAL (
  SELECT p.name FROM order_items i JOIN products p ON p.id = i.product_id
  WHERE i.order_id = o.id LIMIT 3
) p;

-- the earliest possible filter in the pipeline
SELECT ... FROM orders o
JOIN merchants m ON m.id = o.merchant_id
WHERE o.created_at > now() - interval '7 days'   -- filter first, then join

-- filtered count: use a filter, not a subquery
SELECT count(*) FROM orders WHERE status = 'PAID';
-- ❌ SELECT count(*) FROM orders WHERE id IN (SELECT order_id FROM paid);
```

| Problem | Solution |
| :--- | :--- |
| `OFFSET 100000` | keyset pagination |
| `LIKE '%foo%'` | `pg_trgm` + GIN |
| `NOT IN` with a nullable subquery | `NOT EXISTS` |
| Filtering after the join | filter at the earliest stage |
| `count(*)` on a large table | approximate / counter table |
| Function on an indexed column | index expression (`lower(x)`) |
| `OR` across different columns | `UNION ALL` |
| Parametric query with many variants | `PREPARE` / plan cache |
| Stale statistics | `ANALYZE` + a higher `default_statistics_target` |

```sql
-- raise the statistics target for columns that often misbehave
ALTER TABLE orders ALTER COLUMN status SET STATISTICS 500;
ANALYZE orders;

-- plan cache per prepared statement
PREPARE q (bigint, text) AS SELECT ... ;
EXPLAIN (ANALYZE) EXECUTE q(1, 'PAID');
```

## Extended statistics

```sql
-- cross-column statistics: high correlation
CREATE STATISTICS stat_orders_merchant_status (dependencies, ndistinct)
  ON merchant_id, status FROM orders;

-- MCV: most common values
CREATE STATISTICS stat_orders_merchant_status_mcv (mcv)
  ON merchant_id, status FROM orders;

ANALYZE orders;

-- check
SELECT * FROM pg_stats_ext WHERE statistics_name = 'stat_orders_merchant_status';
```

| Type | Helps with |
| :--- | :--- |
| `ndistinct` | estimating the combined distinct count (multi-column) |
| `dependencies` | cross-column correlation (the planner becomes smarter) |
| `mcv` | list of the most frequent values — default 100 |

> A wrong plan is often not due to a missing index, but because **the statistics don't know**
> that the two columns are correlated. `CREATE STATISTICS` is far cheaper than
> creating an index.

## Locking & isolation

| Isolation level | Prevents | Can still happen |
| :--- | :--- | :--- |
| `READ UNCOMMITTED` | — | practically the same as RC in PostgreSQL |
| `READ COMMITTED` (default) | dirty read | non-repeatable read, phantom |
| `REPEATABLE READ` | dirty + non-repeatable | phantom (serialization error on write) |
| `SERIALIZABLE` | everything | needs retry on `40001` |

```sql
-- row lock for update
SELECT * FROM accounts WHERE id = 1 FOR UPDATE;

-- skip already-locked rows (worker queue!)
UPDATE jobs SET status = 'RUNNING'
WHERE id IN (SELECT id FROM jobs WHERE status = 'QUEUED' ORDER BY created_at LIMIT 10 FOR UPDATE SKIP LOCKED)
RETURNING *;

-- advisory lock: mutex across tables / instances
SELECT pg_advisory_xact_lock(4711);    -- released automatically on COMMIT
SELECT pg_try_advisory_lock(4711);     -- bool, does not wait

-- lock timeout so it doesn't hang
SET lock_timeout = '3s';
SET statement_timeout = '30s';
```

| Lock | Blocks | Deadlock solution |
| :--- | :--- | :--- |
| `RowExclusiveLock` (INSERT/UPDATE/DELETE) | other writes on the same row | Consistent update order |
| `ShareUpdateExclusiveLock` (VACUUM, light DDL) | UPDATE, DELETE, VACUUM | Schedule it |
| `AccessExclusiveLock` (ALTER/DROP/TRUNCATE) | **everything** | Do it outside peak hours |
| `ShareLock` (CREATE INDEX CONCURRENTLY) | writes | schedule it |
| `AccessShareLock` (SELECT) | DDL | Avoid DDL during traffic |

```sql
-- detect & resolve deadlocks
SELECT pid, locktype, relation::regclass, mode, granted FROM pg_locks WHERE NOT granted;
SELECT pid, pg_blocking_pids(pid) FROM pg_stat_activity WHERE cardinality(pg_blocking_pids(pid)) > 0;

-- deadlock logging
ALTER SYSTEM SET log_lock_waits = on;
ALTER SYSTEM SET deadlock_timeout = '1s';
SELECT pg_reload_conf();
```

> **Pitfall:** under `READ COMMITTED`, two transactions can **deadlock** if they lock rows
> in a different order. Always lock in the **same order** (e.g. `ORDER BY id`).

## MVCC, VACUUM, ANALYZE

PostgreSQL uses MVCC: readers do not block writers. What blocks is the **row
lock** (write lock).

```sql
-- inspect version & status
SELECT xmin, xmax, cmin, cmax, ctid, * FROM orders LIMIT 1;

-- verbose vacuum
VACUUM (VERBOSE, ANALYZE) orders;
VACUUM (VERBOSE, FULL, ANALYZE) orders;   -- rewrites the table + LOCK EXCLUSIVE (not during traffic)

-- freeze old transactions (unblocks a stuck vacuum)
VACUUM FREEZE orders;

-- more aggressive autovacuum for write-heavy tables
ALTER TABLE orders SET (
    autovacuum_vacuum_scale_factor  = 0.02,   -- default 0.2 (20%)
    autovacuum_analyze_scale_factor = 0.01,   -- default 0.1
    autovacuum_vacuum_insert_scale_factor = 0.05,
    autovacuum_vacuum_cost_limit = 2000
);

-- monitor
SELECT relname, n_dead_tup, n_live_tup,
       round(100.0 * n_dead_tup / NULLIF(n_live_tup + n_dead_tup, 0), 1) AS dead_pct
FROM pg_stat_user_tables WHERE n_dead_tup > 1000 ORDER BY n_dead_tup DESC;
```

| Symptom | Cause | Action |
| :--- | :--- | :--- |
| Table bloats | dead tuples | `VACUUM` (automatic) + autovacuum enabled |
| Old `xmin` still visible | long snapshot holds back vacuum | Shorten transaction duration |
| Plan is off | stale statistics | `ANALYZE` |
| Large & slow index | index bloat | `REINDEX CONCURRENTLY` |
| HOT updates not used | fillfactor full | `ALTER TABLE ... SET (fillfactor = 80)` |
| Repeated updates to the same row | HOT updates need page space | `fillfactor` 70–90 |

```sql
-- find long transactions holding back vacuum
SELECT pid, state, xact_start, now() - xact_start AS age, left(query, 80)
FROM pg_stat_activity
WHERE xact_start IS NOT NULL AND now() - xact_start > interval '5 minutes'
ORDER BY xact_start;

-- kill (use with care)
SELECT pg_cancel_backend(pid) FROM pg_stat_activity WHERE ...;
SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE ...;
```

> **Pitfall:** `VACUUM FULL` locks the table for **writes** while it rewrites the whole table.
> In production = downtime. Use `pg_repack` (extension) for an online rewrite.

## Transaction & savepoint

```sql
BEGIN;
    INSERT INTO orders (...) VALUES (...);
    SAVEPOINT sp1;
    INSERT INTO order_items (...) VALUES (...);   -- fails
    ROLLBACK TO SAVEPOINT sp1;                    -- cancel the item, keep the order
COMMIT;

-- DEFERRED constraint: checked at COMMIT
SET CONSTRAINTS ALL DEFERRED;
```

| Isolation | Behavior |
| :--- | :--- |
| `READ COMMITTED` | a new snapshot per statement (default) |
| `REPEATABLE READ` | snapshot stays fixed for the transaction |
| `SERIALIZABLE` | snapshot + conflict detection → `40001` error |

```sql
-- retry on serialization failure
BEGIN ISOLATION LEVEL SERIALIZABLE;
...
COMMIT;
-- on error 40001 → repeat the whole transaction
```

> **Pitfall:** under `SERIALIZABLE`, a failed transaction must be **repeated in full** — not
> continued. A retry loop is mandatory if you use this isolation level.

## JSONB & JSON path

```sql
ALTER TABLE products ADD COLUMN attributes jsonb NOT NULL DEFAULT '{}'::jsonb;

-- fetch & modify
SELECT id, attributes->>'color' AS color FROM products;
SELECT attributes->'size'->>'unit' FROM products;
UPDATE products SET attributes = jsonb_set(attributes, '{color}', '"blue"') WHERE id = 1;
UPDATE products SET attributes = attributes || '{"tag":"sale"}'::jsonb WHERE id = 1;
UPDATE products SET attributes = attributes - 'internal' WHERE id = 1;

-- contains
SELECT * FROM products WHERE attributes @> '{"color":"red","size":"L"}'::jsonb;
SELECT * FROM products WHERE attributes ? 'brand';        -- key exists
SELECT * FROM products WHERE attributes ?| ARRAY['brand','color'];

-- index
CREATE INDEX idx_products_attrs ON products USING gin (attributes);
CREATE INDEX idx_products_brand ON products ((attributes->>'brand'));

-- JSON path (SQL/JSON)
SELECT jsonb_path_query(attributes, '$.variants[*].sku') FROM products;
SELECT attributes @@ '$.price > 100' FROM products;
```

| Operator | Meaning |
| :--- | :--- |
| `->` | element (JSON) |
| `->>` | element (text) |
| `#>` | path (JSON) |
| `#>>` | path (text) |
| `@>` | contains (JSONB) |
| `<@` | contained by |
| `?` `?|` `?&` | key exists / any / all |
| `@@` | JSON path predicate |
| `jsonb_path_query` | path query (SQL/JSON) |

> **Pitfall:** a JSONB column that changes often causes **bloat** (dead tuples). Use a partial index +
> regular vacuum, or better yet use regular columns if the shape is stable.

## Window function & CTE

```sql
-- top N per group
SELECT * FROM (
  SELECT o.*,
         row_number() OVER (PARTITION BY o.merchant_id ORDER BY o.created_at DESC) AS rn
  FROM orders o
) t WHERE t.rn <= 3;

-- ranking
SELECT id, total,
       rank()       OVER (ORDER BY total DESC) AS rnk,   -- 1,2,2,4
       dense_rank() OVER (ORDER BY total DESC) AS drnk,  -- 1,2,2,3
       percent_rank() OVER (ORDER BY total DESC) AS prank
FROM orders;

-- running total & frame
SELECT id, created_at,
       sum(total) OVER (ORDER BY created_at
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running,
       sum(total) OVER (ORDER BY created_at
         RANGE BETWEEN INTERVAL '7 days' PRECEDING AND CURRENT ROW) AS moving_7d
FROM orders;

-- lag/lead
SELECT id, total,
       total - lag(total)  OVER (ORDER BY created_at) AS delta,
       lead(total)        OVER (ORDER BY created_at) AS next_total
FROM orders;
```

```sql
-- CTEs (inlined since PG12; always materialized before that)
WITH RECURSIVE tree AS (
  SELECT id, parent_id, 1 AS depth FROM categories WHERE parent_id IS NULL
  UNION ALL
  SELECT c.id, c.parent_id, t.depth + 1 FROM categories c JOIN tree t ON c.parent_id = t.id
)
SELECT * FROM tree ORDER BY depth;

-- CTE + DML
WITH updated AS (
  UPDATE orders SET status = 'EXPIRED' WHERE created_at < now() - interval '30 days'
  RETURNING id
)
INSERT INTO audit_log (entity_id, action) SELECT id, 'expire' FROM updated;
```

| Window frame | Meaning |
| :--- | :--- |
| `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` | running total |
| `RANGE BETWEEN n PRECEDING AND CURRENT ROW` | value-based moving average |
| `GROUPS` | group-based |

> **Pitfall:** window functions are **not allowed** in `WHERE` (SQL evaluates windows after
> `WHERE`). Wrap them in a subquery/CTE first.

## Full-text search

```sql
-- generated tsvector column
ALTER TABLE products
  ADD COLUMN search_vector tsvector
  GENERATED ALWAYS AS (
    setweight(to_tsvector('simple', coalesce(name,'')), 'A') ||
    setweight(to_tsvector('simple', coalesce(description,'')), 'B')
  ) STORED;

CREATE INDEX idx_products_search ON products USING gin (search_vector);

-- query
SELECT id, name, ts_rank(search_vector, q) AS rank
FROM products, websearch_to_tsquery('simple', 'sepatu sport') q
WHERE search_vector @@ q
ORDER BY rank DESC LIMIT 20;

-- stemming + built-in dictionary
SELECT to_tsvector('english', 'running shoes');    -- 'run' 'shoe'

-- unaccent + trigram for typos
CREATE EXTENSION IF NOT EXISTS unaccent;
CREATE EXTENSION IF NOT EXISTS pg_trgm;
SELECT similarity(name, 'sepatu') FROM products WHERE name % 'sepatu';
```

| Tool | For |
| :--- | :--- |
| `to_tsvector` / `to_tsquery` | native FTS, fast, stemming + stopwords |
| `websearch_to_tsquery` | web search syntax (`"phrase" -exclude`) |
| `pg_trgm` | fuzzy LIKE / typos |
| `unaccent` | ignores accents (`"cafe" ~ "café"`) |

## Partitioning

```sql
-- declarative RANGE partitioning (time)
CREATE TABLE orders (
  id bigint GENERATED ALWAYS AS IDENTITY,
  created_at timestamptz NOT NULL,
  total numeric(18,2) NOT NULL,
  ...
) PARTITION BY RANGE (created_at);

CREATE TABLE orders_2026_10 PARTITION OF orders
  FOR VALUES FROM ('2026-10-01') TO ('2026-11-01');
CREATE TABLE orders_2026_11 PARTITION OF orders
  FOR VALUES FROM ('2026-11-01') TO ('2026-12-01');

-- default partition for non-matching data
CREATE TABLE orders_default PARTITION OF orders DEFAULT;

-- new partition (cheap: old data is not moved)
CREATE TABLE orders_2027_01 PARTITION OF orders
  FOR VALUES FROM ('2027-01-01') TO ('2027-02-01');

-- detach an old partition (data still exists, table is detached)
ALTER TABLE orders DETACH PARTITION orders_2026_10;

-- hash partitioning
CREATE TABLE events (...) PARTITION BY HASH (user_id);
CREATE TABLE events_p0 PARTITION OF events FOR VALUES WITH (MODULUS 4, REMAINDER 0);

-- list partitioning
CREATE TABLE regions (...) PARTITION BY LIST (region);
```

| Type | For |
| :--- | :--- |
| `RANGE` | time (month/day) — most common |
| `LIST` | discrete values (region, tenant) |
| `HASH` | even distribution, fixed partition count |

| Benefit | Detail |
| :--- | :--- |
| Pruning | queries only touch relevant partitions |
| Retention | `DROP TABLE` on an old partition = instant (vs `DELETE` millions of rows) |
| Per-partition indexes | local, smaller indexes |

> **Pitfall:** partitions are **not** created automatically every year. Old partitions that are never dropped = data
> piles up. Automate partition creation (pg_partman / cron) or stale data accumulates.

## Sequence & identity

```sql
-- identity (modern, recommended)
CREATE TABLE t (id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY);

-- manual sequence + DEFAULT
CREATE SEQUENCE order_no_seq START 1000;
ALTER TABLE orders ALTER COLUMN order_no SET DEFAULT 'ORD-' || nextval('order_no_seq');

-- gaps & cache
ALTER SEQUENCE order_no_seq RESTART WITH 1;
SELECT setval('order_no_seq', 5000, true);   -- next value = 5001
SELECT last_value FROM order_no_seq;

-- safe for parallel worker queues
SELECT nextval('order_no_seq');             -- a gap after rollback is normal
```

| Behavior | Explanation |
| :--- | :--- |
| Gaps | Sequences do not roll back → numbers have holes (normal) |
| `CACHE n` | caches n values in memory; a crash = losing n numbers |
| `NO CYCLE` | errors once maxed out (default) |
| `CYCLE` | wraps back to min (for IDs that may be reused) |

> **Pitfall:** `SERIAL` = sequence + default. The sequence is owned by the table, but it is **not** dropped when
> the table is dropped. Use `IDENTITY` for new tables.

```sql
-- pgvector: Hybrid Search example (embedding + full text, RRF)
CREATE TABLE products (
  id bigint PRIMARY KEY,
  name text,
  embedding vector(768),
  search_vector tsvector
);
CREATE INDEX idx_products_vec ON products USING hnsw (embedding vector_cosine_ops);
CREATE INDEX idx_products_fts ON products USING gin (search_vector);

-- hybrid search: merge full-text & vector scores
WITH fts AS (
  SELECT id, ts_rank(search_vector, websearch_to_tsquery('simple', $1)) AS score
  FROM products WHERE search_vector @@ websearch_to_tsquery('simple', $1)
  LIMIT 50
), vec AS (
  SELECT id, 1 - (embedding <=> $2::vector) AS score
  FROM products ORDER BY embedding <=> $2::vector LIMIT 50
)
SELECT id, sum(score) AS rrf_score
FROM (SELECT * FROM fts UNION ALL SELECT * FROM vec) x
GROUP BY id ORDER BY rrf_score DESC LIMIT 20;
```

> `CREATE EXTENSION` alone is not enough.

## Security & RLS

```sql
-- roles & privileges
CREATE ROLE app_user LOGIN PASSWORD '...' ;
GRANT SELECT, INSERT, UPDATE ON orders TO app_user;
GRANT USAGE, SELECT ON SEQUENCE orders_id_seq TO app_user;
REVOKE ALL ON SCHEMA public FROM PUBLIC;      -- best practice

-- security definer view (RLS-friendly)
CREATE VIEW order_summary WITH (security_invoker = true) AS
SELECT merchant_id, count(*), sum(total) FROM orders GROUP BY merchant_id;

-- Row Level Security: per-row tenant isolation
ALTER TABLE orders ENABLE ROW LEVEL SECURITY;
ALTER TABLE orders FORCE ROW LEVEL SECURITY;   -- also applies to the table owner

CREATE POLICY orders_tenant_policy ON orders
  USING (tenant_id = current_setting('app.tenant_id')::uuid)
  WITH CHECK (tenant_id = current_setting('app.tenant_id')::uuid);

-- set tenant per transaction
SET LOCAL app.tenant_id = '11111111-1111-1111-1111-111111111111';
```

| Control | How |
| :--- | :--- |
| Password | SCRAM-SHA-256 (default PG14+) |
| Host auth | `pg_hba.conf` + `scram-sha-256` |
| TLS | `ssl = on`, `ssl_cert_file`, `clientcert=verify-full` |
| RLS | per-row isolation per tenant |
| Column privilege | `GRANT SELECT (col1, col2) ON t TO u` |
| `SECURITY DEFINER` | elevated function — **must** `SET search_path = ''` |
| Audit | `pgaudit` extension |

```sql
-- elevated function: secure the search_path
CREATE FUNCTION get_secret() RETURNS text
LANGUAGE sql SECURITY DEFINER
SET search_path = ''
AS $$ SELECT value FROM private.secrets LIMIT 1 $$;
```

> **Pitfall:** `SECURITY DEFINER` without `SET search_path` = users can create objects
> in `public` that shadow system functions → privilege escalation.

default_pool_size = 25
reserve_pool_size = 5
reserve_pool_timeout = 3
server_reset_query = DISCARD ALL
ignore_startup_parameters = extra_float_digits

```yaml
# application
spring:
  datasource:
    hikari:
      maximum-pool-size: 20
      minimum-idle: 5
      connection-timeout: 30000
      max-lifetime: 900000
      idle-timeout: 300000
      pool-name: pos-sales-pool
```

| PgBouncer mode | Allows | When |
| :--- | :--- | :--- |
| `session` | session state | tooling/admin |
| `transaction` | **no** session state | application default |
| `statement` | one statement | batch/CLI |

**What is not allowed under transaction pooling:** `PREPARE` (older versions), `LISTEN/NOTIFY`,
session `SET`, temp tables, session-level advisory locks, `WITH HOLD` cursors.

> **Pitfall:** total connections = `replicas × pool_size`. 10 pods × 20 = 200 connections per host —
> check `max_connections` (default 100) before raising the pool size. Exceeding it → `FATAL: sorry,
> too many clients already`.

## Maintenance & backup

```sql
VACUUM (ANALYZE) t;                    -- reclaim + statistics
VACUUM (FULL, ANALYZE) t;              -- rewrites the table (LOCK!)
REINDEX INDEX CONCURRENTLY idx;         -- rebuild an index without a write lock
REINDEX TABLE t;                        -- all indexes (lock)
CLUSTER t USING idx;                   -- reorder rows (lock, full rewrite)
ANALYZE t;                              -- statistics only
```

```bash
# backup
pg_dump -Fc -d pos_sales -f pos_sales.dump          # custom format (compressed)
pg_dump -d pos_sales -Fp -f pos_sales.sql            # plain SQL
pg_dumpall --globals-only -f globals.sql             # roles & tablespaces

# restore
pg_restore -d pos_sales --clean --if-exists --jobs=4 pos_sales.dump
psql -d pos_sales -f pos_sales.sql

# major upgrade
pg_upgrade --check -d /var/lib/postgresql/17 -D /var/lib/postgresql/18
```

| Tool | When |
| :--- | :--- |
| `pg_dump` | logical backup, restore to another version |
| `pg_basebackup` | physical backup, base for a replica |
| WAL archiving | point-in-time recovery |
| `pg_dumpall --globals-only` | roles & tablespaces |

> **Pitfall:** `pg_dump` **cannot** restore to an older database (new features). And
> a logical dump of a large DB takes a long time — use physical backups + WAL in production.

## Monitoring

```sql
-- slowest & most expensive queries
SELECT calls, mean_exec_time, max_exec_time, rows, query
FROM pg_stat_statements WHERE query NOT LIKE '%pg_stat%'
ORDER BY mean_exec_time DESC LIMIT 20;

-- query ordering
SELECT calls, query FROM pg_stat_statements ORDER BY calls DESC LIMIT 10;

-- tables & indexes
SELECT relname, seq_scan, idx_scan, n_live_tup, n_dead_tup,
       pg_size_pretty(pg_total_relation_size(relid)) AS size
FROM pg_stat_user_tables ORDER BY pg_total_relation_size(relid) DESC LIMIT 15;

-- index size
SELECT indexrelname, pg_size_pretty(pg_relation_size(indexrelid)) AS size, idx_scan
FROM pg_stat_user_indexes ORDER BY pg_relation_size(indexrelid) DESC LIMIT 15;

-- checkpoint & buffer
SELECT * FROM pg_stat_bgwriter;
SELECT * FROM pg_stat_checkpointer;

-- vacuum
SELECT relname, last_vacuum, last_autovacuum, last_analyze, last_autoanalyze
FROM pg_stat_user_tables;

-- longest transaction
SELECT pid, now()-xact_start AS age, state, left(query,80)
FROM pg_stat_activity WHERE xact_start IS NOT NULL ORDER BY xact_start LIMIT 5;

-- replication lag
SELECT application_name, state, sync_state,
       pg_wal_lsn_diff(pg_current_wal_lsn(), replay_lsn) AS lag_bytes
FROM pg_stat_replication;
```

| Metric | Alert |
| :--- | :--- |
| Replication lag | > 30 seconds |
| `n_dead_tup` | > 20% of live |
| Cache hit ratio | < 99% |
| Longest transaction | > 5 minutes |
| `max_connections` | > 80% |
| WAL size | keeps growing (lagging slot) |

## Pitfalls (must read)

| Pitfall | Symptom | Solution |
| :--- | :--- | :--- |
| `OFFSET 10000` | The deeper you go, the slower it gets | Keyset pagination |
| `NOT IN` + nullable subquery | Empty results with no error | `NOT EXISTS` |
| `LIKE '%x%'` | Full scan | `pg_trgm` + GIN |
| `numeric` without precision | Different scales across rows | `numeric(18,2)` |
| `float` for money | Rounding drift | `numeric` |
| `timestamp` (not `timestamptz`) | Time zone conflicts | `timestamptz` + `SET TIME ZONE` |
| `SELECT *` | Wasted I/O & memory | Select specific columns |
| Long transactions | Locks held, vacuum stuck | Small batches, commit often |
| `UPDATE` on all rows in 1 stmt | Bloat + long locks | Batches of 1000–5000 rows |
| `count(*)` on a large table | Full scan | Estimate / counter |
| UUID v4 as PK | Index page splits, slow inserts | UUIDv7 or bigint |
| Index on a low-cardinality column | Wasteful, slow writes | Partial index |
| `CREATE INDEX` during traffic | Write lock | `CONCURRENTLY` |
| `VACUUM FULL` during traffic | Full lock | `pg_repack` |
| Trusting `search_path` | Objects in the wrong schema | Set per role/app |
| `SECURITY DEFINER` without search_path | Privilege escalation | `SET search_path = ''` |
| Prepared statements + PgBouncer transaction mode | "prepared statement does not exist" | `prepareThreshold=0` or PgBouncer 1.21+ |
| Connection pool exceeds `max_connections` | `too many clients` | Lower the pool size |
| `GRANT ALL` to the app user | Least-privilege violation | Grant per table/column |
| Lagging replication slot | Disk full | Monitor `pg_replication_slots` |
| Old partitions not dropped | Data piles up | Automate partition drops |
| `ALTER TYPE ... ADD VALUE` inside a transaction | Errors on older versions | Commit first, then use it |
