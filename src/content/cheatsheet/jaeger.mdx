## Mental model: traces & spans

```
Trace (1 request end-to-end)
├── Span  gateway        (7.2ms)  root
│   ├── Span  auth       (1.1ms)
│   ├── Span  order-db  (12.4ms)   ← this is where the problem is
│   └── Span  kafka-pub (0.8ms)
└── Span  payment        (35.0ms)
```

| Concept | Meaning |
| :--- | :--- |
| Trace | one logical operation across services, wrapped in a **trace id** (32 hex) |
| Span | one unit of work within a trace, with a **span id** (16 hex) + parent |
| Parent/child | the hierarchy established by context propagation |
| Attributes | key-values on a span (id, count, status) |
| Events | points in time within a span (relative timestamp) |
| Status | `Unset` / `Error` — marks a failed span |
| Baggage | key-values **propagated** across the whole trace (use sparingly) |
| Span kind | `SERVER`, `CLIENT`, `PRODUCER`, `CONSUMER`, `INTERNAL` |

> **Pitfall:** a `CLIENT` span (outgoing call) and a `SERVER` span (incoming) are **two
> different spans**. If service A calls service B, there are 2 spans: `A:CLIENT` and
> `B:SERVER`. That's normal — don't merge them into one.

## OpenTelemetry: auto-instrumentation

### Java (Spring Boot)

```bash
# download the agent
curl -L -o opentelemetry-javaagent.jar \
  https://github.com/open-telemetry/opentelemetry-java-instrumentation/releases/latest/download/opentelemetry-javaagent.jar

# run with the agent
java -javaagent:/otel/opentelemetry-javaagent.jar \
  -jar app.jar
```

```bash
export OTEL_SERVICE_NAME=order-service
export OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4317
export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
export OTEL_TRACES_SAMPLER=parentbased_traceidratio
export OTEL_TRACES_SAMPLER_ARG=0.1          # 10% in production, 1.0 in dev
export OTEL_PROPAGATORS=tracecontext,baggage
export OTEL_RESOURCE_ATTRIBUTES=service.namespace=pos,deployment.environment=prod
export OTEL_LOGS_EXPORTER=none
```

```yaml
# spring boot — equivalent properties
management:
  tracing:
    sampling:
      probability: 0.1
  otlp:
    tracing:
      endpoint: http://otel-collector:4317
      transport: grpc
```

| Env var | Meaning |
| :--- | :--- |
| `OTEL_SERVICE_NAME` | service name → becomes the `service.name` label |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | span destination (collector) |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | `grpc` or `http/protobuf` |
| `OTEL_TRACES_SAMPLER` | `always_on`, `always_off`, `traceidratio`, `parentbased_*` |
| `OTEL_TRACES_SAMPLER_ARG` | sampling ratio (0.1 = 10%) |
| `OTEL_PROPAGATORS` | `tracecontext,baggage` (W3C) |
| `OTEL_RESOURCE_ATTRIBUTES` | additional resource attributes |
| `OTEL_JAVAAGENT_LOGGING` | `none`/`simple`/`debug` — check that the agent is running |

> **Pitfall:** the agent does not instrument libraries that are **shaded** (e.g. shaded
> JARs). If internal service spans don't show up, check whether the artifact is shaded.

### Go

```go
import (
    "go.opentelemetry.io/contrib/instrumentation/net/http/otelhttp"
    "go.opentelemetry.io/otel"
    "go.opentelemetry.io/otel/propagation"
    "go.opentelemetry.io/otel/sdk/trace"
    "go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracegrpc"
)

func initTracer(ctx context.Context) (func(context.Context) error, error) {
    exp, err := otlptracegrpc.New(ctx,
        otlptracegrpc.WithEndpoint("otel-collector:4317"),
        otlptracegrpc.WithInsecure())
    if err != nil { return nil, err }

    tp := trace.NewTracerProvider(
        trace.WithBatcher(exp),
        trace.WithResource(resource.NewWithAttributes(
            semconv.SchemaURL,
            semconv.ServiceName("order-service"),
        )),
        trace.WithSampler(trace.ParentBased(trace.TraceIDRatioBased(0.1))),
    )
    otel.SetTracerProvider(tp)
    otel.SetTextMapPropagator(propagation.NewCompositeTextMapPropagator(
        propagation.TraceContext{}, propagation.Baggage{}))

    return tp.Shutdown, nil
}

// client: wrap http.Transport
client := &http.Client{
    Transport: otelhttp.NewTransport(http.DefaultTransport),
}
```

```go
// gRPC interceptor
import "go.opentelemetry.io/contrib/instrumentation/google.golang.org/grpc/otelgrpc"

conn, err := grpc.NewClient(target,
    grpc.WithStatsHandler(otelgrpc.NewClientHandler()),
    grpc.WithStatsHandler(otelgrpc.NewClientHandler()),
)
```

## OpenTelemetry: manual spans

```java
// Java — span for an important operation
@Service
@RequiredArgsConstructor
public class PaymentService {

    private final Tracer tracer;   // io.opentelemetry.api.trace.Tracer

    public PaymentResponse charge(ChargeRequest req) {
        Span span = tracer.spanBuilder("chargeCard")
                .setSpanKind(SpanKind.CLIENT)
                .setAttribute("card.id", req.cardId())
                .setAttribute("amount.cents", req.amountCents())
                .startSpan();
        try (Scope scope = span.makeCurrent()) {          // REQUIRED: active context
            PaymentResponse res = gateway.charge(req);
            span.setAttribute("provider", res.provider());
            return res;
        } catch (Exception e) {
            span.recordException(e);
            span.setStatus(StatusCode.ERROR, e.getMessage());
            throw e;
        } finally {
            span.end();                                   // REQUIRED: always called
        }
    }
}
```

```go
// Go — manual span
ctx, span := tracer.Start(ctx, "chargeCard",
    trace.WithSpanKind(trace.SpanKindClient),
    trace.WithAttributes(
        attribute.String("card.id", cardID),
        attribute.Int64("amount.cents", amount),
    ),
)
defer span.End()

if err := pay(ctx, cardID, amount); err != nil {
    span.RecordError(err)
    span.SetStatus(codes.Error, err.Error())
    return err
}
```

| Rule | Why |
| :--- | :--- |
| Always call `span.end()` | an unclosed span = never sent |
| Pass `makeCurrent()` / `ctx` through | child spans & context propagation |
| `recordError` + `SetStatus(ERROR)` | errors must be **visible** in the UI |
| Low-cardinality `SetAttribute` | attributes become indexes in storage |
| Don't create a span per item in a loop | thousands of spans per request |

## Span semantics & attributes

```java
// span kinds
span.setSpanKind(SpanKind.SERVER);     // receives a request
span.setSpanKind(SpanKind.CLIENT);     // calls another service
span.setSpanKind(SpanKind.PRODUCER);   // publishes a message
span.setSpanKind(SpanKind.CONSUMER);   // consumes a message
```

| Semantic attribute | Content |
| :--- | :--- |
| `http.request.method` | `GET` |
| `http.response.status_code` | `200` |
| `url.path` | `/api/orders/8821` (**template**, not the actual value) |
| `server.address` | `order-service` |
| `db.system.name` | `postgresql` |
| `db.query.text` | query (careful: may contain sensitive data) |
| `messaging.system` | `kafka` |
| `messaging.destination.name` | topic |
| `rpc.service` / `rpc.method` | `OrderService` / `CreateOrder` |

| Rule | Reason |
| :--- | :--- |
| Max ~15 attributes per span | storage & cost |
| **Do not** include PII / tokens / passwords | spans are sent to storage |
| IDs (order/user) as attributes | allowed, but not as metric labels |
| `db.statement` without parameter values | don't leak data |
| `exception.message` | allowed, but truncate if long |

## W3C trace context & propagation

```
traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
             ^^  ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^  ^^^^^^^^^^^^^^^^^^  ^^
          version      trace-id (32 hex)        span-id (16 hex)    flags
```

```bash
# the header sent by the service
curl -H "traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01" \
     http://localhost:8080/api/orders
```

| Header | Meaning |
| :--- | :--- |
| `traceparent` | W3C trace context (today's standard) |
| `tracestate` | vendor-specific state, forwarded along |
| `baggage` | arbitrary key-values, carried into every span |
| `b3` | legacy B3 (JAEGER) — don't use it for new systems |

```java
// automatic propagation via the agent / Micrometer
// context from the HTTP header → the new span becomes a child
```

| Rule | Reason |
| :--- | :--- |
| Trace context **must** travel over the network | without it, traces break at service boundaries |
| B3 is only for legacy compatibility | W3C is the standard |
| Keep baggage **small** | it rides on every request, increasing header size |
| Headers can't be trusted blindly | an intermediate hop can forge the trace id |

## Sampling: head, tail, parent-based

```yaml
# OTel Collector — tail sampling (decision made after spans finish)
processors:
  tail_sampling:
    decision_wait: 10s            # wait for spans to finish
    policies:
      - name: errors
        type: status_code
        status_code: { status_codes: [ERROR] }
      - name: slow
        type: latency
        latency: { threshold_ms: 1000 }
      - name: baseline
        type: probabilistic
        probabilistic: { sampling_percentage: 5 }
    # composition: keep if any policy matches
```

| Strategy | How | When |
| :--- | :--- | :--- |
| Head (SDK) | `OTEL_TRACES_SAMPLER_ARG=0.1` | cheap, but errors can be missed |
| Head parent-based | `parentbased_traceidratio` | **best default** — children follow the parent |
| Tail (collector) | the collector decides after spans finish | ideal for "keep all errors + 1% of successes" |

| Trade-off | Head | Tail |
| :--- | :--- | :--- |
| Cost | minimal | spans are still sent to the collector |
| Error_rate | can be 0 | **visible** (all errors are kept) |
| Complete trace | may have gaps | intact for what's kept |

> **Pitfall:** using head sampling `always_on` in production = **all traffic** lands in
> storage → costs explode. Minimum: `parentbased_traceidratio` 0.01–0.1, or tail
> sampling in the collector.

## Jaeger architecture

```
App ──OTLP──▶ OTel Collector ──▶ Jaeger Collector ──▶ Ingester ──▶ Storage
                    │                                            (badger/ES/Cassandra/ClickHouse)
                    └── tail sampling (can be done in the collector)
App ──jaeger-agent──▶ Jaeger Collector (for legacy traces via UDP/thrift)
```

| Component | Role | Notes |
| :--- | :--- | :--- |
| Jaeger Collector | receives spans, sampling, batching | can be replaced by the OTel Collector |
| Jaeger Query | serves the UI + API | reads from storage |
| Jaeger Ingester | batches spans into storage | streaming |
| Agent | sidecar, sends via UDP | only for legacy SDKs (jaeger-client) |
| All-in-One | collector+query+ingester in one pod | for dev & small clusters |

**Jaeger v2** (2024+) is built on top of the **OTel Collector**: the pipeline/distribution goes
through the OTel collector, storage through drivers (`badger`, `elasticsearch`, `clickhouse`).

## Deployment

```yaml
# jaeger-all-in-one (dev / small clusters)
apiVersion: apps/v1
kind: Deployment
metadata:
  name: jaeger
  namespace: monitoring
spec:
  replicas: 1
  selector:
    matchLabels: { app: jaeger }
  template:
    metadata:
      labels: { app: jaeger }
    spec:
      containers:
        - name: jaeger
          image: jaegertracing/jaeger:2.6.0
          env:
            - name: COLLECTOR_OTLP_ENABLED
              value: "true"
            - name: SPAN_STORAGE_TYPE
              value: badger
            - name: BADGER_EPHEMERAL
              value: "false"
            - name: MEMORY_MAX_TRACES
              value: "50000"
          ports:
            - { name: otlp-grpc, containerPort: 4317 }
            - { name: otlp-http, containerPort: 4318 }
            - { name: query, containerPort: 16686 }
          readinessProbe:
            httpGet: { path: /, port: 16686 }
            initialDelaySeconds: 5
          livenessProbe:
            httpGet: { path: /, port: 16686 }
            initialDelaySeconds: 15
          volumeMounts:
            - { name: badger, mountPath: /badger/data }
      volumes:
        - name: badger
          persistentVolumeClaim:
            claimName: jaeger-badger
```

```yaml
# OTel Collector — export to Jaeger
exporters:
  otlp/jaeger:
    endpoint: jaeger-collector:4317
    tls:
      insecure: true

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [memory_limiter, batch, tail_sampling]
      exporters: [otlp/jaeger]
```

> **Pitfall:** Jaeger All-in-One with `memory` storage → **all traces are lost on
> restart**. For production use `badger` (with a PVC) or `elasticsearch`/`clickhouse`.

## Query API & UI

```bash
# find traces by service
curl -s "http://localhost:16686/api/traces?service=order-service&limit=20" \
  | jq '.data[] | {traceID, spans: (.spans|length), duration: .duration}'

# trace by id
curl -s "http://localhost:16686/api/traces/4bf92f3577b34da6a3ce929d0e0e4736" \
  | jq '.data[0].spans | sort_by(.duration) | reverse | .[0:5] | .[] | {operationName, duration}'

# slowest spans
curl -s "http://localhost:16686/api/traces?service=order-service&lookback=1h&limit=20" \
  | jq '[.data[].spans[] | {op: .operationName, ms: (.duration/1000)}] | sort_by(-.ms) | .[0:10]'

# services & dependencies
curl -s http://localhost:16686/api/services | jq -r '.data[]'
curl -s http://localhost:16686/api/dependencies | jq '.data[0].dependencies'

# spans with errors
curl -s "http://localhost:16686/api/traces?service=order-service&tags=%7B%22error%22%3Atrue%7D&limit=20" \
  | jq '.data | length'
```

| API param | Meaning |
| :--- | :--- |
| `service` | filter by service name |
| `operation` | filter by operation (span) name |
| `tags` | `key=value` filter (JSON-encoded) |
| `lookback` | `1h`, `24h` |
| `minDuration` / `maxDuration` | duration filter (ms) |
| `limit` | number of traces |
| `start` / `end` | epoch range (microseconds) |

**Jaeger UI:**
- **Search** → filter by service + operation + tags (error=true) + lookback + min-duration.
- **Trace detail** → flame chart; click a span → attributes, events, logs.
- **Find traces** → sort by duration to find the slow ones.
- **Dependencies** → map between services.
- **Metrics** → RED metrics from span metrics (v1).

## Log ↔ trace ↔ metric correlation

```logql
# log → trace: search in Loki then jump to Jaeger
{app="order-service"} | json | trace_id="4bf92f3577b34da6a3ce929d0e0e4736"
```

```yaml
# Grafana: derived field from Loki → link to Jaeger
derivedFields:
  - name: TraceID
    matcherRegex: "trace_id=(\\w+)"
    url: "$${__value.raw}"
    datasourceUid: jaeger-main
```

```promql
# trace → metric: from trace detail, "Trace to metrics"
# or use exemplars: from a histogram bucket, click the exemplar → trace
```

```java
// make sure trace_id lands in the MDC (current span)
Span span = Span.current();
if (span.getSpanContext().isValid()) {
    MDC.put("trace_id", span.getSpanContext().getTraceId());
}
```

> **Pitfall:** `trace_id` is only in the log if **a span is active** when the log is written.
> Logs outside a request (scheduler, startup) have no trace → fill in `-` or your own UUID.

## Cost & capacity

| Component | Default limit / notes |
| :--- | --- |
| `MEMORY_MAX_TRACES` | 50,000 traces in memory (all-in-one) |
| `max_traces` (collector) | span queue before flush |
| Storage | badger (lightweight), ES/Cassandra/ClickHouse (at scale) |
| Span per trace | 10–30 normal; > 100 = excessive instrumentation |
| Attributes per span | ~15; more than that = noise |
| Sampling | 1–10% head, or tail sampling |

```yaml
# collector: batasi memory & batch
processors:
  memory_limiter:
    check_interval: 1s
    limit_percentage: 75
    spike_limit_percentage: 15
  batch:
    timeout: 5s
    send_batch_size: 512
    send_batch_max_size: 1024

extensions:
  jaeger_storage:
    backends:
      some_storage:
        memory:
          max_traces: 100000
```

> **Pitfall:** a full span queue (`max_traces`) = spans are **dropped** silently. Check the
> `jaeger_collector_queue_size` & `jaeger_receiver_accepted_spans` vs
> `jaeger_receiver_refused_spans` metrics.

## Pitfalls (must-read)

| Pitfall | Symptom | Solution |
| :--- | :--- | :--- |
| Forgot `span.end()` | Span never sent | `defer span.end()` / try-finally |
| Forgot `makeCurrent()` | Child span isn't linked | Always close the scope |
| Forgot to pass `ctx` (Go) | Trace breaks between services | Always pass `ctx` |
| `head sampling always_on` | Storage costs explode | `parentbased_traceidratio` 0.01–0.1 |
| Span per item in a loop | Thousands of spans per request | One span per operation |
| Attributes contain PII/tokens | Sensitive data stored | Sanitize before `SetAttribute` |
| `url.path` contains raw IDs | Cardinality & PII | Templated path |
| `memory` storage in production | Traces lost on restart | badger + PVC, or ES/ClickHouse |
| B3 used in new systems | Not compatible | W3C `traceparent` |
| Trace context doesn't travel over HTTP | Trace breaks at the boundary | Middleware/propagator |
| Full span queue | Spans dropped silently | Monitor refused_spans, raise max_traces |
| Trace ID doesn't reach the logs | Can't correlate | MDC + filter |
| One span for all operations | No granularity | Split at each boundary |
| Raw `db.statement` | Data leak | Parameterize |
