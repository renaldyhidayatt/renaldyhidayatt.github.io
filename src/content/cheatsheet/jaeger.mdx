## Mental model: trace & span

```
Trace (1 request end-to-end)
├── Span  gateway        (7.2ms)  root
│   ├── Span  auth       (1.1ms)
│   ├── Span  order-db  (12.4ms)   ← di sini masalahnya
│   └── Span  kafka-pub (0.8ms)
└── Span  payment        (35.0ms)
```

| Konsep | Arti |
| :--- | :--- |
| Trace | satu operasi logis lintas service, dibungkus **trace id** (32 hex) |
| Span | satu unit kerja di dalam trace, punya **span id** (16 hex) + parent |
| Parent/child | hubungan hierarki dari context propagation |
| Attributes | key-value di span (id, jumlah, status) |
| Events | titik waktu di dalam span (timestamp relatif) |
| Status | `Unset` / `Error` — penanda span gagal |
| Baggage | key-value yang **terpropagasi** ke seluruh trace (pakai hemat) |
| Span kind | `SERVER`, `CLIENT`, `PRODUCER`, `CONSUMER`, `INTERNAL` |

> **Jebakan:** span `CLIENT` (panggilan keluar) dan span `SERVER` (masuk) adalah **dua
> span berbeda**. Kalau service A memanggil service B, ada 2 span: `A:CLIENT` dan
> `B:SERVER`. Itu normal — janganaggregation jadi satu.

## OpenTelemetry: auto-instrumentation

### Java (Spring Boot)

```bash
# download agent
curl -L -o opentelemetry-javaagent.jar \
  https://github.com/open-telemetry/opentelemetry-java-instrumentation/releases/latest/download/opentelemetry-javaagent.jar

# jalankan dengan agent
java -javaagent:/otel/opentelemetry-javaagent.jar \
  -jar app.jar
```

```bash
export OTEL_SERVICE_NAME=order-service
export OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4317
export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
export OTEL_TRACES_SAMPLER=parentbased_traceidratio
export OTEL_TRACES_SAMPLER_ARG=0.1          # 10% di produksi, 1.0 di dev
export OTEL_PROPAGATORS=tracecontext,baggage
export OTEL_RESOURCE_ATTRIBUTES=service.namespace=pos,deployment.environment=prod
export OTEL_LOGS_EXPORTER=none
```

```yaml
# spring boot — properties yang setara
management:
  tracing:
    sampling:
      probability: 0.1
  otlp:
    tracing:
      endpoint: http://otel-collector:4317
      transport: grpc
```

| Env var | Arti |
| :--- | :--- |
| `OTEL_SERVICE_NAME` | nama service → jadi label `service.name` |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | tujuan span (collector) |
| `OTEL_EXPORTER_OTLP_PROTOCOL` | `grpc` atau `http/protobuf` |
| `OTEL_TRACES_SAMPLER` | `always_on`, `always_off`, `traceidratio`, `parentbased_*` |
| `OTEL_TRACES_SAMPLER_ARG` | rasio sampling (0.1 = 10%) |
| `OTEL_PROPAGATORS` | `tracecontext,baggage` (W3C) |
| `OTEL_RESOURCE_ATTRIBUTES` | atribut resource tambahan |
| `OTEL_JAVAAGENT_LOGGING` | `none`/`simple`/`debug` — cek agent jalan |

> **Jebakan:** agent tidak meng-instrumentasi library yang **di-shadown** (mis. shaded
> JAR). Kalau span service internal tidak muncul, cek apakah artifact-nya shaded.

### Go

```go
import (
    "go.opentelemetry.io/contrib/instrumentation/net/http/otelhttp"
    "go.opentelemetry.io/otel"
    "go.opentelemetry.io/otel/propagation"
    "go.opentelemetry.io/otel/sdk/trace"
    "go.opentelemetry.io/otel/exporters/otlp/otlptrace/otlptracegrpc"
)

func initTracer(ctx context.Context) (func(context.Context) error, error) {
    exp, err := otlptracegrpc.New(ctx,
        otlptracegrpc.WithEndpoint("otel-collector:4317"),
        otlptracegrpc.WithInsecure())
    if err != nil { return nil, err }

    tp := trace.NewTracerProvider(
        trace.WithBatcher(exp),
        trace.WithResource(resource.NewWithAttributes(
            semconv.SchemaURL,
            semconv.ServiceName("order-service"),
        )),
        trace.WithSampler(trace.ParentBased(trace.TraceIDRatioBased(0.1))),
    )
    otel.SetTracerProvider(tp)
    otel.SetTextMapPropagator(propagation.NewCompositeTextMapPropagator(
        propagation.TraceContext{}, propagation.Baggage{}))

    return tp.Shutdown, nil
}

// client: bungkus http.Transport
client := &http.Client{
    Transport: otelhttp.NewTransport(http.DefaultTransport),
}
```

```go
// gRPC interceptor
import "go.opentelemetry.io/contrib/instrumentation/google.golang.org/grpc/otelgrpc"

conn, err := grpc.NewClient(target,
    grpc.WithStatsHandler(otelgrpc.NewClientHandler()),
    grpc.WithStatsHandler(otelgrpc.NewClientHandler()),
)
```

## OpenTelemetry: manual span

```java
// Java — span untuk operasi penting
@Service
@RequiredArgsConstructor
public class PaymentService {

    private final Tracer tracer;   // io.opentelemetry.api.trace.Tracer

    public PaymentResponse charge(ChargeRequest req) {
        Span span = tracer.spanBuilder("chargeCard")
                .setSpanKind(SpanKind.CLIENT)
                .setAttribute("card.id", req.cardId())
                .setAttribute("amount.cents", req.amountCents())
                .startSpan();
        try (Scope scope = span.makeCurrent()) {          // WAJIB: context aktif
            PaymentResponse res = gateway.charge(req);
            span.setAttribute("provider", res.provider());
            return res;
        } catch (Exception e) {
            span.recordException(e);
            span.setStatus(StatusCode.ERROR, e.getMessage());
            throw e;
        } finally {
            span.end();                                   // WAJIB: selalu dipanggil
        }
    }
}
```

```go
// Go — manual span
ctx, span := tracer.Start(ctx, "chargeCard",
    trace.WithSpanKind(trace.SpanKindClient),
    trace.WithAttributes(
        attribute.String("card.id", cardID),
        attribute.Int64("amount.cents", amount),
    ),
)
defer span.End()

if err := pay(ctx, cardID, amount); err != nil {
    span.RecordError(err)
    span.SetStatus(codes.Error, err.Error())
    return err
}
```

| Aturan | Kenapa |
| :--- | :--- |
| `span.end()` selalu dipanggil | span yang tidak ditutup = tidak terkirim |
| `makeCurrent()` / `ctx` diteruskan | child span & context propagation |
| `recordError` + `SetStatus(ERROR)` | error harus **terlihat** di UI |
| `SetAttribute` low-cardinality | atribut jadi index di storage |
| Jangan buat span di loop per item | ribuan span per request |

## Semantik span & atribut

```java
// span kinds
span.setSpanKind(SpanKind.SERVER);     // menerima request
span.setSpanKind(SpanKind.CLIENT);     // memanggil service lain
span.setSpanKind(SpanKind.PRODUCER);   // publish message
span.setSpanKind(SpanKind.CONSUMER);   // consume message
```

| Atribut semantik | Isi |
| :--- | :--- |
| `http.request.method` | `GET` |
| `http.response.status_code` | `200` |
| `url.path` | `/api/orders/8821` (**template**, bukan nilai sebenarnya) |
| `server.address` | `order-service` |
| `db.system.name` | `postgresql` |
| `db.query.text` | query (hati-hati: bisa berisi data sensitif) |
| `messaging.system` | `kafka` |
| `messaging.destination.name` | topic |
| `rpc.service` / `rpc.method` | `OrderService` / `CreateOrder` |

| Aturan | Alasan |
| :--- | :--- |
| Maks ~15 atribut per span | storage & biaya |
| **Jangan** masukkan PII / token / password | span dikirim ke storage |
| ID (order/user) sebagai atribut | boleh, tapi jangan sebagai label metrik |
| `db.statement` tanpa nilai parameter | jangan bocorkan data |
| `exception.message` | boleh, tapi potong bila panjang |

## W3C trace context & propagation

```
traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
             ^^  ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^  ^^^^^^^^^^^^^^^^^^  ^^
          version      trace-id (32 hex)        span-id (16 hex)    flags
```

```bash
# header yang dikirim service
curl -H "traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01" \
     http://localhost:8080/api/orders
```

| Header | Arti |
| :--- | :--- |
| `traceparent` | W3C trace context (standar sekarang) |
| `tracestate` | vendor-specific state, ikut diteruskan |
| `baggage` | key-valuearbitrary, ikut ke semua span |
| `b3` | B3 lama (JAEGER) — jangan pakai untuk sistem baru |

```java
// propagasi otomatis via agent / Micrometer
// context dari HTTP header → span baru jadi child
```

| Aturan | Alasan |
| :--- | :--- |
| Trace context **harus** lewat network | tanpa ini, trace putus di batas service |
| B3 hanya untuk kompatibilitas lama | W3C = standard |
| Baggage **kecil** | ikut di semua request, menambah ukuran header |
| Header tidak boleh dipercaya begitu saja | hop di tengah bisa memalsukan trace id |

## Sampling: head, tail, parent-based

```yaml
# OTel Collector — tail sampling (keputusan setelah span selesai)
processors:
  tail_sampling:
    decision_wait: 10s            # tunggu span selesai
    policies:
      - name: errors
        type: status_code
        status_code: { status_codes: [ERROR] }
      - name: slow
        type: latency
        latency: { threshold_ms: 1000 }
      - name: baseline
        type: probabilistic
        probabilistic: { sampling_percentage: 5 }
    # composisi: keep kalau salah satu policy match
```

| Strategi | Cara | Kapan |
| :--- | :--- | :--- |
| Head (SDK) | `OTEL_TRACES_SAMPLER_ARG=0.1` | murah, tapi error bisa terlewat |
| Head parent-based | `parentbased_traceidratio` | **default terbaik** — anak ikut induk |
| Tail (collector) | collector memutuskan setelah span selesai | tepat untuk "simpan semua error + 1% sukses" |

| Trade-off | Head | Tail |
| :--- | :--- | :--- |
| Biaya | minimal | span tetap dikirim ke collector |
| Error_rate | bisa 0 | **terlihat** (semua error disimpan) |
| Trace lengkap | mungkin bolong | utuh untuk yang disimpan |

> **Jebakan:** memakai head sampling `always_on` di produksi = **seluruh traffic** masuk
> storage → biaya meledak. Minimal: `parentbased_traceidratio` 0.01–0.1, atau tail
> sampling di collector.

## Arsitektur Jaeger

```
App ──OTLP──▶ OTel Collector ──▶ Jaeger Collector ──▶ Ingester ──▶ Storage
                    │                                            (badger/ES/Cassandra/ClickHouse)
                    └── tail sampling (bisa di collector)
App ──jaeger-agent──▶ Jaeger Collector (untuk trace lama via UDP/thrift)
```

| Komponen | Tugas | Catatan |
| :--- | :--- | :--- |
| Jaeger Collector | terima span, sampling, batch | bisa digantikan OTel Collector |
| Jaeger Query | serving UI + API | baca dari storage |
| Jaeger Ingester | batch span ke storage | streaming |
| Agent | sidecar, kirim via UDP | hanya untuk SDK lama (jaeger-client) |
| All-in-One | collector+query+ingester dalam 1 pod | untuk dev & cluster kecil |

**Jaeger v2** (2024+) dibangun di atas **OTel Collector**: pipeline/distribution lewat
collector OTel, storage lewat driver (`badger`, `elasticsearch`, `clickhouse`).

## Deployment

```yaml
# jaeger-all-in-one (dev / cluster kecil)
apiVersion: apps/v1
kind: Deployment
metadata:
  name: jaeger
  namespace: monitoring
spec:
  replicas: 1
  selector:
    matchLabels: { app: jaeger }
  template:
    metadata:
      labels: { app: jaeger }
    spec:
      containers:
        - name: jaeger
          image: jaegertracing/jaeger:2.6.0
          env:
            - name: COLLECTOR_OTLP_ENABLED
              value: "true"
            - name: SPAN_STORAGE_TYPE
              value: badger
            - name: BADGER_EPHEMERAL
              value: "false"
            - name: MEMORY_MAX_TRACES
              value: "50000"
          ports:
            - { name: otlp-grpc, containerPort: 4317 }
            - { name: otlp-http, containerPort: 4318 }
            - { name: query, containerPort: 16686 }
          readinessProbe:
            httpGet: { path: /, port: 16686 }
            initialDelaySeconds: 5
          livenessProbe:
            httpGet: { path: /, port: 16686 }
            initialDelaySeconds: 15
          volumeMounts:
            - { name: badger, mountPath: /badger/data }
      volumes:
        - name: badger
          persistentVolumeClaim:
            claimName: jaeger-badger
```

```yaml
# OTel Collector — ekspor ke Jaeger
exporters:
  otlp/jaeger:
    endpoint: jaeger-collector:4317
    tls:
      insecure: true

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [memory_limiter, batch, tail_sampling]
      exporters: [otlp/jaeger]
```

> **Jebakan:** Jaeger All-in-One dengan storage `memory` → **semua trace hilang saat
> restart**. Untuk produksi pakai `badger` (dengan PVC) atau `elasticsearch`/`clickhouse`.

## Query API & UI

```bash
# cari trace by service
curl -s "http://localhost:16686/api/traces?service=order-service&limit=20" \
  | jq '.data[] | {traceID, spans: (.spans|length), duration: .duration}'

# trace by id
curl -s "http://localhost:16686/api/traces/4bf92f3577b34da6a3ce929d0e0e4736" \
  | jq '.data[0].spans | sort_by(.duration) | reverse | .[0:5] | .[] | {operationName, duration}'

# span paling lambat
curl -s "http://localhost:16686/api/traces?service=order-service&lookback=1h&limit=20" \
  | jq '[.data[].spans[] | {op: .operationName, ms: (.duration/1000)}] | sort_by(-.ms) | .[0:10]'

# service & dependency
curl -s http://localhost:16686/api/services | jq -r '.data[]'
curl -s http://localhost:16686/api/dependencies | jq '.data[0].dependencies'

# span dengan error
curl -s "http://localhost:16686/api/traces?service=order-service&tags=%7B%22error%22%3Atrue%7D&limit=20" \
  | jq '.data | length'
```

| Param API | Arti |
| :--- | :--- |
| `service` | filter nama service |
| `operation` | filter nama operation (span) |
| `tags` | filter `key=value` (JSON-encoded) |
| `lookback` | `1h`, `24h` |
| `minDuration` / `maxDuration` | filter durasi (ms) |
| `limit` | jumlah trace |
| `start` / `end` | rentang epoch (mikrodetik) |

**UI Jaeger:**
- **Search** → filter service + operation + tags (error=true) + lookback + min-duration.
- **Trace detail** → flame chart; klik span → attributes, events, logs.
- **Find traces** → urutkan by duration untuk cari yang lambat.
- **Dependencies** → peta antar service.
- **Metrics** → RED metrics dari span metrics (v1).

## Korelasi log ↔ trace ↔ metric

```logql
# log → trace: cari di Loki lalu loncat ke Jaeger
{app="order-service"} | json | trace_id="4bf92f3577b34da6a3ce929d0e0e4736"
```

```yaml
# Grafana: derived field dari Loki → link ke Jaeger
derivedFields:
  - name: TraceID
    matcherRegex: "trace_id=(\\w+)"
    url: "$${__value.raw}"
    datasourceUid: jaeger-main
```

```promql
# trace → metric: dari detail trace, "Trace to metrics"
# atau pakai exemplar: dari histogram bucket, klik exemplar → trace
```

```java
// pastikan trace_id masuk ke MDC (span saat ini)
Span span = Span.current();
if (span.getSpanContext().isValid()) {
    MDC.put("trace_id", span.getSpanContext().getTraceId());
}
```

> **Jebakan:** `trace_id` hanya ada di log kalau **span sedang aktif** saat log dicetak.
> Log di luar request (scheduler, startup) tidak punya trace → isi `-` atau UUID sendiri.

## Biaya & kapasitas

| Komponen | Batas default / catatan |
| :--- | --- |
| `MEMORY_MAX_TRACES` | 50.000 trace di memory (all-in-one) |
| `max_traces` (collector) | queue span sebelum flush |
| Storage | badger (ringan), ES/Cassandra/ClickHouse (skala) |
| Span per trace | 10–30 normal; > 100 = instrumentation berlebihan |
| Atribut per span | ~15; lebih dari itu = noise |
| Sampling | 1–10% head, atau tail sampling |

```yaml
# collector: batasi memory & batch
processors:
  memory_limiter:
    check_interval: 1s
    limit_percentage: 75
    spike_limit_percentage: 15
  batch:
    timeout: 5s
    send_batch_size: 512
    send_batch_max_size: 1024

extensions:
  jaeger_storage:
    backends:
      some_storage:
        memory:
          max_traces: 100000
```

> **Jebakan:** queue span penuh (`max_traces`) = span **dibuang** diam-diam. Cek metrik
> `jaeger_collector_queue_size` & `jaeger_receiver_accepted_spans` vs
> `jaeger_receiver_refused_spans`.

## Jebakan (wajib dibaca)

| Jebakan | Gejalanya | Solusinya |
| :--- | :--- | :--- |
| `span.end()` lupa | Span tidak terkirim | `defer span.end()` / try-finally |
| `makeCurrent()` lupa | Child span tidak terhubung | Scope selalu di-close |
| Lupa teruskan `ctx` (Go) | Trace putus antar service | Selalu pass `ctx` |
| `head sampling always_on` | Biaya storage meledak | `parentbased_traceidratio` 0.01–0.1 |
| Span per item dalam loop | Ribuan span per request | Span per operasi |
| Atribut berisi PII/token | Data sensitif tersimpan | Sanitasi sebelum `SetAttribute` |
| `url.path` berisi ID asli | Cardinality & PII | Template path |
| Storage `memory` di produksi | Trace hilang saat restart | badger + PVC, atau ES/ClickHouse |
| B3 dipakai di sistem baru | Tidak kompatibel | W3C `traceparent` |
| Trace context tidak lewat HTTP | Trace putus di batas | Middleware/propagator |
| Queue span penuh | Span dibuang diam-diam | Monitor refused_spans, naikkan max_traces |
| Trace ID tidak masuk log | Tidak bisa korelasi | MDC + filter |
| Satu span untuk semua operasi | Tidak ada granularity | Pecah per boundary |
| `db.statement` mentah | Bocor data | Parameterize |
