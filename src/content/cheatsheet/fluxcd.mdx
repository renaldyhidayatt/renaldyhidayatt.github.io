# FluxCD — Cheat Sheet

> Target: **FluxCD 2.9** with the GitOps Toolkit API: `source.toolkit.fluxcd.io/v1`
> (GitRepository, OCIRepository, HelmRepository), `kustomize.toolkit.fluxcd.io/v1`
> (Kustomization), `helm.toolkit.fluxcd.io/v2` (HelmRelease),
> `notification.toolkit.fluxcd.io/v1` (Alert, Provider, Receiver), and image automation v1.
> Used as an ArgoCD alternative for clusters that need per-object **drift detection**,
> **OCI artifacts**, and built-in **image automation**.

## Mental model 5 menit

| Concept | Summary |
| :--- | :--- |
| Flux = a set of controllers, not 1 application | source-controller, kustomize-controller, helm-controller, notification-controller, image-reflector-controller, image-automation-controller |
| Source | artifact from Git/OCI/Bucket → stored in the cluster as an Artifact |
| Kustomization | pipeline: fetch → decrypt → build → validate → apply → health check |
| HelmRelease | a Helm chart that gets reconciled (not `helm install`) |
| Reconciliation | controller pulls state → applies → reports status |
| Drift | the difference between what was applied and what is in the cluster |
| Artifact | the result of a source fetch (immutable, lives in the cluster) |
| Suspend | stop reconciliation without deleting resources |
| `dependsOn` | order between Kustomizations (wait for Ready) |
| Prune | delete resources missing from the source |
| Interval | reconciliation frequency (min 60 seconds) |
| Notification | Alert → Provider → Receiver (event → webhook) |

## Architecture & controllers

```
source-controller      → fetch Git/OCI/Helm chart → Artifact
kustomize-controller   → Artifact + Kustomize → apply ke cluster
helm-controller        → Artifact + HelmRelease → apply ke cluster
notification-controller→ Alert event → Provider → Receiver
image-reflector-controller → tags & digests from the registry
image-automation-controller → update image ref di Git
```

| Controller | CRDs it manages |
| :--- | :--- |
| `source-controller` | GitRepository, OCIRepository, HelmRepository, HelmChart, Bucket |
| `kustomize-controller` | Kustomization |
| `helm-controller` | HelmRelease |
| `notification-controller` | Alert, Provider, Receiver |
| `image-reflector-controller` | ImageRepository, ImagePolicy |
| `image-automation-controller` | ImageUpdateAutomation |

> Flux is **not** monolithic like ArgoCD: each controller can be scaled & restarted
> on its own, and reconcile state is stored in Kubernetes (not in an internal database).

## CLI flux

```bash
# install
curl -s https://fluxcd.io/install.sh | sudo bash
brew install fluxcd/tap/flux
# in a container:
docker run -it --entrypoint sh -v ~/.kube/config:/kubeconfig ghcr.io/fluxcd/flux-cli:v2.9.0

# check
flux version
flux check --pre
flux check                    # prerequisites / installed controllers

# sources & targets
flux get sources all
flux get kustomizations
flux get helmreleases
flux get all
flux tree kustomization order-service      # Kustomization dependencies

# manual reconcile
flux reconcile source git pos
flux reconcile kustomization order-service
flux reconcile helmrelease podinfo

# suspend / resume
flux suspend kustomization order-service
flux resume kustomization order-service

# diff & local build
flux diff kustomization order-service
flux build kustomization ./manifests/order-service
flux build artifact ./manifests/order-service

# events & logs
flux events --for Kustomization/order-service
flux events --for HelmRelease/podinfo --watch
flux logs

# export (yaml CRD)
flux export kustomization order-service
flux export source git pos

# trace a single request
flux trace --kind Kustomization --name order-service
```

| Command | Use when |
| :--- | :--- |
| `flux get all` | quick audit of all resources |
| `flux tree kustomization` | see dependencies & order |
| `flux reconcile` | force a sync now (without waiting for the interval) |
| `flux diff kustomization` | what will change before applying |
| `flux events --for` | why it is not reconciling (authoritative!) |
| `flux trace` | trace the reconcile of a single resource |
| `flux suspend` | stop reconcile while debugging |

## Bootstrap

```bash
# bootstrap: install controllers + create GitRepository + Kustomization
flux bootstrap git \
  --owner=sanedge \
  --repository=pos-k8s \
  --branch=main \
  --path=clusters/pos \
  --personal=false \
  --token-auth=false \
  --silent
```

```bash
# or manually
flux install --export > flux-system.yaml
kubectl apply -f flux-system.yaml
kubectl -n flux-system wait --for=condition=ready pod --all --timeout=5m

flux create source git pos \
  --url=ssh://git@github.com/sanedge/pos-k8s.git \
  --branch=main \
  --secret-ref=git-auth \
  --interval=5m

flux create kustomization pos \
  --source=pos \
  --path="./clusters/pos" \
  --prune=true \
  --interval=10m \
  --health-check="Deployment/order-service" \
  --health-check="Deployment/api-gateway" \
  --timeout=5m
```

## GitRepository (source API v1)

```yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: GitRepository
metadata:
  name: pos
  namespace: flux-system
spec:
  interval: 5m
  url: ssh://git@github.com/sanedge/pos-k8s.git
  ref:
    branch: main
  ignore: |
    # ignore certain paths while scanning for changes
    #!/.*\.md$
    #!/README\.md$
  secretRef:
    name: git-auth
  verify:
    mode: public-key                # public-key | signed | header
  proxySecretRef:
    name: proxy-config
  timeout: 60s
  suspend: false
```

```bash
# create the git secret (deploy key / token)
flux create secret git git-auth \
  --url=ssh://git@github.com/sanedge/pos-k8s.git \
  --ssh-key-algorithm=ecdsa \
  --private-key-file=./id_ecdsa

flux create secret git git-auth \
  --url=https://github.com/sanedge/pos-k8s.git \
  --username=git \
  --password=$(cat token.txt)
```

| Field | Meaning |
| :--- | :--- |
| `interval` | fetch frequency (min 60s) |
| `ref` | branch / tag / commit / semver |
| `ignore` | path regex ignored during change detection |
| `secretRef` | credentials (SSH key, token) |
| `verify.mode` | `public-key` (recommended), `signed`, `header` |
| `reconcileStrategy` | `Revision` (default) or `Retries` |

## Kustomization (kustomize API v1)

```yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: order-service
  namespace: flux-system
spec:
  interval: 10m
  path: ./deployments/kubernetes/base/order-service
  prune: true
  wait: true                      # wait for all resources to be ready
  timeout: 5m
  retryInterval: 1m
  targetNamespace: pos
  sourceRef:
    kind: GitRepository
    name: pos
    # namespace: shared           # cross-namespace reference
  dependsOn:
    - name: infra-postgres        # wait for another Kustomization to be Ready
  healthChecks:
    - apiVersion: apps/v1
      kind: Deployment
      name: order-service
      namespace: pos
  healthCheckExprs:
    - apiVersion: bitnami.com/v1alpha1
      kind: SealedSecret
      failed: status.conditions.filter(e, e.type == 'Synced').all(e, e.status == 'False')
      current: status.conditions.filter(e, e.type == 'Synced').all(e, e.status == 'True')
  postBuild:
    substitute:
      cluster_env: "prod"
    substituteFrom:
      - kind: ConfigMap
        name: cluster-vars
        optional: true
    substituteStrategy: Always
  decryption:
    provider: sops
    secretRef:
      name: sops-keys
  commonMetadata:
    labels: { managed-by: flux }
  images:
    - name: superapp/order-service
      newTag: v1.4.2
  ignore:
    - paths: ["/spec/replicas"]    # let the HPA own it
      target: { kind: Deployment }
```

| Field | Meaning | Pitfall |
| :--- | :--- | :--- |
| `prune` | delete resources missing from the source | `false` → orphaned resources pile up |
| `wait` | wait for all resources to be ready | `healthChecks` end up ignored |
| `dependsOn` | order between Kustomizations | circular dependency = never applies |
| `healthChecks` | check a Deployment rollout | wrong name = endless timeout |
| `healthCheckExprs` | custom logic (CEL) | wrong expression = waits until timeout |
| `postBuild.substitute` | `${var}` variables | only runs if a variable exists (or `substituteStrategy: Always`) |
| `decryption` | SOPS for Secrets | only supported provider: `sops` |
| `targetNamespace` | target namespace | is **not** created automatically |
| `deletionPolicy` | `Mirror` (default), `Delete`, `WaitForTermination`, `Orphan` | `Delete` = resources vanish when the CR is deleted |

> **Pitfall:** `targetNamespace` is **not** created automatically — it must exist in the
> source or be created manually. `postBuild.substitute` only runs if at least one variable
> is available; if not, use `substituteStrategy: Always`.

## HelmRelease (helm API v2)

```yaml
apiVersion: helm.toolkit.fluxcd.io/v2
kind: HelmRelease
metadata:
  name: podinfo
  namespace: flux-system
spec:
  interval: 5m
  timeout: 5m
  chart:
    spec:
      chart: podinfo
      version: "6.x"
      sourceRef:
        kind: HelmRepository
        name: podinfo
        namespace: flux-system
  install:
    remediation:
      retries: 3
  upgrade:
    remediation:
      retries: 3
    cleanupOnFail: true
  rollback:
    cleanupOnFail: true
    timeout: 5m
  values:
    replicaCount: 2
    resources:
      limits: { cpu: 500m, memory: 256Mi }
  valuesFrom:
    - kind: ConfigMap
      name: podinfo-values
      valuesKey: values.yaml
    - kind: Secret
      name: podinfo-secret
      valuesKey: values.yaml
  dependsOn:
    - name: ingress-nginx
```

```yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: HelmRepository
metadata:
  name: podinfo
  namespace: flux-system
spec:
  interval: 5m
  url: https://stefanprodan.github.io/podinfo
```

| Field | Meaning |
| :--- | :--- |
| `chart.sourceRef` | HelmRepository / GitRepository / Bucket |
| `install.remediation` | automatic rollback if install fails |
| `upgrade.remediation` | rollback if upgrade fails |
| `upgrade.cleanupOnFail` | clean up the resources of the failed release |
| `values` | inline values |
| `valuesFrom` | values from ConfigMap/Secret |

## Notifications (notification API v1)

```yaml
apiVersion: notification.toolkit.fluxcd.io/v1
kind: Provider
metadata:
  name: slack
  namespace: flux-system
spec:
  type: slack
  address: https://hooks.slack.com/services/xxx
---
apiVersion: notification.toolkit.fluxcd.io/v1
kind: Alert
metadata:
  name: pos
  namespace: flux-system
spec:
  providerRef:
    name: slack
  eventSeverity: info
  eventSources:
    - kind: GitRepository
      name: "*"
    - kind: Kustomization
      name: "*"
  eventTypes:
    - ready
    - not-ready
  exclusionList:
    - "waiting for.*"
  suspend: false
```

| Event | When |
| :--- | :--- |
| `ready` | the resource reconciled successfully |
| `not-ready` | failed / timeout |
| `info` | general information (reconcile started) |
| `severity` | only what needs attention |

## Image automation

```yaml
apiVersion: image.toolkit.fluxcd.io/v1
kind: ImageRepository
metadata:
  name: order-service
  namespace: flux-system
spec:
  interval: 10m
  image: ghcr.io/sanedge/order-service
  provider: generic
  secretRef:
    name: regcred
---
apiVersion: image.toolkit.fluxcd.io/v1
kind: ImagePolicy
metadata:
  name: order-service
  namespace: flux-system
spec:
  imageRepositoryRef:
    name: order-service
  latest: true                       # or a semver range
  filterTags:
    - "semver:*"
---
apiVersion: image.toolkit.fluxcd.io/v1
kind: ImageUpdateAutomation
metadata:
  name: order-service
  namespace: flux-system
spec:
  imageRef:
    name: order-service
  update:
    kind: GitRepository
    imageRepositoryRef:
      name: order-service
    commit:
      author: fluxcdbot
      message: 'Update image'
  writeBack:
    method: annotation                 # annotation | patch
```

| Field | Meaning |
| :--- | :--- |
| `ImagePolicy.latest` | take the newest tag |
| `filterTags` | filter tags (e.g. only `semver:*`) |
| `ImageUpdateAutomation.update` | write target (Git) |
| `writeBack.method` | `annotation` (safe) or `patch` (overwrites the file) |

## Reconciling, drift & suspend

```bash
flux get kustomizations
# NAME             READY   MESSAGE
# order-service   True    Applied revision: main@sha1:abc123

flux events --for Kustomization/order-service
flux reconcile source git pos --with-source
flux suspend kustomization order-service    # stop reconciling
flux resume kustomization order-service
```

```yaml
spec:
  suspend: true       # resource is not reconciled, but stays in the cluster
```

| Status | Meaning |
| :--- | :--- |
| `Ready: True` | success |
| `Ready: False` | failure — see `message` |
| `Stalled: True` | reconcile has stopped completely (resource does not exist) |
| `Reconciling` | in progress |

> Flux **fixes drift** by default (reconcile = apply the desired state).
> If certain fields must not be reverted, use `spec.ignore` with `target` —
> **always** scope it with `target`, never globally.

## OCI artifacts & promotion

```bash
# push & tag an OCI artifact (not an image!)
flux push artifact oci://ghcr.io/sanedge/manifests/order-service \
  --path=./deployments/kubernetes/base/order-service \
  --source="$(git rev-parse HEAD)" \
  --path=./manifests

flux tag artifact oci://ghcr.io/sanedge/manifests/order-service:staging \
  --tag=production
```

```yaml
apiVersion: source.toolkit.fluxcd.io/v1
kind: OCIRepository
metadata:
  name: pos-artifacts
  namespace: flux-system
spec:
  interval: 5m
  url: oci://ghcr.io/sanedge/manifests
  ref:
    tag: production
  secretRef:
    name: regcred
---
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: order-service
  namespace: flux-system
spec:
  sourceRef:
    kind: OCIRepository
    name: pos-artifacts
  path: ./order-service
  prune: true
```

> **Pitfall:** OCI artifacts are stored in the **registry**, not in the cluster. A cluster
> without registry access → `Kustomization` fails. Lightweight & bandwidth-friendly, but
> it needs a stable registry.

## SOPS & SealedSecrets

```yaml
# Flux: decryption provider sops
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: order-service
  namespace: flux-system
spec:
  decryption:
    provider: sops
    secretRef:
      name: sops-keys
```

```bash
# encrypt before committing
sops --encrypt --encrypted-regex '^(data|stringData)$' \
  --in-place secrets/order-service.yaml

# age key for Flux (.agekey suffix)
flux create secret sops sops-keys --kubeconfig=...  # or manually
```

```yaml
# SealedSecrets (alternative) — separate CRD
apiVersion: bitnami.com/v1alpha1
kind: SealedSecret
metadata:
  name: order-service-secrets
  namespace: pos
spec:
  encryptedData:
    DB_PASSWORD: AgBy...
  template:
    metadata:
      name: order-service-secrets
```

| Approach | Notes |
| :--- | :--- |
| SOPS | Flux decrypts itself; encrypted files in Git |
| SealedSecrets | CRD; a controller decrypts in the cluster |
| External Secrets | Integration with Vault/AWS/GCP |

## Multi-cluster & RBAC

```yaml
# Kustomization applying to a remote cluster (kubeConfig)
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: order-service
  namespace: apps
spec:
  kubeConfig:
    configMapRef:
      name: kubeconfig           # workload identity, no static kubeconfig
  serviceAccountName: apps-sa   # for impersonation in the target cluster
```

| Mechanism | Description |
| :--- | :--- |
| `kubeConfig.secretRef` | static kubeconfig in a Secret (same namespace) |
| `kubeConfig.configMapRef` | **recommended** — secretless via workload identity |
| `serviceAccountName` | SA impersonation in the target cluster |
| `spec.dependsOn[].readyExpr` | CEL expression for dependency readiness |

## Pitfalls (must read)

| Pitfall | Symptom | Solution |
| :--- | :--- | :--- |
| `interval` < 60s | Rejected by the controller (min 60s) | Use ≥ 1m |
| `targetNamespace` missing | Apply fails | Create the namespace in the source or manually |
| `prune: false` | Orphaned resources pile up & keep running | Set `prune: true` |
| `wait: true` + `healthChecks` | `healthChecks` are ignored | Pick one |
| Wrong `healthCheckExprs` | Waits until timeout | Test the expression in the CEL Playground |
| Circular `dependsOn` | Never applies | Check `flux tree kustomization` |
| SOPS without `decryption` | Secret is applied in encrypted form | Add `spec.decryption.provider: sops` |
| `postBuild.substitute` without variables | Substitution is skipped | Set `substituteStrategy: Always` |
| `spec.ignore` without `target` | Every resource loses that field | **Always** scope it with `target` |
| Image Update writes to `main` | Deploy without review | Write to a dedicated branch + PR |
| `latest` tag in ImagePolicy | Unexpected updates | Use a `semver` range |
| OCI artifact unreachable | Reconcile fails | Make sure the registry is reachable |
| Plaintext secret commit | Secrets leak | SOPS / SealedSecrets |
| `flux reconcile` masks the problem | The real problem stays hidden | Read `flux events` first |
| Upgrading the controller without reading release notes | Fields change | Read the changelog before upgrading |
| Ingress & service out of sync | 404 on deploy | One Kustomization for both |
