# Grafana — Cheat Sheet

> Target: **Grafana 11.x** with datasources **Prometheus** (metrics), **Loki** (logs), and
> **Jaeger** (traces), used for visualizing all platforms (E-Commerce, POS, Payment Gateway).
> Dashboards are managed as JSON files in the repo and *provisioned* into the cluster. All snippets
> below are used in the repo and **verified**.

**What's in this sheet**

## Mental model

```
Datasource ──query──▶ Panel ──render──▶ Dashboard ──browse──▶ Viewer
     ▲                   │
     └── dashboard JSON ─┘ (stored in Git, provisioned into the cluster)
```

| Concept | Meaning |
| :--- | :--- |
| Datasource | connection to a data source (Prometheus, Loki, Jaeger, SQL) |
| Dashboard | a set of panels + variables + layout, stored as JSON |
| Panel | a single visualization (timeseries, stat, table, …) |
| Target | a query inside a panel (can be many) |
| Variable | a parameter used in queries (namespace, pod, service) |
| Transformation | transforms query results before rendering |
| Folder | a grouping of dashboards |
| Provisioning | Grafana loads dashboards/datasources from files on start |
| Alert rule | evaluated by Grafana (or Prometheus) → contact point |

> Why dashboards as **JSON files in Git** instead of saved via the UI? Because what's saved
> in the UI can change without review and is lost on reinstall. Files in Git = versioned,
> reviewed, and rollback-able.

## Dashboard JSON structure

```json
{
  "uid": "order-service",
  "title": "Super App — Order Service",
  "description": "Request rate, latency, errors, and dependencies",
  "tags": ["superapp", "backend", "order"],
  "timezone": "utc",
  "editable": true,
  "schemaVersion": 39,
  "version": 7,
  "refresh": "30s",
  "time": { "from": "now-6h", "to": "now" },
  "timepicker": { "refresh_intervals": ["10s", "30s", "1m", "5m", "15m"] },
  "templating": { "list": [] },
  "panels": []
}
```

| Field | Meaning | Pitfall |
| :--- | :--- | :--- |
| `uid` | unique ID, used in URLs & API | **must be** unique & stable (used by links + annotations) |
| `schemaVersion` | format version | bump if imported from the UI |
| `version` | revision | incremented on every save, used for optimistic locking during provisioning |
| `refresh` | auto-refresh | `""` = off |
| `time.from` | default initial range | `now-6h` = last 6 hours |
| `editable` | can be changed from the UI | `false` if you want pure GitOps |
| `tags` | dashboard labels | used for filtering & organizing |
| `links` | links to other dashboards | `type: dashboard` |

```json
{
  "panels": [
    {
      "id": 1,
      "type": "timeseries",
      "title": "Request Rate by Status",
      "datasource": { "type": "prometheus", "uid": "prometheus-main" },
      "gridPos": { "h": 8, "w": 12, "x": 0, "y": 0 },
      "fieldConfig": {
        "defaults": {
          "unit": "reqps",
          "min": 0,
          "custom": { "drawStyle": "line", "lineWidth": 2, "fillOpacity": 10 }
        },
        "overrides": []
      },
      "targets": [
        {
          "refId": "A",
          "datasource": { "type": "prometheus", "uid": "prometheus-main" },
          "expr": "sum by (status) (rate(http_server_requests_total{job=\"$job\"}[$__rate_interval]))",
          "legendFormat": "{{status}}",
          "instant": false,
          "range": true
        }
      ],
      "options": { "legend": { "displayMode": "list", "placement": "bottom" } }
    }
  ]
}
```

## Panels & query targets

| Panel type | For |
| :--- | --- |
| `timeseries` | timeline (default for metrics) |
| `stat` | big number (single value) |
| `gauge` | value against a range (percentage) |
| `bar` / `barchart` | category comparison |
| `table` | tabular data (column formatting) |
| `heatmap` | 2-dimensional correlation (latency × status) |
| `logs` | log panel (Loki) |
| `traces` | trace panel (Jaeger/Tempo) |
| `candlestick` | OHLC |
| `text` | markdown/notes |
| `alertlist` | list of active alerts |
| `row` | panel grouping (collapse) |

```json
{
  "type": "table",
  "title": "Top 10 Slowest Endpoints",
  "transformations": [
    { "id": "organize", "options": { "excludeByName": { "Time": true, "__name__": true } } }
  ],
  "fieldConfig": {
    "defaults": { "unit": "s", "decimals": 3 },
    "overrides": [
      { "matcher": { "id": "byName", "options": "Value" },
        "properties": [{ "id": "custom.cellOptions", "value": { "type": "color-text" } }] }
    ]
  },
  "targets": [{
    "refId": "A",
    "format": "table",
    "instant": true,
    "expr": "topk(10, sum by (path) (rate(http_server_request_duration_seconds_sum[5m]) / rate(http_server_request_duration_seconds_count[5m])))"
  }]
}
```

| Target element | Meaning |
| :--- | :--- |
| `refId` | "A", "B" — connects targets within the same panel |
| `expr` | query (Prometheus) |
| `legendFormat` | label pattern (`{{status}}`, `{{pod}}`) |
| `instant` | `true` = query "now" (not a range) — required for tables |
| `range` | time-range query |
| `format` | `time_series`, `table`, `heatmap` |
| `datasource.uid` | **UID**, not the name (Grafana 9+) |

> **Pitfall:** `datasource` is written as `{"type": "prometheus", "uid": "..."}` — if you use
> the **name** ("Prometheus"), provisioning fails silently when the name changes.

## Template variables

```json
{
  "templating": {
    "list": [
      {
        "name": "namespace",
        "label": "Namespace",
        "type": "query",
        "datasource": { "type": "prometheus", "uid": "prometheus-main" },
        "definition": "label_values(kube_pod_info, namespace)",
        "query": { "query": "label_values(kube_pod_info, namespace)", "refId": "StandardVariableQuery" },
        "refresh": 2,
        "includeAll": true,
        "multi": true,
        "allValue": ".*",
        "current": { "text": "All", "value": "$__all" },
        "options": []
      },
      {
        "name": "pod",
        "label": "Pod",
        "type": "query",
        "datasource": { "type": "prometheus", "uid": "prometheus-main" },
        "definition": "label_values(kube_pod_info{namespace=~\"$namespace\"}, pod)",
        "query": { "query": "label_values(kube_pod_info{namespace=~\"$namespace\"}, pod)", "refId": "StandardVariableQuery" },
        "includeAll": true,
        "multi": true,
        "allValue": ".*"
      },
      {
        "name": "datasource",
        "type": "datasource",
        "query": "prometheus",
        "hide": 0
      },
      {
        "name": "interval",
        "type": "interval",
        "query": "30s",
        "auto": true,
        "auto_min": "10s"
      },
      {
        "name": "env",
        "type": "custom",
        "query": "prod,staging",
        "current": { "text": "prod", "value": "prod" }
      }
    ]
  }
}
```

| Type | Function |
| :--- | --- |
| `query` | from a datasource (label_values, metric query, or Loki query) |
| `custom` | manual list (comma separated) |
| `interval` | time range (`$__interval`, `$__rate_interval`) |
| `datasource` | pick a datasource (for multi-source dashboards) |
| `constant` | fixed value, hidden |
| `textbox` | free-form input from the user |
| `adhoc` | free-form filter (key + operator + value) |

| Important option | Meaning |
| :--- | :--- |
| `includeAll` | show the "All" option |
| `allValue` | value used when All is selected (`.*`) |
| `multi` | allows selecting several |
| `refresh` | `1` = when the dashboard opens, `2` = when the variable changes |
| `hide` | `0` visible, `1` = hide label, `2` = hide entirely |
| `definition` | query text (for display), `query` = the actual query |

```promql
# use variables in queries
sum by (pod) (rate(http_server_requests_total{namespace=~"$namespace", pod=~"$pod"}[$__rate_interval]))
```

> **Pitfall:** nested variables must use regex, not `=`:
> `namespace=~"$namespace"` (not `namespace="$namespace"`), because the value can be
> `prod|staging`.

## Transformations

```json
{
  "transformations": [
    { "id": "filter", "options": { "filters": [] } },
    { "id": "groupBy", "options": { "fields": { "Name": { "aggregations": [], "operation": "groupby" } } } },
    { "id": "calculateField", "options": { "alias": "error_ratio", "mode": "binary", "binary": { "left": "errors", "operator": "/", "right": "total" } } },
    { "id": "renameByRegex", "options": { "renamePattern": "(.*)_total", "renamePatternFormat": "PLAIN" } },
    { "id": "organize", "options": { "excludeByName": { "Time": true } } },
    { "id": "joinByField", "options": { "byField": "orderId", "mode": "outer" } },
    { "id": "addFieldFromCalculation", "options": { "mode": "binary", "alias": "ratio" } },
    { "id": "labelsToFields", "options": { "mode": "columns" } },
    { "id": "reduce", "options": { "reducers": ["lastNotNull"] } }
  ]
}
```

| Transformation | Use |
| :--- | :--- |
| `filter` | filter rows (e.g. only 5xx status) |
| `groupBy` | group rows |
| `calculateField` | compute a new column (ratio) |
| `renameByRegex` / `renameByName` | clean up column names |
| `organize` | hide/reorder columns |
| `joinByField` | join two queries (e.g. metrics + logs) |
| `labelsToFields` | turn Prometheus labels into columns |
| `reduce` | collapse rows into a single value |
| `sortBy` | sort |
| `limit` | take the top N |

## Datasources & provisioning

```yaml
# observability/grafana/provisioning/datasources/datasources.yaml
apiVersion: 1
datasources:
  - name: Prometheus
    uid: prometheus-main
    type: prometheus
    access: proxy
    url: http://prometheus:9090
    isDefault: true
    jsonData:
      httpMethod: POST
      timeInterval: 30s
      manageAlerts: true
      prometheusType: Prometheus
      prometheusVersion: 2.50.0
      exemplarTraceIdDestinations:
        - name: trace_id
          datasourceUid: jaeger-main

  - name: Loki
    uid: loki-main
    type: loki
    access: proxy
    url: http://loki:3100
    jsonData:
      maxLines: 1000
      derivedFields:
        - name: TraceID
          matcherRegex: "trace_id=(\\w+)"
          url: "$${__value.raw}"
          datasourceUid: jaeger-main

  - name: Jaeger
    uid: jaeger-main
    type: jaeger
    access: proxy
    url: http://jaeger-query:16686
```

```yaml
# observability/grafana/provisioning/dashboards/dashboards.yaml
apiVersion: 1
providers:
  - name: superapp
    orgId: 1
    folder: Super App
    folderUid: superapp
    type: file
    disableDeletion: false
    allowUiUpdates: false          # dashboards are changed in Git, not in the UI
    updateIntervalSeconds: 30
    options:
      path: /etc/grafana/provisioning/dashboards
      foldersFromFilesStructure: true
```

| Option | Meaning |
| :--- | :--- |
| `uid` | **must be** unique — used by panels & the API |
| `allowUiUpdates` | `false` = UI is read-only (dashboards in Git = source of truth) |
| `disableDeletion` | `true` = dashboard isn't deleted even if the file disappears |
| `updateIntervalSeconds` | Poll files from disk (default 10s) |
| `foldersFromFilesStructure` | folders follow the folder structure on disk |

> **Pitfall:** with `allowUiUpdates: true`, people can change dashboards in the UI and
> those changes are **lost** when the next provisioning pass overwrites the file.

## Dashboard & folder provisioning

```text
observability/grafana/
├── provisioning/
│   ├── dashboards/
│   │   ├── dashboards.yaml       # provider
│   │   └── dashboards/
│   │       ├── order-service.json
│   │       └── payment-gateway.json
│   └── datasources/
│       └── datasources.yaml
```

```yaml
# many dashboards → use one provider + folder structure
apiVersion: 1
providers:
  - name: superapp
    folder: Super App
    type: file
    options:
      path: /etc/grafana/provisioning/dashboards
      foldersFromFilesStructure: true
```

```bash
# validate dashboard JSON before committing
jq empty dashboards/order-service.json

# check UIDs are unique across files
jq -r '.uid' dashboards/*.json | sort | uniq -d     # must be empty
```

> **Pitfall (real-world experience):** Grafana folders **cannot** be created via ConfigMap
> *keys* because keys can't contain a slash (`/`). Solved it with `items[].path` +
> an `initContainer` that *resolves* the symlink, or `foldersFromFilesStructure: true`.
> Without that, the provider sees **0 dashboards** even though the files are in the volume.

## Alerting in Grafana

```yaml
# provisioning/alerting/contact-points.yaml
apiVersion: 1
contactPoints:
  - orgId: 1
    name: slack-backend
    receivers:
      - uid: slack-backend-uid
        type: slack
        settings:
          url_file: /etc/grafana/secrets/slack-webhook
          recipient: "#alerts-backend"
          title: "{{ template \"slack.default.title\" . }}"
          text: "{{ template \"slack.default.text\" . }}"
```

```yaml
# provisioning/alerting/policies.yaml
apiVersion: 1
policies:
  - orgId: 1
    receiver: slack-backend
    group_by: ["grafana_folder", "alertname"]
    group_wait: 30s
    group_interval: 5m
    repeat_interval: 4h
    routes:
      - receiver: pagerduty-oncall
        object_matchers: ["severity=critical"]
        continue: false
      - receiver: slack-backend
        object_matchers: ["severity=warning"]
```

| Concept | Meaning |
| :--- | :--- |
| Contact point | notification destination (Slack, PagerDuty, email, webhook) |
| Notification policy | routing: which alerts go where |
| `group_by` | which alerts get batched into one notification |
| `group_wait` | wait before the first notification |
| `repeat_interval` | how often to resend while still firing |
| Silence | temporarily mute alerts (maintenance) |

```promql
# alert rule (Grafana-managed, unified alerting)
sum(rate(http_server_requests_total{job="order-service",status=~"5.."}[5m]))
  / sum(rate(http_server_requests_total{job="order-service"}[5m])) > 0.05
```

> **Pitfall:** `repeat_interval` too small (e.g. 1m) → notification spam when an alert
> flaps. `group_wait` + `group_interval` + `repeat_interval` must increase in tiers.

## Explore & cross-tool integration

```
Explore ── query Loki ──► log lines ──► click trace_id ──► Jaeger trace
   │
   └─── Trace to metrics ──► from a Jaeger span ──► query Prometheus
```

| Integrasi | Cara |
| :--- | --- |
| Loki → Jaeger | `derivedFields` with `matcherRegex` trace_id + `datasourceUid` |
| Jaeger → Prometheus | Trace view → "Trace to metrics" |
| Metrics → Logs | Time series panel → "Explore" → Loki over the same range |
| Dashboard → Dashboard | `links` with `type: dashboard` + variables passed through |
| Logs → Metrics | From a log line, open Explore Prometheus at the same timestamp |

```json
{
  "links": [
    {
      "title": "Loki logs (same window)",
      "type": "link",
      "url": "/explore?left={\"datasource\":\"loki-main\",\"queries\":[{\"expr\":\"{job=~\\\"$job\\\"}\"}]}",
      "targetBlank": true
    }
  ]
}
```

## Query & dashboard performance

| Variable | Meaning |
| :--- | --- |
| `$__interval` | interval computed from panel width (for `$__rate_interval`) |
| `$__rate_interval` | `max($__interval + scrape_interval, 4 × scrape_interval)` — **required** for `rate()` |
| `$__from` / `$__to` | panel start/end timestamps (ms) |

```promql
# DO NOT: fixed interval, doesn't follow zoom
rate(http_server_requests_total[5m])

# DO: follow the panel size
rate(http_server_requests_total[$__rate_interval])
```

| Symptom | Cause | Fix |
| :--- | :--- | --- |
| Slow dashboard | heavy query (not using `$__rate_interval`) | use the interval variable |
| "No data" panel when zooming | rate window too small | `$__rate_interval` |
| Heavy server render | `maxDataPoints` too large | lower `maxDataPoints` |
| Many series | labels not aggregated | `sum by (...)` in the query |
| Dashboard load > 3 seconds | too many panels | split the dashboard, use `row` collapse |

```json
{ "maxDataPoints": 500, "interval": "30s" }
```

```ini
# grafana.ini
[query_cache]
enabled = true
ttl = 5s
[server]
max_connections_per_host = 100
[users]
default_theme = dark
```

## API & automation

```bash
# list dashboards
curl -s -H "Authorization: Bearer $GRAFANA_TOKEN" \
  http://localhost:3000/api/search?type=dash-db | jq '.[] | {title, uid}'

# export a dashboard as JSON
curl -s -H "Authorization: Bearer $GRAFANA_TOKEN" \
  http://localhost:3000/api/dashboards/uid/order-service | jq '.dashboard' > order-service.json

# import / update a dashboard
curl -s -X POST -H "Authorization: Bearer $GRAFANA_TOKEN" \
  -H "Content-Type: application/json" \
  -d @order-service.json \
  http://localhost:3000/api/dashboards/db

# provisioned dashboards → this endpoint is READ-ONLY
curl -s -H "Authorization: Bearer $GRAFANA_TOKEN" \
  http://localhost:3000/api/dashboards/uid/order-service

# health
curl -s http://localhost:3000/api/health
```

| Endpoint | Fungsi |
| :--- | --- |
| `GET /api/search` | cari dashboard/data source/folder |
| `GET /api/dashboards/uid/:uid` | ambil dashboard |
| `POST /api/dashboards/db` | simpan dashboard |
| `GET /api/datasources` | list datasources |
| `GET /api/folders` | list folders |
| `GET /api/annotations` | annotation (event deploy) |

## Pitfalls (must-read)

| Pitfall | Symptom | Solution |
| :--- | :--- | :--- |
| Datasource uses the **name** instead of UID | Provisioning fails silently | Use `uid` |
| `allowUiUpdates: true` | UI changes are lost | `false` + dashboards in Git |
| Folder created as a ConfigMap key | 0 dashboards visible | `items[].path` + symlink resolve, or `foldersFromFilesStructure` |
| `rate()` with a fixed window | Slow on small panels | `$__rate_interval` |
| Variable uses `=` for multi-select | Doesn't match | Use `=~` |
| `allValue` left empty | "All" matches nothing | `allValue: ".*"` |
| `instant: true` forgotten in a table | Empty table | Set `instant` + `format: table` |
| `legendFormat` uses a label that doesn't exist | Empty labels in the legend | Check the real label names |
| Duplicate UID | Dashboards overwrite each other | `jq -r '.uid' *.json \| sort \| uniq -d` |
| Dashboard without `version` | Conflict during provisioning | Bump `version` on every change |
| `refresh` too fast (5s) | Load on Grafana & Prometheus | 30s–1m |
| Alert `repeat_interval` too small | Notification spam | ≥ 1 hour for non-critical |
| Panel `maxDataPoints` too large | Slow render | Lower it to 200–500 |
| JSON imported from the UI without `uid` | Dashboard is unstable | Set `uid` manually |
| Dashboard shows "No data" though the metric exists | Wrong namespace/service filter | Check variables & labels |
