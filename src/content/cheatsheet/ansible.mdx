> Target: **ansible-core 2.17+** on the controller, managed nodes Linux (Debian/Ubuntu/RHEL).

## Concepts & execution flow

```text
controller (laptop/CI)  ──SSH──>  managed node
   ├── inventory.ini         no agent
   ├── playbook.yml          push task, run module (python), discard
   ├── roles/                result: files/config/service on target
   └── group_vars/           state recomputed on every run
```

| Term | Meaning |
| :--- | :--- |
| **Inventory** | list of managed hosts + groups |
| **Playbook** | list of **plays**; one play = target hosts + tasks |
| **Role** | a reusable collection of tasks/templates/handlers |
| **Task** | a single module invocation (idempotent) |
| **Module** | unit of work (`apt`, `template`, `systemd`) |
| **Handler** | a task that only runs when `notify`-ed |
| **Facts** | collected host data (`ansible_facts`) |

Flow of one run: parse inventory → gather facts → run plays per host (parallel, `forks`) →
tasks that are `changed` flag handlers → handlers run at the end of the play.

## Project structure

```text
ansible-project/
├── ansible.cfg                 # default inventory, ssh args, vault password
├── site.yml                    # main playbook
├── inventory/
│   └── production.ini
├── group_vars/
│   ├── all/main.yml            # shared variables
│   ├── all/vault.yml           # secrets (encrypted)
│   └── webservers.yml          # per-group variables
├── host_vars/
│   └── db-01.yml
├── roles/<name>/{defaults,tasks,templates,handlers,meta,vars,files}
├── playbooks/                  # additional playbooks (deploy, maintenance)
└── requirements.yml            # external collections & roles
```

```ini
# ansible.cfg
[defaults]
inventory               = inventory/production.ini
roles_path              = roles
stdout_callback         = default
callback_result_format  = yaml
callbacks_enabled       = profile_tasks
inject_facts_as_vars    = False
host_key_checking       = True
pipelining              = True
forks                   = 10
vault_password_file     = .vault-pass
log_path                = /tmp/ansible.log

[ssh_connection]
ssh_args = -o ControlMaster=auto -o ControlPersist=60s -o StrictHostKeyChecking=accept-new -o IdentitiesOnly=yes
```

```bash
# external dependencies are installed from a file, not manually
cat requirements.yml
# collections: [ { name: community.general }, { name: ansible.posix } ]
ansible-galaxy collection install -r requirements.yml
```

| Option | Effect |
| :--- | :--- |
| `inject_facts_as_vars = False` | follows the ansible-core 2.24 default; use `ansible_facts['x']` |
| `vault_password_file` | no interactive prompt, good for CI |
| `IdentitiesOnly=yes` | other keys in ssh-agent do not exhaust `MaxAuthTries` |
| `StrictHostKeyChecking=accept-new` | new hosts are accepted, **changed** host keys are still rejected |
| `pipelining = True` | faster (no sftp per module); make sure `requiretty` is off |
| `profile_tasks` | show the slowest tasks, useful for long plays |

## Inventory & group_vars

```ini
[all:vars]
ansible_user=deploy
ansible_python_interpreter=/usr/bin/python3
# ansible_ssh_private_key_file=~/.ssh/ansible

[webservers]
web-01 ansible_host=10.10.1.11
web-02 ansible_host=10.10.1.12

[dbservers]
db-01 ansible_host=10.10.1.21 db_role=primary

[staging:children]                # group of groups
webservers
dbservers

[staging:vars]
env=staging
```

```yaml
# group_vars/all/main.yml — common values, NO secrets
timezone: Asia/Jakarta
app_port: 8080
admin_cidr: "10.10.1.0/24"
```

```yaml
# group_vars/webservers.yml
nginx_worker_processes: auto
ufw_rules:
  - { port: "80", from: "{{ admin_cidr }}", comment: "http" }
```

| Item | Rule |
| :--- | :--- |
| `ansible_host` | the real address used by SSH |
| `inventory_hostname` | the logical name (used in templates & logs) |
| Nested groups | child group variables win over the parent |
| `host_vars/` | per-host override — keep exceptions here, not `if` inside tasks |
| Secrets | do not put them in `main.yml`; use a separate vault file |
| `.example` files | convention for values that must not be committed (Ansible does not load them) |

> **Pitfall #1:** a new host that was forgotten from the parent group will not get the common role
> (base packages, NTP, monitoring agent). Always verify with
> `ansible-inventory --graph` after editing the inventory.

## Daily commands (CLI cheat)

```bash
# LOOK first — almost always the first step
ansible-inventory --graph                       # group hierarchy
ansible-inventory --host web-01 --yaml          # effective variables for one host
ansible all -m setup -a 'filter=ansible_distribution*'

# ad-hoc (one module, no playbook)
ansible all -m ping
ansible webservers -m shell -a 'systemctl is-active nginx'
ansible webservers -m command -a 'nginx -v' -b

# playbook
ansible-playbook site.yml --check --diff        # simulation
ansible-playbook site.yml --limit webservers    # a single group
ansible-playbook site.yml --tags nginx          # only tagged tasks
ansible-playbook site.yml --list-tasks          # what will run

# debugging
ansible-playbook site.yml -vvv 2>&1 | tee /tmp/run.log
ANSIBLE_LOG_PATH=/tmp/ansible-debug.log ansible-playbook site.yml
```

| Flag | Function |
| :--- | :--- |
| `--check` | dry-run (tasks without check mode support are skipped) |
| `--diff` | show file/template changes |
| `--limit` | restrict hosts/groups |
| `--list-hosts` / `--list-tasks` | view targets/tasks without running |
| `--start-at-task` | start from a specific task (debugging, not production) |
| `-e` / `--extra-vars` | highest precedence |
| `-b` / `-K` | become (sudo), optionally prompt for sudo password |
| `--tags` / `--skip-tags` | select tagged tasks |
| `--syntax-check` | parse the playbook without connecting |

## Playbook, role, task

```yaml
---
# site.yml — play order = real dependency order
- name: "Base system for all hosts"
  hosts: all
  become: yes
  gather_facts: yes
  roles:
    - common

- name: "Web server"
  hosts: webservers
  become: yes
  gather_facts: no                  # facts not needed -> faster
  roles:
    - nginx

- name: "Deploy aplikasi"
  hosts: webservers
  become: yes
  vars_files:
    - group_vars/all/vault.yml      # values only, not logic
  tasks:
    - name: Render systemd unit
      ansible.builtin.template:
        src: app.service.j2
        dest: /etc/systemd/system/app.service
        mode: '0644'
      notify: Reload systemd
```

```yaml
# roles/nginx/meta/main.yml — explicit dependency
dependencies:
  - role: common
```

```yaml
# roles/common/tasks/main.yml — pattern used consistently
- name: Update apt cache
  ansible.builtin.apt:
    update_cache: yes
    cache_valid_time: 3600          # do not refetch within 1 hour

- name: Set timezone
  community.general.timezone:
    name: "{{ timezone }}"

- name: Deploy SSH configuration
  ansible.builtin.template:
    src: sshd-hardening.conf.j2
    dest: /etc/ssh/sshd_config.d/10-hardening.conf
    mode: '0644'
    validate: 'sshd -t -f %s'       # bad file = task fails, not broken ssh
  notify: Reload sshd
```

| Concept | When to use |
| :--- | :--- |
| `roles:` | one complete role for a host group |
| `include_role` + `tasks_from` | run only a **part** of a role |
| `import_tasks` | static, evaluated at parse time |
| `include_tasks` | dynamic, evaluated at run time (can loop over a variable) |
| `import_playbook` | playbook composition |
| `tags:` | quick run of a specific part while iterating |
| `gather_facts: no` | saves time; requires that facts are not used |

> **Pitfall #2:** `import_*` does not see variables just set by a previous task;
> `include_*` does. If a task file depends on a `set_fact` above it and the result
> is not as expected, swap import → include.

## Variables: precedence & debugging

```text
low     role defaults            roles/x/defaults/main.yml
        inventory group_vars    filter by group
        inventory host_vars     filter by host
        play vars / vars_files
        task vars
        block vars
        set_fact / register
        extra-vars (-e)         <- highest, wins over everything
```

```yaml
# Quick debugging, do not leave in production
- name: Effective variables
  ansible.builtin.debug:
    var: nginx_worker_processes
    verbosity: 1                    # only shown with -v

- name: Compare conditions
  ansible.builtin.debug:
    msg: "host={{ inventory_hostname }} ip={{ ansible_facts['default_ipv4']['address'] }}"
```

```bash
# From outside the playbook — the most honest way to see the final value
ansible-inventory --host web-01 --yaml
ansible-playbook site.yml -vv --check
```

| Aturan | Kenapa |
| :--- | :--- |
| `-e` wins over everything, including `defaults` | useful for overrides; dangerous when used carelessly |
| Do not use play-level `vars:` for values that can change | hard to trace; use group_vars/host_vars |
| `ansible_facts['x']` | global fact variables are no longer complete in newer ansible-core |
| Values from `-e` are strings | compare with `| bool` / `| int` |

> **Pitfall #3:** `when: app_enabled` with `-e app_enabled=false` is still **true** (a non-empty
> string). Always `when: app_enabled | bool`.

## Jinja2 templates

```jinja2
{# Local vs remote host: different URL #}
api_base_url: >-
  http://{{ 'localhost' if inventory_hostname == 'web-01' else ansible_host }}:{{ app_port }}

{# Filter & map, no manual loop #}
upstreams: "{{ groups['webservers'] | map('extract', hostvars, 'ansible_host') | list }}"

{# Safe for a group that may be empty #}
replicas: "{{ groups['replicas'] | default([]) }}"
```

```jinja2
{# templates/nginx-site.conf.j2 #}
upstream app_backend {
{% for host in groups['webservers'] %}
    server {{ hostvars[host].ansible_host }}:{{ app_port }};
{% endfor %}
}

server {
    listen 80;
    server_name {{ inventory_hostname }};
    location / {
        proxy_pass http://app_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

| Filter | Purpose |
| :--- | :--- |
| `map('extract', hostvars, 'ansible_host')` | get the IP of every host in a group |
| `default([])` / `default('x', true)` | fallback value for an empty variable/group |
| `combine()` | merge dicts (override some values) |
| `to_json` / `to_nice_yaml` | render config (JSON/YAML) |
| `bool` / `int` | convert before comparing |
| `regex_replace` | normalize text |
| `omit` | conditionally drop a module parameter |
| `selectattr` / `rejectattr` | filter a list of dicts by field |

> **Pitfall #4:** `template` only writes the file when the content **changes**. If the render result
> depends on fluctuating facts (hostname resolution, IP), the file gets rewritten — and then
> the handler restarts the service. Aggressive handlers = unnecessary downtime.

## Handler & notify

```yaml
# roles/nginx/handlers/main.yml
- name: Reload nginx
  ansible.builtin.systemd:
    name: nginx
    state: reloaded

- name: Reload systemd
  ansible.builtin.systemd:
    daemon_reload: yes
```

```yaml
- name: Deploy nginx configuration
  ansible.builtin.template:
    src: nginx-site.conf.j2
    dest: /etc/nginx/conf.d/site.conf
    validate: 'nginx -t -c %s'
  notify: Reload nginx
```

| Rule | Why |
| :--- | :--- |
| Handler runs **once** at the end of the play even if notified repeatedly | avoid repeated restarts |
| `notify` only when the task is `changed` | keeps idempotency intact |
| `meta: flush_handlers` | force handlers to run before the next task |
| Changes to `listen`/socket need `restarted` | `reloaded` is not enough for some services |
| Handler order = definition order | the handler file structure affects execution order |
| `listen: "restart web stack"` | one notify can trigger many handlers |

> **Pitfall #5:** handlers do **not** run in `--check`. Do not use `--check` to
> confirm a service has restarted — verify separately (`systemctl is-active`, check the port).

## Conditions, loops, facts

```yaml
# Condition — compare the correct types
- name: Install nginx only on web
  ansible.builtin.apt:
    name: nginx
  when:
    - inventory_hostname in groups['webservers']
    - nginx_enabled | bool

# Loop over a dict item
- name: Create application directories
  ansible.builtin.file:
    path: "{{ item.path }}"
    state: directory
    owner: "{{ item.owner }}"
    mode: '0750'
  loop:
    - { path: /opt/app/data, owner: app }
    - { path: /opt/app/logs, owner: app }

# until/retries — poll the condition, not a blind sleep
- name: Wait for the app to be ready
  ansible.builtin.uri:
    url: "http://127.0.0.1:{{ app_port }}/health"
    status_code: 200
  register: health
  retries: 10
  delay: 3
  until: health.status == 200
```

```yaml
# Facts — access through ansible_facts['...']
- ansible.builtin.debug:
    msg: "{{ ansible_facts['distribution'] }} {{ ansible_facts['distribution_version'] }}"

- name: Save result for the next play
  ansible.builtin.set_fact:
    deployed_sha: "{{ lookup('pipe', 'git rev-parse --short HEAD') }}"
```

| Keyword | Note |
| :--- | :--- |
| `register` + `.stdout`, `.rc`, `.changed` | use `stdout_lines` for multi-line output |
| `changed_when: false` | for read-only commands |
| `failed_when` | override success logic (e.g. `rc not in [0, 1]`) |
| `ignore_unreachable: true` | for plays that handle dead hosts |
| `delegate_to` | run the module on another host |
| `run_once: true` | task runs once, result applies to all hosts |
| `throttle` | limit parallelism of heavy tasks |

> **Pitfall #6:** commands like `psql`, `ss`, `docker ps` without `changed_when: false` always
> report `changed` → the second run is not `changed=0` and handlers run for no reason.

## Most frequently used modules

| Need | Module | Note |
| :--- | :--- | :--- |
| Packages | `ansible.builtin.apt` / `dnf` | `cache_valid_time` to save time |
| File/dir/permissions | `ansible.builtin.file` | explicit `mode` required for secrets (`'0600'`) |
| Template | `ansible.builtin.template` | `validate:` before replacing |
| Copy/content | `ansible.builtin.copy` | `content:` for small files |
| Config lines | `ansible.builtin.lineinfile` | `regexp` + `backup: yes` |
| Service | `ansible.builtin.systemd` | `daemon_reload: yes` after changing a unit |
| Timer | `ansible.builtin.systemd` | manage `x.timer`: `state: started`, `enabled: yes` |
| Shell | `ansible.builtin.shell` | needed for pipes/redirects; avoid if a module exists |
| Program | `ansible.builtin.command` | no shell; safer & faster |
| File status | `ansible.builtin.stat` | check before acting |
| Wait | `ansible.builtin.wait_for` | `host`+`port`, or `path`+`search_regex` |
| HTTP test | `ansible.builtin.uri` | `status_code`, `retries`, `until` |
| Assert | `ansible.builtin.assert` | **gate** before dangerous operations |
| SSH key | `ansible.posix.authorized_key` | collection `ansible.posix` |
| Timezone | `community.general.timezone` | collection `community.general` |
| Git | `ansible.builtin.git` | `version:` pin a commit, not a branch |
| User/group | `ansible.builtin.user` / `group` | `system: yes` for service accounts |
| Cron | `ansible.builtin.cron` | `name:` required so it can be changed & removed |

```yaml
# gate pattern: reject dangerous execution before it happens
- name: Confirmation required (destructive operation)
  ansible.builtin.assert:
    that: (confirm | default('')) == 'DROP-AND-REBUILD'
    fail_msg: "Run with -e confirm=DROP-AND-REBUILD"
    quiet: true
```

## Vault & secrets

```bash
# vault password in a gitignored file (or a password manager)
echo 'my-strong-passphrase' > .vault-pass && chmod 600 .vault-pass

ansible-vault create  group_vars/all/vault.yml
ansible-vault edit    group_vars/all/vault.yml
ansible-vault view    group_vars/all/vault.yml
ansible-vault rekey   group_vars/all/vault.yml
ansible-vault encrypt_string --name 'db_password' 'S3cret'   # a single variable only
```

```sh
#!/bin/sh
# .vault-pass.sh — password from macOS Keychain / secret manager, not plaintext
security find-generic-password -a ansible-vault -s my-project -w
```

| Aturan | Kenapa |
| :--- | :--- |
| Secrets only in a separate vault file | easy auditing, not mixed with config values |
| `no_log: true` on tasks that touch secrets | prevents leaking into logs |
| `mode: '0600'` for files containing secrets | the default `0644` leaks to other users |
| Do not put secrets in `-e` | they show up in shell history & process logs |
| Vault variable prefix (`vault_db_password`) is optional but helps auditing | makes it clear which ones are encrypted |
| Rotation: `rekey` then update in the password manager | single source of truth |

> **Pitfall #7:** vault variables accessed in `when:` can fail if the vault is not yet
> decrypted (e.g. in `--check` without a password). Keep only **values** in the vault, not
> condition structure.

## Check mode, diff, and proper dry-run

```bash
# 1. Start with a simulation + diff
ansible-playbook site.yml --check --diff --limit webservers

# 2. Make sure the task list matches expectations before running
ansible-playbook site.yml --list-tasks

# 3. Destructive operations: the confirm= gate is more reliable than --check
ansible-playbook playbooks/reset-app.yml            # without confirm = shows the plan
ansible-playbook playbooks/reset-app.yml -e confirm=RESET-APP
```

```yaml
# Tasks that do not support check mode: tell the reader
- name: Preview command (not executed during --check)
  ansible.builtin.command: app-cli migrate --dry-run
  changed_when: false
  check_mode: true
```

| Attribute | Effect |
| :--- | :--- |
| `check_mode: yes` | force the task to be simulated only |
| `check_mode: no` | force the task to **really run** even with `--check` |
| `diff: yes` | show the diff even when global `--diff` is not used |
| `--step` | confirm each task (manual debugging) |
| `supports_check_mode` | module metadata; `command`/`shell` do not support it |

> **Pitfall #8:** `--check` on a playbook that depends on results of earlier tasks (files that
> have not really been created yet) often produces false errors. For destructive operations, the
> `confirm=` gate (assert) is more trustworthy.

## Idempotency — ground rules

Principle: **run it twice, the second run must be `changed=0`.**

```bash
ansible-playbook site.yml > /tmp/run1.log
ansible-playbook site.yml > /tmp/run2.log
grep -E 'changed=[1-9]' /tmp/run2.log && echo "NOT IDEMPOTENT" || echo "idempotent"
```

| Source of non-idempotency | Fix |
| :--- | :--- |
| read-only `shell`/`command` | `changed_when: false` |
| `command` that sometimes fails normally | `failed_when:` with an explicit condition |
| `lineinfile` without `regexp` | add `regexp` + `line` |
| Timestamp in the filename | `creates:` or `stat` first |
| `shell` that always writes | switch to a native module (`copy`, `template`) |
| `git` without `version` | pin a commit/tag so it does not always fetch |
| `file` without owner/mode | explicit values avoid repeated diffs |
| Seed data always runs | `creates:` / check the result with `stat` |

> **Pitfall #9:** `register` + `when: result.changed` is a classic trap — `changed`
> belongs to the task, not to the environment. Store the decision in an explicit variable.

## Troubleshooting

```bash
# 1. Connectivity
ansible web-01 -m ping -vvv
ssh -i ~/.ssh/ansible -o IdentitiesOnly=yes deploy@web-01

# 2. Wrong / undefined variables
ansible-inventory --host web-01 --yaml | less
ansible-playbook site.yml --limit webservers -vv | grep -n 'nginx_'

# 3. Syntax & lint
ansible-playbook site.yml --syntax-check
ansible-lint site.yml roles/

# 4. On the target: what is actually happening
journalctl -u nginx --no-pager | tail -50
cat /tmp/ansible.log | tail -100          # from ansible.cfg
systemctl status app
```

| Symptom | Common cause | Check |
| :--- | :--- | :--- |
| `UNREACHABLE` | wrong IP / host down / firewall | `ping`, `ssh -v`, check `ansible_host` |
| `Permission denied (publickey)` | wrong key / `IdentitiesOnly` | `ssh -v` without an agent |
| `MODULE FAILURE` + python error | wrong interpreter / python missing | `ansible_python_interpreter` |
| `undefined` variable | host not in the group / name typo | `ansible-inventory --graph` |
| Task runs on the wrong host | host is in two groups | `--limit` + `-vv` |
| Handler does not run | task not `changed` | check idempotency |
| Play is slow | unnecessary `gather_facts` / small `forks` | `gather_facts: no`, raise `forks` |
| Vault error | password cannot be read | check `vault_password_file` |
| `sudo: a password is required` | `-K` missing, or no NOPASSWD | `-K` or fix sudoers |

> **Pitfall #10:** `ansible_host` is read from the inventory at the start of the run. If a playbook changes
> the host IP/DNS, the same run still uses the old value — run a new play or
> `meta: refresh_inventory`.

## Pitfalls (must-read)

| Pitfall | Symptom | Solution |
| :--- | :--- | :--- |
| `when` compares a string to a bool | Task still runs despite `-e x=false` | `| bool` |
| read-only `command` without `changed_when` | Second run is not `changed=0` | `changed_when: false` |
| `import_tasks` with `set_fact` | Empty / undefined variables | switch to `include_tasks` |
| Handlers do not run in `--check` | Service seems not restarted | verify manually |
| Fluctuating `template` | File changes every run, service restarts | stable data source |
| `lineinfile` without `regexp` | Duplicate lines pile up | `regexp` + `line` |
| Credentials in `-e` | Leak into history & logs | vault / env |
| Task containing secrets without `no_log` | Secrets printed in the output | `no_log: true` |
| `validate:` not used | Broken config only found at reload | `validate` for nginx/sshd/systemd |
| Host forgotten from the parent group | Common role does not run | `ansible-inventory --graph` |
| `ansible_facts['x']` vs old variables | `undefined` after a core upgrade | migrate to `ansible_facts[]` |
| `gather_facts: no` while facts are needed | Fact variables are empty | re-enable per play |
