# Monolith E-commerce Project

This project is a monolithic e-commerce application that integrates multiple services using **FastAPI** and **SQLAlchemy**. It leverages **PostgreSQL** as the database, and the architecture is containerized with **Docker Compose** for seamless setup and scaling. The system includes key components such as authentication, order processing, and product management, with observability tools for monitoring and debugging.

## Key Features
- **Authentication**: Login and verify tokens using Keycloak.
- **Product Management**: Get all products.
- **Order Management**: Create orders and send emails to customers using Apache Kafka.
- **Email Notifications**: Asynchronous email sending for transactional updates.
- **API Gateway**: A centralized entry point for all services.
- **Observability**: Integrated tools like Prometheus, Grafana, Jaeger, and OpenTelemetry.

## Technologies Used
- **Backend Framework**: FastAPI
- **Database**: PostgreSQL
- **ORM**: SQLAlchemy
- **Message Broker**: Kafka
- **Monitoring and Observability**: Prometheus, Grafana, OpenTelemetry, Jaeger
- **Authentication**: Keycloak
- **Containerization**: Docker Compose

## Technical Decisions & Trade-offs

**FastAPI instead of Django**
Async handlers on ASGI, Pydantic-validated payloads, and OpenAPI docs generated per route make each small service cheap to define and document. What is given up is the batteries: no admin, no bundled auth, no built-in migrations — acceptable here because each service exposes a handful of endpoints and identity is delegated anyway.

**Keycloak instead of hand-rolled authentication**
Delegating login, token issuance, and user management to Keycloak means the services only verify tokens, eliminating a whole class of security bugs you would otherwise write yourself. The cost: one more stateful container to run and configure, and its realm and client model carries a learning curve that a small JWT library does not.

**Kafka between orders and email**
Order creation publishes an event that the email service consumes, so a slow or dead mail server can never fail a checkout. The trade-off: Kafka is at-least-once, so the consumer must be idempotent and the confirmation email is eventually consistent rather than guaranteed inline with the order.

**SQLAlchemy as the ORM**
Mapping products and orders to Python objects keeps the query logic readable and the service code compact. The price: an ORM hides SQL just enough to invite N+1 query patterns and makes performance tuning less obvious than raw SQL — tolerable at this data size, worth watching as queries grow.

**The GIL in a service-per-process layout**
Each service runs as its own process, so the GIL is mostly a non-issue here: the work is I/O-bound (Postgres queries, Kafka publishes, SMTP sends), which FastAPI's async event loop handles well. The honest limit is CPU-bound work — heavy computation would still serialize per worker, and the fix is more processes, not threads.

**Docker Compose over Kubernetes**
The whole stack — services, PostgreSQL, Kafka, Keycloak, and the observability set — comes up with one compose file, keeping the demo reproducible on a laptop. The cost: no self-healing, autoscaling, or rolling updates; fine for a reference monolith, not for real production traffic.

## Installation
```bash
# Clone the repository
$ git clone https://github.com/MamangRust/monolith-ecommerce-example.git
$ cd monolith-ecommerce

# Start the application
$ docker-compose up --build
```

### Accessing the Services
- **API Gateway**: [http://localhost:8084](http://localhost:8084)
- **Keycloak**: [http://localhost:8080](http://localhost:8080)
- **Grafana**: [http://localhost:3000](http://localhost:3000)
- **Prometheus**: [http://localhost:9090](http://localhost:9090)
- **Jaeger**: [http://localhost:16686](http://localhost:16686)

## Services
### Authentication Service
- **Path**: `./auth-service`
- **Deskripsi**: Manages user authentication and roles using Keycloak.
- **Database**: PostgreSQL with SQLAlchemy ORM.
- **Port**: `8088`

### Product Service
- **Path**: `./product-service`
- **Deskripsi**: Get all products.
- **Database**: PostgreSQL with SQLAlchemy ORM.
- **Port**: `8081`

### Order Service
- **Path**: `./order-service`
- **Deskripsi**: Create orders and send emails to customers using Apache Kafka.
- **Database**: PostgreSQL with SQLAlchemy ORM.
- **Port**: `8082`

### Email Service
- **Path**: `./email-service`
- **Deskripsi**: Sends emails to customers using Apache Kafka.
- **Dependencies**: Kafka for message queueing.
- **Port**: `8083`

## Observability and Monitoring
- **Prometheus**: Collects metrics from all services and Kafka.
- **Grafana**: Displays collected metrics in interactive dashboards.
- **Jaeger**: Traces requests across services for debugging.
- **OpenTelemetry**: Ensures consistent telemetry data across services.
